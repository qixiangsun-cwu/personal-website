NumPy 与 ndarray 本章起点

为什么需要 NumPy · ndarray 的三条规矩 · 导入与第一个数组 · 打印与查看的两个坑

从这一章开始，我们处理的对象从“几个数”变成“成千上万个 数”。第 6 章负责把数据从文件里读进内存；读进来之后，数据在程序里就是一大堆数字。如果还是用列表一个个装、用 for 循环一个个算，数据量一上来就会慢到没法用。NumPy 就是为这件事准备的：它提供一个专门装数字的容器 ndarray，以及一整套“整块算”的运算规则。

这一模块先回答三个问题：为什么要把列表换成数组（1.1）、数组有哪些必须遵守的规矩（1.2）、怎么创建并查看第一个数组（1.3、1.4）。整个第 7 章，乃至第 8 章 pandas、第 9 章可视化，都建立在这个容器之上。

1.1 为什么需要 NumPy

先做一个看起来很简单、结果却很让人意外的实验：给一个列表“乘 2”。

Python 列表：* 表示“重复”
nums = [1, 2, 3]
nums * 2        # [1, 2, 3, 1, 2, 3]
nums + 2        # TypeError：列表不能加数字
# 想要 [2, 4, 6]，只能再手写循环
[x * 2 for x in nums]
NumPy 数组：* 表示“逐元素乘”
arr = np.array([1, 2, 3])
arr * 2         # [2 4 6]
arr + 2         # [3 4 5]
arr ** 2        # [1 4 9]
# 整块算，一行写完，不用循环

结果不是 [2, 4, 6]，而是 [1, 2, 3, 1, 2, 3]。因为在 Python 里，列表的 * 被定义成重复（把整个列表复制几份接在一起），+ 被定义成拼接。列表根本不知道“每个元素”这个概念——它只是一个装对象的口袋。想逐元素乘 2，只能自己写循环或列表推导式。

NumPy 的数组不一样。它把“一整块同类型的数字”当成一个整体，于是 arr * 2 的含义是每个元素都乘 2，arr + 2 是每个元素都加 2。这种“不写循环、整块算”的方式叫向量化（vectorization）。循环并没有消失——它被交给 NumPy 内部用 C 写的代码去跑，所以代码更短，速度还更快。

图 7-1　列表的 * 2 是“复制一遍”，数组的 * 2 才是“每个元素各乘 2”——这一个差别，就是 NumPy 存在的理由
一句话记住：列表的 * 是“重复”，数组的 * 是“逐元素乘”。想要数学意义上的整体运算，就得先把数据变成数组。
列表做不了数学，数组可以：乘 2、加 2、平方、求和 
import numpy as np

nums = [1, 2, 3]
arr = np.array([1, 2, 3])

print('列表 * 2：', nums * 2)
try:
    print(nums + 2)
except TypeError as e:
    print('列表 + 2 报错：', e)

print('数组 * 2：', arr * 2)
print('数组 + 2：', arr + 2)
print('数组 ** 2：', arr ** 2)
print('数组求和：', arr.sum())
运行结果（实测）
列表 * 2： [1, 2, 3, 1, 2, 3]
列表 + 2 报错： can only concatenate list (not "int") to list
数组 * 2： [2 4 6]
数组 + 2： [3 4 5]
数组 ** 2： [1 4 9]
数组求和： 6
顺带算一笔内存账：100 万个整数，用列表存大约要 36 MB（每个元素一个 28 字节的 int 对象，外加列表里 8 字节的指针），用 int64 数组只要 8 MB。数据量越大，这个差距越致命——这也是为什么“数据一大就上 NumPy”。

更实际的理由是生态：pandas 的每一列底层就是一个 ndarray；scikit-learn 的输入要求是数组或能转成数组的结构；PyTorch 的 Tensor 和 ndarray 几乎可以无缝互转。学会 ndarray，等于拿到后面所有工具的“通用货币”。

和 AI 的关系：大模型里的“张量（Tensor）”就是多维数组的另一个名字。图像是一张 (高, 宽, 3) 的数组，一批图片是 (批大小, 高, 宽, 3) 的数组，一句话的嵌入向量是一个 (768,) 的数组。今天在 NumPy 里把 shape 和索引弄明白，后面看 PyTorch 代码才不会是天书。
✅ 本节小结：列表的 * 2 是重复，数组的 * 2 是逐元素乘；NumPy 提供数组对象与向量化运算，代码短、速度快、省内存，是 pandas / scikit-learn / PyTorch 的共同地基。

1.2 ndarray 对象的三条规矩

课件把 ndarray 的特点总结成两句：存储相同类型的数据、数组的维度和大小要事先确定。再补上第三条——它天生支持多维。这三条不是随便定的，它们正好换来 1.1 里说的“快”和“省”。下面逐条看。

① 元素类型必须相同

  • 一个数组只有一个 dtype
  • 写的时候混了不同类型，NumPy 会自动“向上提升”成同一种
  • 好处：每个元素占一样多的字节，能等距排布

② 大小固定

  • 创建那一刻，元素个数就定死了
  • 没有 append，想加元素只能造一个新数组
  • 好处：内存一次分配好，不用边加边扩容

③ 支持多维

  • 一维是一条线，二维是一张表，三维是一叠表
  • 每一维叫一个轴（Axis），从 0 开始编号
  • 好处：表格、图像、一批样本都能用一个对象表示

把这三条和列表放在一起对照，区别就清楚了。注意表格里“运算”那两行——那是 1.1 里最直观的差别。

对比项Python 列表 listNumPy 数组 ndarray
元素类型可以混，int、str、对象随便放必须统一，整个数组只有一个 dtype
长度随时 append / remove，长度会变创建时固定，改长度只能新建一个
内存布局指针数组 + 一堆分散的对象一整块连续内存，元素等距排列
* 2 的含义把整段重复一次，长度翻倍每个元素各乘 2，长度不变
+ 2 的含义直接报 TypeError每个元素各加 2
求和写法sum(nums)，还行arr.sum()，一行且更快
适合装什么少量、结构复杂、类型杂的数据大量、同类型的数值（成绩、价格、像素、向量）

“连续内存”到底长什么样？下图把两种结构画出来：列表是“一排指针，指向散落在各处的对象”；数组是“一整条等宽的传送带，旁边挂一张纸条写着它是怎么排的”。

图 7-2　“元素类型相同 + 大小固定”换来的是连续内存——这才是 NumPy 比列表快的根本原因
类型统一与大小固定：混着写会被提升，想加元素只能新建 
import numpy as np

a = np.array([1, 2, 3])
b = np.array([1, 2, 3.5])
c = np.array([1, 2, '3'])

print('a 的 dtype：', a.dtype)
print('b 的 dtype：', b.dtype)
print('c 的 dtype：', c.dtype)
print('b 的内容：', b)
print('c 的内容：', c)
print('数组有 append 吗：', hasattr(a, 'append'))
print('np.append 其实返回新数组：', np.append(a, 4))
print('原来的 a 还是：', a)
运行结果（实测）
a 的 dtype： int64
b 的 dtype： float64
c 的 dtype： <U21
b 的内容： [1.  2.  3.5]
c 的内容： ['1' '2' '3']
数组有 append 吗： False
np.append 其实返回新数组： [1 2 3 4]
原来的 a 还是： [1 2 3]
看清楚 dtype 的变化：[1, 2, 3.5] 里混了整数和小数，整个数组被提升成 float64；[1, 2, '3'] 里混进了字符串，于是所有元素都变成字符串，数字 1 也变成了 '1'。这不是 bug，是“类型必须相同”这条规矩在起作用：NumPy 会找一种能装下所有元素的类型。所以建模、计算时一定要保证数组里都是数字，不然算出来的结果会让你莫名其妙。
✅ 本节小结：ndarray 三条规矩——元素类型必须相同（不同就自动提升）、大小创建时固定（没有 append）、支持多维（每一维叫一个轴）。换来的是等距、连续、可整块运算的内存布局，这就是它比列表快的原因。

1.3 导入与第一个数组

用 NumPy 的第一步永远是导入。惯例写法是 import numpy as np——np 是全世界通用的别名，别人的代码、教程、公司项目都这么写，跟着写就不会错。导入之后，用 np.array() 把列表变成数组。

创建好之后第一件事是“看它一眼”。这里有一个教材和屏幕不一致的细节，很多同学第一次看会以为自己的输出错了：课件和书上写的是 array([1, 2, 3])，而你 print 出来是 [1 2 3]——没有逗号，也没有 array 这个词。两个都对，只是“给谁看”不一样。

1.4 打印与查看：两个高频小坑

第一个数组跑通了，接下来最容易踩的坑都在“输出”上。这两个坑不影响计算结果，但会让你的输出难看、甚至对不上课件，考试时也容易误判。

坑一：把 numpy 标量塞进列表。NumPy 2.x 里，numpy 的标量（np.float64、np.int64）显示成 np.float64(1.5) 这种带类型名的样子。单独 print 一个标量没问题（走 str，显示成 1.5），可一旦放进列表里，就会跟着列表的格式打出 [np.float64(1.5)]——非常丑，而且和你想要的 [1.5] 不是一回事。

坑二：浮点数的“尾巴”。0.1 + 0.2 在计算机里不等于 0.3，数组求和时会打出 0.6000000000000001 这样一长串。要展示两位小数，用 np.round(x, 2) 或 round(float(x), 2)。

两个输出坑：np.float64 污染列表、浮点尾巴 
import numpy as np

arr = np.array([0.1, 0.2, 0.3])
print('直接求和：', arr.sum())
print('保留两位：', np.round(arr.sum(), 2))

v = np.float64(1.5)
print('放进列表（丑）：', [v])
print('先转 float（对）：', [float(v)])
print('切一片再 tolist：', arr[:2].tolist())
print('数组本身：', arr)
运行结果（实测）
直接求和： 0.6000000000000001
保留两位： 0.6
放进列表（丑）： [np.float64(1.5)]
先转 float（对）： [1.5]
切一片再 tolist： [0.1, 0.2]
数组本身： [0.1 0.2 0.3]
输出三句话，背下来：① 展示数组 → 直接 print(arr)，想看到“带逗号的列表”就 print(arr.tolist())；② 展示单个标量 → 先 float() / int()，再用 round(float(x), 2) 控制小数位；③ 永远不要在 print([...]) 里直接混 numpy 标量，会打出 np.float64(...)。
顺手记一个查看三件套：print(arr) 看内容、arr.shape 看形状、arr.dtype 看类型。这三个信息拿到，一个数组就基本摸清了——下一模块正式讲它们。
✅ 本节小结：展示用 print(arr) 或 arr.tolist()，单个标量先 float()；别把 numpy 标量直接放进列表（会打出 np.float64(...)）；小数展示用 np.round / round(float(x), 2) 去掉浮点尾巴。

2.1 array()：从列表 / 元组创建

np.array() 是最直接的造法：把现成的 Python 数据“倒”进数组。它接受列表，也接受元组；传一个嵌套列表就得到二维数组，外面的列表是行，里面的列表是列。

2.3 zeros / ones / full / eye

做数据分析时经常需要“先摆一个空表，再往里填数”——比如先建一个 10×5 的成绩表，再去逐格赋值。这类需求就用占位函数：zeros() 全 0、ones() 全 1、full() 填任意值、eye() 造单位矩阵（对角线是 1、其余是 0）。

它们的参数都是 shape：传一个整数表示一维（长度为几），传一个元组表示多维（每维多长）。这里有个新手必踩的坑——np.zeros(3) 和 np.zeros((2, 3)) 都对，但 np.zeros(2, 3) 是错的，那会被理解成传了两个参数。

2.4 reshape：改形状不改数据

数组造好之后，形状不一定合适。比如 arange(6) 得到一条 6 个元素的线，但你要的是一张 2 行 3 列的表——这时用 reshape()。它的作用是换一种“读法”：数据本身一个不动，只是把“怎么分行、怎么分列”重新规定一遍。

reshape(2, 3) 就是 2 行 3 列；reshape(3, -1) 里的 -1 表示“这一维我不想算，你自己推”——NumPy 会用总元素数除以另一维，算出 6 ÷ 3 = 2。所以 reshape(3, -1) 和 reshape(3, 2) 等价。一维的 reshape(-1) 就是“拉平”。

reshape 改形状：2×3、3×2、-1 自动推断

a = np.arange(6)
print('原数组：', a)

print('reshape(2, 3)：')
print(a.reshape(2, 3))

print('reshape(3, -1)：')
print(a.reshape(3, -1))

print('reshape(-1) 拉平：', a.reshape(-1))
print('原数组没变：', a)
运行结果（实测）

reshape(2, 3)：
[[0 1 2]
 [3 4 5]]
reshape(3, -1)：

reshape(-1) 拉平： [0 1 2 3 4 5]

reshape 有一条铁律：元素总数必须前后相等。6 个元素可以变成 2×3、3×2、1×6、6×1，但不能变成 4×2（那需要 8 个位置）——多一个少一个都会直接报错。这条规矩正是 1.2 说的“大小固定”的延续。

故意写错：6 个元素塞不进 4×2

print('元素个数：', a.size)
print('3 × 2 =', 3 * 2, '，位置够')
print('4 × 2 =', 4 * 2, '，位置不够')

print(a.reshape(4, 2))    # 这里会报错

一句话记住：reshape 只改“怎么读”，不改“是什么”。元素还是那些元素、顺序也没变，只是换了个行列的排法；所以元素总数必须守恒，-1 只是让 NumPy 帮你算那一维。
✅ 本节小结：reshape 只改形状、不改数据；-1 表示让 NumPy 自己算那一维；元素总数必须和原数组相等，否则抛 ValueError；原数组不会被改动。

数组属性与一维访问 高频考点

数组造出来了，接下来的问题永远是同一个：怎么把我要的那几个数取出来。这一模块先学会看数组的“身份证”（形状、维度、大小、类型），再学三种取数方式：单个索引、切片、列表下标。最后一种藏着本课最容易被忽略的坑——切片是视图，不是副本。

3.1 三个属性：shape / ndim / size

NumPy 对象的属性不用加括号（它们不是函数），直接点出来就行。最重要的三个是：shape（形状）、ndim（维度数）、size（元素总数），再加一个 dtype（元素类型）。

三个数的关系非常好记：ndim 就是 shape 这个元组里有几个数；size 就是 shape 里各维相乘。一维数组的 shape 写成 (10,)——注意那个逗号，它是元组的标记，不是笔误，少了逗号就变成普通括号里的一个数了。

✅ 本节小结：shape 是元组（一维写成 (10,)，逗号不能省）、ndim 是维数、size 是元素总数，三者满足 ndim = len(shape)、size = 各维相乘；dtype 说明元素类型。属性不加括号。

本课最高频的坑：切片是「视图」，不是「副本」！
s = a[0:3] 并没有把数据复制一份给你，它只是给原数组的同一块内存又起了个名字、划了个范围。所以你改 s[0]，原数组 a[0] 跟着变；反过来改 a，s 里看到的也变。这一点和列表切片（列表切片是浅拷贝）完全相反，是 NumPy 新手最容易翻车的地方。下面用代码证明给你看。
证明切片是视图：改切片 → 原数组跟着变；.copy() 才是独立副本 
import numpy as np

a = np.arange(10, 21, 2)
s = a[0:3]
print('改之前 a：', a)
s[0] = 99
print('改 s[0] 之后 a：', a)
print('共享内存吗：', np.shares_memory(a, s))

c = a[0:3].copy()
c[0] = -1
print('改 copy 之后 a：', a)
print('copy 的内容：', c)
运行结果（实测）
改之前 a： [10 12 14 16 18 20]
改 s[0] 之后 a： [99 12 14 16 18 20]
共享内存吗： True
改 copy 之后 a： [99 12 14 16 18 20]
copy 的内容： [-1 12 14]
什么时候要 copy：① 想把一段数据单独拿出来加工、又不想污染原数据——先 .copy()；② 做完切片后要修改它——先想清楚“我是要改原数组，还是只要改这一段”，要改原数组就用视图（这是 NumPy 省内存的设计），只改自己就 copy；③ 判断方法很简单：np.shares_memory(a, s) 返回 True 就是视图。
✅ 本节小结：切片 a[start:stop:step] 左闭右开；a[:3]、a[::2]、a[::-1] 是常用写法；切片是视图，和原数组共享内存，改切片会改原数组，要独立副本必须 .copy()。

3.4 列表作为下标（花式索引）

切片只能取“连续的一段”（或者按固定间隔取）。如果我要的是不连续的几个位置——比如第 1、第 2、第 5 个——就用“列表作为下标”，官方叫花式索引（fancy indexing）：a[[1, 2, 5]]。

方括号里那个列表是“位置清单”，NumPy 按清单把对应位置的元素挑出来，组成一个新数组。清单可以乱序。（a[[5, 0, 1]] 就按 5、0、1 的顺序给你。）也可以重复。（a[[0, 0, 0]] 就给你三个一模一样的首元素，长度跟着清单走。）这两点是切片做不到的。

列表下标：挑选、乱序、重复，而且拿到的是副本

print('a：', a)
print('a[[1, 2, 5]]：', a[[1, 2, 5]])
print('乱序 a[[5, 0, 1]]：', a[[5, 0, 1]])
print('重复 a[[0, 0, 0]]：', a[[0, 0, 0]])

f = a[[0, 1]]
f[0] = 77
print('改副本之后 a：', a)
print('副本 f：', f)

四

二维访问与布尔索引 必会基本功

a[行, 列] 两个下标定位 · a[0] 是整行 · a[:, 0] 是整列 · 冒号 : 表示这一维全要 · 布尔掩码先造再挑

第三个模块里我们只跟一维数组打交道，一个下标就能指到某个元素。二维数组不一样了：它是一张表格，横着有行、竖着有列，要指到一个具体的格子，就得给两样信息——第几行、第几列。所以访问二维数组的基本写法是 a[行, 列]；如果只给一个数字，NumPy 会理解成“你只限定了行”，把它交给你一整行。

除了“按坐标拿”，还有一种更常用的拿法：按条件拿。比如“把这 20 个分数里大于 80 的全挑出来”，用下标一个个挑太笨了，NumPy 的做法是先算出一个布尔数组（一串 True / False），再用这串 True / False 去原数组里“筛”。这就是本模块的第二个重点——布尔索引。

4.1 二维索引：两个数字定位

二维数组的每个元素由两个下标确定，写在同一对方括号里，中间用逗号隔开：a[0, 1] 表示第 0 行第 1 列。两个下标都从 0 开始，所以 a[1, 1] 拿到的是第 2 行第 2 列那个格子，不是第 1 行第 1 列的。

最容易踩的坑是只给一个下标。a[0] 不是“第 0 行的第一个元素”，而是“第 0 行的全部元素”，拿到的还是一个一维数组 [1 2 3 4]——它的形状是 (4,)，还能接着往下索引，比如 a[0][1] 确实能拿到 2。但 NumPy 不推荐这种“分两步走”的写法：a[0][1] 是先把整行取出来、再在整行上取一次，a[0, 1] 才是一次性定位，一步到位。

✅ 本节小结：二维数组用两个下标定位——a[行, 列]，都从 0 开始；只给一个下标 a[0] 拿到的是整行（一维数组）；想拿单个元素，两个下标一个都不能少。

4.2 二维切片与 : 的用法

二维数组的每一个维度都能像一维那样“切”，两个维度之间还是用逗号隔开：a[行怎么取, 列怎么取]。冒号 : 的意思是“这一维我全要”——一个冒号占了位置，就等于把这一维原样留下。

  • a[0:2]：行取前两行，列没写就相当于第二维全要 → 形状 (2, 4)；
  • a[:, 0]：行全要、列只要第 0 列 → 整列，是一维数组，形状 (3,)；
  • a[:, [0, 2]]：行全要、列按列表挑第 0、2 列 → 形状 (3, 2)；
  • a[0:2, 1:]：行取前两行、列从下标 1 到最后 → 形状 (2, 3)。

4.3 布尔索引：用条件挑元素

逐个算下标太累，现实中的需求往往是“把满足某个条件的元素都挑出来”。NumPy 的布尔索引分两步走：先对数组做一次比较运算，得到一串 True / False（长度和原数组一样，这叫掩码）；再把这串 True / False 塞进方括号里，NumPy 就按 True 的位置把元素挑出来。

例如 a = np.arange(10, 21, 2) 得到 [10 12 14 16 18 20]。a > 15 会逐元素判断，得到 [False False False True True True]；把这个布尔数组放进方括号 a[a > 15]，True 那三个位置对应的元素就被挑了出来，结果是 [16 18 20]。下图就是这个“掩码 → 结果”的映射。

import numpy as np

a = np.arange(10, 21, 2)
print('a =', a)
print('a > 15 得到布尔数组：', a > 15)
print('a[a > 15] 挑出满足条件的：', a[a > 15])
print('a[a % 3 == 0]：', a[a % 3 == 0])
# 多条件：每个条件都要加括号，用 & | 连接
print('(a > 10) & (a < 20)：', a[(a > 10) & (a < 20)])
print('(a == 10) | (a == 20)：', a[(a == 10) | (a == 20)])
print('掩码里 True 的个数：', int((a > 15).sum()))

多条件必须用 & | ~，而且每个条件都要加括号。写 a[a > 10 and a < 20] 会直接报 ValueError——Python 的 and 只想得到“一个整体是真还是假”，它没法对整张数组逐元素判断；而 & 是 NumPy 重载过的按位与，会逐元素算。还有优先级问题：& 的优先级比比较运算符高，不写括号的话 a > 10 & a < 20 会被理解成 a > (10 & a) < 20，结果要么报错要么离谱。规矩就一条：一个条件一对括号，中间用 & 或 | 连。
✅ 本节小结：布尔索引分两步——a > 15 得到同长度的 True / False 掩码，a[a > 15] 按掩码挑出元素；结果是一维数组、长度等于 True 的个数，原数组不变；多条件用 & / | / ~ 且每个条件加括号。
五

数组的运算 易错：* 不是矩阵乘法

转置 a.T · 逐元素加减乘除（+ - * / **）· 点积 np.dot / @ · 广播（选学但重要）

课件把“数组的运算”拆成三块：转置、点积、统计运算。统计运算（sum / mean / axis 那一套）内容多，单独放到第六模块讲；这一模块先把前两块讲透，再加一个 NumPy 里非常实用、但规则要单独记的广播。

先说一句最重要的：NumPy 里的 * 不是矩阵乘法，它是逐元素相乘——两个数组同一位置的数各自相乘。矩阵乘法是 np.dot()（或 @）。这两个符号长得像、结果差得远，是这门课最容易翻车的地方，第五节会把同一对数组两种算法摆在一起对照。

5.2 逐元素运算（* 不是矩阵乘法！）

NumPy 最让人舒服的地方，就是运算符可以直接对整张数组用：a + b、a - b、a * b、a / b、a ** 2……它们全都是逐元素算的——第 0 个跟第 0 个算、第 1 个跟第 1 个算，各算各的，互不干扰。这就是第一个模块说的“向量化”：不用写 for 循环，一行搞定。

因为都是逐元素，所以默认要求两个数组形状完全相同。[1, 2, 3] 加 [10, 20, 30]，得到 [11, 22, 33]；形状不一样就会报错（除非能广播，见 5.4）。

七个常用运算符

  • + -：加减，逐元素
  • *：逐元素相乘
  • /：除，结果一定是浮点
  • **：乘方，a ** 2 是各自平方
  • // %：整除、取余

数组和标量也能算

a * 2 是每个元素都乘 2；a + 10 是每个都加 10。标量会自动“铺”到每一个元素上——这是最简单的广播。

形状必须配得上

逐元素运算要求两边形状相同（或能广播）。(3,) 和 (3,) 可以，(3,) 和 (4,) 直接报错。

再强调一次：* 是逐元素乘，不是矩阵乘法。数学课上写的矩阵乘法，在 NumPy 里是 np.dot(a, b) 或 a @ b，不是 a * b。如果你拿 * 去算“矩阵乘矩阵”，程序不会报错，只会安安静静给你一个完全错误的结果——这种错最难查。下一节用同一对数组把两种乘法摆在一起看。
✅ 本节小结：+ - * / ** // % 全部逐元素运算，要求形状相同（或能广播）；数组和标量算时标量自动铺到每个位置；* 是逐元素相乘，不是矩阵乘法。

5.3 点积 dot / matmul

矩阵乘法在 NumPy 里由 np.dot() 完成，也可以写成运算符 @（Python 3.5 起支持），两者结果完全一样。它的算法是“左边的行 × 右边的列，乘完再相加”：结果的第 i 行第 j 列，等于左边第 i 行和右边第 j 列对应相乘再求和。

两种情形要分清（课件 7.2 的原文）：

  • 一维 × 一维（长度相同）：结果是一个数（标量），叫向量内积。比如 [1, 2, 1] 和 [3, 4, 5] → 1×3 + 2×4 + 1×5 = 16。
  • 二维 × 二维：形状 (m, k) 乘 (k, n)，结果是 (m, n)。左边矩阵的列数必须等于右边矩阵的行数（都是 k），否则接不上、直接报错。

下面用同一对 2×2 数组把公式算给你看：x = [[1, 2], [3, 4]]、y = [[5, 6], [7, 8]]。结果第 0 行第 0 列 = x 的行 0（1, 2）乘 y 的列 0（5, 7）= 1×5 + 2×7 = 19；第 1 行第 1 列 = 3×6 + 4×8 = 50。

5.4 广播（选学但重要） 选学但重要

逐元素运算要求形状相同，可有时候我们偏偏想让形状不一样的数组算——比如一个 (3, 3) 的矩阵，每一行都加上同一个 [100, 200, 300]。难道要先把 [100, 200, 300] 复制成三行吗？不用。NumPy 有一套广播（broadcasting）规则，会“概念上”把这个短数组铺开，用不着真的复制内存。

广播的两条规则

  1. 从最右边的维度开始，逐个往左对齐比较形状；
  2. 每一对维度，要么相等，要么其中一个是 1（或者一方压根没有这一维），否则就报错。

拿 (3, 3) + (3,) 试：从右往左比，最右边那个 3 和 3 相等——过；左边 (3,) 没有第二维了，相当于 1——过。于是短数组被“复制”到每一行，结果形状是 (3, 3)。这就是为什么 (3,3) + (3,) 能算。

6.2 axis：沿哪个方向缩

一维数组没什么好选的，只有一个方向。二维数组有两个轴：第 0 轴是行方向，第 1 轴是列方向。做统计的时候要告诉 NumPy“沿哪个轴缩”，这个参数就是 axis。

不写 axis 时，NumPy 把整个数组拍平了算，得到一个数。写了 axis，就是“把那一维压掉”，结果里少一维、每个剩下的位置出一个数：

  • axis=0：沿第 0 轴（行方向）把行压掉 → 每一列出一个数，结果是 4 个数，形状 (4,)（3 行 4 列的矩阵）；
  • axis=1：沿第 1 轴（列方向）把列压掉 → 每一行出一个数，结果是 3 个数，形状 (3,)。
一句话记牢：axis 就是你要“压掉”的那一维。压掉第 0 维（3 行），剩下的是 4 列 → 4 个数；压掉第 1 维（4 列），剩下的是 3 行 → 3 个数。先想“哪个方向被压没了”，再看结果剩几个数，比背“按行还是按列”靠谱得多。

6.3 用统计函数做成绩小结

把 axis 用起来，一张成绩表能一次算出好几份小结。假设 3 名学生考了 4 门课，成绩表 s 是 3 行 4 列——行是学生，列是课程。这时候 axis 的语义就有了业务含义：

axis=0：按“课程”汇总

  • 把 3 名学生压掉，每门课剩 1 个数
  • np.mean(s, axis=0) → 每门课的平均分（4 个数）
  • np.max(s, axis=0) → 每门课的最高分
  • 适合回答“这门课大家考得怎么样”

axis=1：按“学生”汇总

  • 把 4 门课压掉，每名学生剩 1 个数
  • np.max(s, axis=1) → 每名学生的最高分（3 个数）
  • np.sum(s, axis=1) → 每名学生的总分
  • 适合回答“这个学生考得怎么样”

还有一个细节：np.argmax(s) 不写 axis 时，会把整张表拍平成一维再找最大值的位置，得到的是一个“压平后的下标”。想把它还原成“第几行第几列”，用整除和取余就行：行 = 下标 // 列数，列 = 下标 % 列数。下面 demo 里算的就是这个。

✅ 本节小结：成绩表行 = 学生、列 = 课程时，axis=0 得每门课的统计（平均 / 最高 / 最低），axis=1 得每名学生的统计（最高 / 最低 / 总分）；argmax 不写 axis 给的是压平后的下标，用 下标 // 列数 和 下标 % 列数 还原行列。

6.4 打印陷阱：别让 np.float64 混进列表

最后讲一个几乎所有新手都会撞上的显示问题。单独打印一个 numpy 标量是没问题的——print(np.mean(x)) 会老老实实打出 20.75，因为它走的是字符串转换。可一旦把这个标量放进列表再打印，Python 会去调它的 repr()，于是输出变成 [np.float64(20.75), np.int64(27), np.int64(10)]——一串带着类型名的丑东西。写作业、做报告、把结果贴进文档时，这个尾巴非常碍眼。

NumPy 2.x 对这一点比旧版更“诚实”（旧版里 repr 少了类型名），所以这个坑现在更容易碰到。两类解法，按场景选：

  • 标量：先转成 Python 原生数——float(np.mean(x))、int(np.max(x))，需要两位小数就再套 round(..., 2)；
  • 数组：要“以列表形式”展示就用 arr.tolist()，它会把每个元素都转成 Python 原生数；如果只是想看看数组内容，直接 print(arr) 也干净（得到 [19 14 25] 这种样式）。
np.float64(...) 是从哪冒出来的：三种正确写法对照 
import numpy as np

x = np.array([19, 14, 25, 10, 27, 26, 27, 18])
print('直接打印一个 numpy 标量（没问题）：', np.mean(x))
print('掉进坑里：', [np.mean(x), np.max(x), np.min(x)])   # 列表里混了 numpy 标量
print('正确做法 1：先转成 Python 数 ——', [float(np.mean(x)), int(np.max(x)), int(np.min(x))])
print('正确做法 2：要按列表展示数组，用 .tolist() ——', np.array([19, 14, 25]).tolist())
print('数组直接 print 也是干净的：', np.array([19, 14, 25]))
运行结果（实测）
直接打印一个 numpy 标量（没问题）： 20.75
掉进坑里： [np.float64(20.75), np.int64(27), np.int64(10)]
正确做法 1：先转成 Python 数 —— [20.75, 27, 10]
正确做法 2：要按列表展示数组，用 .tolist() —— [19, 14, 25]
数组直接 print 也是干净的： [19 14 25]
同一个坑还有两个变种。① 浮点误差尾巴：np.mean([0.1, 0.2, 0.3]) 可能打出 0.20000000000000004 这种，看着像算错了，其实是二进制浮点的正常误差——要展示就 round(float(v), 2) 或 np.round(x, 2)。② 大数组被省略：数组元素一多，print 会显示成 [ 1 2 3 ... 98 99 100]，中间用省略号带过，这不是数据丢了，只是 NumPy 帮你省屏幕。想全看，用 np.set_printoptions(threshold=np.inf)，但一般没必要。
✅ 本节小结：numpy 标量单独 print 正常，放进列表就会打出 np.float64(...) / np.int64(...)；标量先 float() / int()，数组要列表形式就 .tolist()；浮点误差尾巴用 round 收掉。这几条是交作业时的“体面分”。

7.1 排序：函数 vs 方法

排序是数据处理的第一个动作：排名次、找最大、取前 N 名，底下都是排序。NumPy 给了两个入口，长得几乎一样，但改不改原数组完全是两回事：

  • np.sort(x) 是 NumPy 的函数——名字前面是 np.，必须把数组当参数传进去；它返回一个排好序的新数组，x 一个元素都不动。
  • x.sort() 是 ndarray 的方法——名字前面是数组自己，不用再传数组；它原地排序，把 x 里的元素位置直接改掉，返回值是 None。
np.sort(x)　函数：给一份排好序的副本
y = np.sort(x)      # x 不动，y 是新数组
print(x)            # 还是原来的顺序
print(y)            # 从小到大排好了
x.sort()　方法：就地改自己
x.sort()            # 不返回数组，x 自己变了
print(x)            # 已经是排好序的
y = x.sort()        # ✗ 这样写 y 是 None
                    #   不是排好序的数组

最容易踩的坑：y = x.sort() 不会报错，但 y 是 None，后面 y[0] 就会崩。要“既排序又留下原数组”，写 y = np.sort(x)；要“就地改”，写 x.sort() 然后继续用 x。

一维数组排序不用想方向，二维就必须说清楚沿哪个轴排。规则和统计函数一致：np.sort 的默认是 axis=-1，也就是“最后一维”——二维时等于 axis=1，在每一行内部从小到大排，一行的元素始终留在这一行里；axis=0 才是同一列上下排，元素的列号不变、行号变。

7.2 变形与拼接

数组的形状经常“不合用”：模型要 (样本数, 特征数)，你手上是一长条；两个月的销量分在两个数组里，要接成一个。NumPy 里这两类活儿分得很清楚——变形不改变元素个数（只换一种“看法”），拼接会改变元素个数（真的多了东西）。

改形状：reshape

  • 元素总数必须相等，只换行列
  • -1 占位，让 NumPy 自己算那一维
  • 总数对不上 → ValueError

拉平：ravel / flatten

  • 都得到一维数组，元素顺序一样
  • ravel() 返回视图，改它会动到原数组
  • flatten() 返回副本，随便改

拼接：concatenate 家族

  • concatenate 沿指定轴拼
  • vstack 竖向加行、hstack 横向加列
  • append 末尾追加，每次新建数组
reshape：只换形状不换数据，-1 让 NumPy 自己算那一维 
import numpy as np

a = np.arange(12)                               # 0 ~ 11，共 12 个数
print('a =', a.tolist())
print('a.shape =', a.shape)

b = a.reshape(3, 4)                             # 3 行 4 列
print('reshape(3, 4) 之后：')
print(b)
print('b.shape =', b.shape)

c = b.reshape(-1)                               # -1：这一维让 NumPy 自己算
print('reshape(-1) 拉回一维：', c.tolist())

d = b.reshape(2, -1)                            # 2 行，列数自己算 → 6
print('reshape(2, -1) 的形状：', d.shape)

ravel 是视图、flatten 是副本：改一下就知道差别

print('改 f[1] 之后 f：', f.tolist())
print('同一时刻 a 还是：')

视图和副本的区别，本质是“省不省内存”：ravel() 不复制数据，只换一个“一维”的壳，所以改它会顺带改到原数组，胜在省内存；flatten() 把数据整份复制一遍，怎么改都影响不到原数组，胜在安全。这和 3.3 里“切片是视图不是副本”是同一个道理。

vstack 和 hstack 是 concatenate 的两个常用特例：vstack 相当于 concatenate(axis=0)，竖着摞、行数变多；hstack 相当于 concatenate(axis=1)，横着接、列数变多。拼接的唯一硬要求是“除了拼接的那一维，其余维度必须一样”——(2, 2) 能和 (1, 2) 竖向摞，但不能和 (3, 3) 横向接。

np.append 不是列表的 append——它不会在原数组后面加东西，而是返回一个新数组。所以它和 np.sort 一样属于“函数派”：原数组不动，结果在返回值里。循环里反复 np.append 会一次次复制数据，数据量大时要改用列表收集、最后一次性 np.array。
✅ 本节小结：reshape 只改形状不改数据，元素总数必须匹配，-1 可以占位让它自己算；ravel 返回视图、flatten 返回副本——要不要改原数组，心里得有数；concatenate 沿现有轴拼，vstack 竖向加行、hstack 横向加列，append 每次新建一个数组。变形不改变元素个数，拼接会改变。

7.4 AI 渗透：为什么 AI 框架全用数组

这一章学的 ndarray，在 AI 工程里有一个几乎一模一样的“亲戚”——PyTorch 的 Tensor（张量）。两者不是“像”，而是同构：形状、类型、索引、切片、广播、点积、按轴归约，一套概念两边通用，连函数名都大半重合。学会 ndarray，等于提前学会了 Tensor 的 80%；剩下 20% 里最要紧的那一点，是 Tensor 多了一个“算在哪”的属性。

唯一的“翻译成本”是两个词：NumPy 叫 axis，PyTorch 叫 dim；NumPy 习惯写函数 np.xxx，PyTorch 大多挂在 torch.xxx 或者干脆做成方法。剩下的语法几乎可以逐字照抄——这也是为什么几乎所有 AI 教材都默认你已经会 NumPy。

那 GPU 张量又是什么？ndarray 住在内存里，只能用 CPU 算；Tensor 多一个 device，可以搬到显卡的显存里，用几千个核心同时算。搬家的动作就是一句 t.to('cuda')，搬过去之后形状、索引、点积的写法一点不变——变的是速度，不是语法。7.3 那行 np.dot(scores, weight) 是 10×5 乘 5，如果放大成 4096×4096 乘 4096×4096，就是 Transformer 里一次前向的基本动作。

至于数据预处理为什么全都用 NumPy，原因很实在：① 所有读数据的库最后都给你 ndarray——np.loadtxt 读文本、pandas 的 .values、PIL / OpenCV 读图片都是；② 预处理动作全是数组操作——归一化是广播、切分训练集是切片、拼 batch 是 vstack、打乱顺序是花式索引；③ 转成 Tensor 几乎不花代价——torch.from_numpy(a) 与 ndarray 共享同一块内存，不复制数据。所以标准流程是：磁盘 → NumPy（在 CPU 上洗数据）→ Tensor（进模型）→ GPU（开算）。

回头看 NumPy 与 AI 的关系：ndarray 和 PyTorch 的 Tensor 是同构的——同样的 shape / dtype，同样的索引切片、广播、点积、按轴归约，连 np.sort(x) / x.sort() 这种“函数 vs 原地方法”的区分都对得上一份 torch.sort(t) / t.sort()。GPU 张量只是给 Tensor 多了个 device（cpu / cuda），搬上显存之后写法一个都不改，变的只是并行度和显存限制。至于数据预处理为什么全用 NumPy：所有读数据的库最后都交给你一个 ndarray，清洗、归一化、切分、拼 batch 全是数组操作，而 torch.from_numpy() 又和 ndarray 共享内存、零拷贝——NumPy 是数据进模型之前的“通用语言”，这一章学的就是这门语言。
✅ 本节小结：ndarray 与 Tensor 同构——shape / dtype / 索引 / 广播 / dot / axis 归约一套通用，只有 axis 改叫 dim；GPU 张量只多一个 device，.to('cuda') 之后写法不变；数据预处理阶段全用 NumPy，因为所有读数据的库都产出 ndarray，from_numpy 又能零拷贝转成张量。学会 NumPy，就是拿到了进 AI 框架的入场券。

一、知识点总结卡

NumPy 与 ndarray

  • NumPy = Numerical Python，开源科学计算库
  • 核心对象 ndarray：多维、同类型、定长数组
  • 导入惯例：import numpy as np
  • 列表只能"逐个搬运"，数组可以"整批运算"（向量化）
  • 是 pandas / matplotlib / sklearn / PyTorch 的共同底座
  • print 数组是 [1 2 3]（元素间无逗号）

创建数组

  • np.array(列表)：从列表 / 嵌套列表创建
  • np.arange(起, 止, 步)：不含止
  • np.linspace(起, 止, 个数)：含两端
  • np.zeros / ones / full(shape, 值)、np.eye(n)
  • reshape(2, 3) 改形状；-1 让 NumPy 自己算
  • 元素总数必须匹配，否则 ValueError

属性与访问

  • shape 形状元组、ndim 维数、size 元素数、dtype 类型
  • 一维：a[3]、a[-1]；切片 a[0:3]、a[::2]、a[::-1]
  • 切片是视图，改切片会改原数组；要副本用 .copy()
  • a[[1,2,5]] 列表下标：可选乱序 / 重复，得到副本
  • 二维：a[行, 列]；a[0] 是整行；a[:,0] 是整列
  • a[a > 15] 布尔索引：先造掩码再挑选

运算

  • a.T 转置：交换两个轴；一维转置不变
  • + - * / ** 都是逐元素运算
  • * 不是矩阵乘法！矩阵乘法用 np.dot(a, b) 或 a @ b
  • 一维·一维 dot = 内积（一个数）；(m,k)·(k,n) = (m,n)
  • 广播：形状从右往左对齐，相等或其中一个是 1 就能算
  • 形状不兼容会报 ValueError

统计与 axis

  • min / max / mean / sum / std / var / argmax / argmin
  • 不写 axis：对整个数组算，得到一个数
  • axis=0：沿第 0 轴压掉行 → 每列出一个数
  • axis=1：沿第 1 轴压掉列 → 每行出一个数
  • 一句话：axis 就是你要压掉的那一维
  • argmax() 返回的是下标不是值

排序与变形

  • np.sort(x) 返回新数组，不改原数组
  • x.sort() 原地排序，原数组被改
  • 二维排序要指定 axis，np.sort 默认 axis=-1
  • reshape 改形状；ravel 拉平（尽量返回视图）、flatten 拉平（返回副本）
  • np.concatenate / vstack / hstack 拼接
  • np.argsort(x) 返回排序后的下标，取前几名很好用

二、易错清单（都在这台机器上真实踩过）

现象 / 报错原因正确做法
a * b 的结果跟手算的矩阵乘法对不上 * 是逐元素相乘 矩阵乘法用 np.dot(a, b) 或 a @ b
改了切片，原数组跟着变了 切片是视图不是副本 要独立副本用 a[0:3].copy()

axis=0、axis=1 结果跟预期反了 把"沿哪个轴"理解成了"结果有几行" 记住 axis 是压掉的那一维：axis=0 压行 → 每列一个数
ValueError: operands could not be broadcast together 两个数组形状无法广播 用 reshape 调成可广播形状；先看 a.shape 和 b.shape

两次运行结果不一样 用了 np.random 却没固定种子 先 np.random.seed(0)，结果可复现
