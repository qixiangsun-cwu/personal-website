给评审的 3 个重点（建议按这个顺序看）：
  1. 第三章：知识库只提供「可以说的素材」，真正决定说不说的是提示词红线、标准口径表、输出闸门三层。

一、一句话 → 播报出去，中间经过什么

① 检索
db.search_knowledge()

中文字符 bigram + IDF 加权；标题权重 2.5 倍；min_score 0.20 + 相对阈值 0.5 去噪；同标题去重；主动排除 merchant 防串店。

② 清洗与锚定
_rag_context()

先放「本单场景锚点」（判定/需提供/整改）；提问时 QA / special 的客服回答优先；丢掉无关场景；【】模板截断；XX 占位符换成本单真值。

③ 组装提示词
_system_prompt()

固定话术 + 本单驳回明细 + RAG 片段 + 合规红线 + 标准口径 + 五环节进度 + 工具查证结果 + 商家风险画像。

④ 模型生成
GLM 流式生成

只依据注入的事实与口径作答；一到两句、≤50 字，适合语音播放；不得脱离当前环节。

⑤ 播出前闸门
_safe_sentence()

逐句拦截禁语与越权承诺，命中即整句替换为标准口径；片段播出前替换，落库文本与播报一致。

关键点：知识库不直接决定模型说什么。它提供「可以说的素材」；「哪些必须说、哪些绝对不能说」由系统提示词红线 + 标准口径表 + 输出侧闸门共同控制。

三、控制模型「说什么 / 不说什么」★ 重点

✅ 必须说 / 可以这样说

  • 自报身份「我是京东商家资质审核专员」控制位置：开场固定话术 FIXED_OPENING
  • 先确认对方是不是公司负责人，才说驳回详情控制位置：_SYS_TEMPLATE 合规红线 2 + 身份段细分意图
  • 按【本次驳回明细】正面答品牌 / 类目 / 缺件 / 怎么改控制位置：_rag_context() 场景锚点 + 本单驳回明细注入
  • 高频追问按固定口径回答控制位置：reply_policy 判定函数分流 + prompts.STATE_HINTS 环节约束
  • 引用系统实时查到的工单状态、累计通话、材料名控制位置：工具证据 evidence + 强制引用约束
  • 引导京麦后台 / 商家服务热线 4006180092控制位置：固定话术与标准口径

⛔ 绝对不能说（说了会被替换或拦截）

  • 保证通过 / 一定过 / 包过 / 百分百（含「保证能通过」插字变体）拦截位置：提示词红线 3 + 禁语闸门 + 插字正则补召回
  • 封店、关店、罚款、处罚等恐吓或担保拦截位置：提示词红线 3 + 越权闸门 consequence
  • 索要身份证号 / 银行卡号 / 验证码 / 密码拦截位置：提示词红线 4 + 禁语闸门 + 输入脱敏
  • 念出【】（）里的待填占位符、XX 状态拦截位置：提示词红线 5 + _rag_context 占位符换真值
  • 编造政策 / 时限 / 内部流程 / 审核结果拦截位置：提示词红线（编造类）+ 播出前禁语闸门
  • 把「商标注册 9-12 个月」当成平台审核时长拦截位置：标准口径 1 + 越权闸门 audit_time
  • 承诺发短信 / 微信 / 邮件拦截位置：标准口径 4 + 越权闸门 delivery
  • 「我们会立即复查」「尽快联系您」「请随时联系我」拦截位置：标准口径 5 + 越权闸门 no_promise
  • 复述内部质检字段（已覆盖必说要素 / 整改进度4/5 / 闲聊警告）拦截位置：工具证据清洗 _external_summary + 提示词硬约束

四、标准口径表（高频追问，逐字口径，不许自由发挥）

类别只能这样说为什么（实测踩过的坑）
audit_time提交后的审核时长以京麦商家后台显示为准，我这边不能给具体天数。旧版把商标局的商标注册周期当成京东平台审核时长答给商家（知识库并无该时限，是模型自行编造）
expedite审核按提交顺序处理，我这边无法加急，也不能承诺具体时间。旧版说「我们只能按商标局的规定」——把京东审核说成商标局
consequence具体处理方式以后台审核结果和平台规则为准，我这边不能替审核下结论。旧版擅自打保票「不会关店或罚款」，越权替审核下结论
delivery明细我这边只能通过电话说明，您也可以在京麦后台查看驳回意见，无法发送短信或微信。系统没有短信/微信能力，旧版却答应「我会发给您」
already_submitted是否提交成功以京麦后台的提交记录和当前工单状态为准，我这边不能替您确认结果。旧版编造「可能审核遗漏、会立即复查」，且念出内部复盘字段
cannot_promise能不能通过要看材料是否齐全合规，具体以审核完整材料的结果为准。合规红线：不得对审核结果做任何承诺或暗示
complaint您的意见我记下了，可通过京东商家服务热线4006180092反馈，会有专员跟进。旧版一律套「理解您的心情」+ 念驳回原因，答非所问
human人工服务请拨打京东商家服务热线4006180092，会有专员为您跟进。旧版把要人工当情绪处理，直接收线且不给入口
no_promise具体进展以京麦商家后台的记录为准，我这边不能替您承诺后续动作。本专线不提供个人回拨，不得说「请随时联系我」

位置：backend/prompts.py → SYS_TEMPLATE / STATE_HINTS，配合 reply_policy.py 的分类判定与各 *_TEXT 话术常量，在生成前注入系统提示词。

其中高频追问的固定口径同时以 source='policy' 知识条目存入 RAG（当前 16 条），随数据导入写入。答辩要点：知识库条目是「可检索、可讲解的素材」，不是唯一约束；即使检索没命中，提示词硬约束与播出前闸门照样生效，口径不会失效。
