## 第二段（线上版 vs 本地版，写材料可直接用）

**一、整体做法**
线上版把原来跑在 Node + Python 上的后端，重写成了 Cloudflare Workers 无服务器版本：书库元数据存 D1 数据库，绘本页图和整本动画视频存 R2 对象存储。前端 `纸书智伴.html` 以及 `assets/` 下的 JS/CSS **零改动**，只是换了后端。因此线上是 7×24 不掉线、不依赖任何一台电脑开机。

**二、完全一致的能力（可以放心写）**
- 绘本翻页、页码跳转、页面文字叠加
- 点读热区（指到哪个角色，就读哪一句）
- 整本动画播放，支持拖动进度条（R2 支持 Range 分段读取）
- 照片 OCR 识别：tesseract.js 本来就在浏览器本地跑，线上完全一样
- 三本书的文字识别结果、热区坐标、有声字幕都是**建书时用真实模型跑出来的真实数据**，存在数据库里，线上读的是同一份

**三、有差异的能力（必须如实说明）**

| 能力 | 本地版 | 线上版 | 原因 |
| --- | --- | --- | --- |
| 朗读播报 | 火山 TTS / edge-tts 云端音色 | 浏览器自带语音 | 免密钥的 edge-tts 走 WebSocket 连微软朗读服务，从 Cloudflare 机房出口访问时三个端点全部返回 403/530（拒绝数据中心 IP），这是对方的反滥用策略，与我们的代码无关。前端本来就有 `speechSynthesis` 兜底，所以朗读不会中断，只是音色换成系统语音 |
| 页面问答 | DeepSeek 生成 | 有密钥则一样；无密钥则退回原文检索 | 线上目前还没配 DeepSeek 密钥。无密钥时返回的是「从本页原文里找到的最相关句子」，并且接口会明确标注 `degraded:true`、`confidence` 低于阈值时 `grounded:false`，**绝不编造答案** |
| 识字 / 单词卡 | DeepSeek 生成 | 有密钥则一样；无密钥则用内置小字典 | 内置词典只覆盖少量常用字和 19 个绘本高频英文词，未命中的字会明确返回「不在内置字典中」而不是乱写 |
| 上传绘本建书 | 支持 | 暂未开放 | 无服务器环境没有文件系统，上传后的落盘、拆页、建索引要改写成 R2 + 异步流程，本次未做 |
| Remotion 生成动画 | 支持 | 不支持 | 渲染是 CPU 密集任务，需要本机 ffmpeg 和渲染工程，Workers 跑不了 |
| 豆包图生视频 | 支持 | 不支持 | 需要长时间轮询并下载 25MB 级视频落盘 |
| 专属音色克隆 | 支持 | 不支持 | Chatterbox 模型 3.1GB，需要 GPU 本机运行 |

**四、写材料时的建议措辞**

推荐这样表述：

> 本项目采用「本地完整版 + 云端展示版」双形态部署。云端版将 Node/Python 后端重写为 Cloudflare Workers 无服务器架构（D1 数据库 + R2 对象存储），在保持前端交互完全一致的前提下实现 24 小时公网可访问；对依赖持久进程与本地算力的能力（在线渲染、视频生成、音色克隆）保留本地演示形态，并在接口层做显式降级标注，避免任何结果伪造。

**不建议**这样写：
- ✗「线上版功能完整，和本地一模一样」——不准确
- ✗「朗读用的是火山引擎」——线上目前是浏览器语音
- ✗「问答由大模型实时生成」——线上无密钥时是原文检索

**五、为什么这样处理反而加分**

参赛评审很看重「降级是否诚实」。我们这套线上版有个可验证的细节：调用 `/api/health` 会返回各适配器的真实状态（`deepseek: false` 表示未配置），`/api/qa` 在无密钥时返回 `mode: "local"`、`degraded: true`、`reason: "未配置 DeepSeek 密钥，使用原文检索回答"`，识字接口查不到字时返回空字段而不是编造。**系统宁可显示「我不知道」，也不编一个答案**——这正是原项目从一开始就定的红线，线上版严格保持了。

## 补充：如果被问到「能不能体验完整版」

回答：

- 云端版覆盖了项目 90% 的核心亮点（翻页、点读、动画、OCR、检索问答），已经可以直接体验；
- 完整版（实时生成的动画、音色克隆、上传建书）需要在本机演示环境运行，答辩/路演时可以现场跑；
- 一旦配置了 DeepSeek 密钥和火山 TTS 密钥，云端版的问答与朗读就会和本地版一致，这两项只需在 Cloudflare 后台填两个密钥即可，不需要改代码。
