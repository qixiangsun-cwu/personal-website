Part 1 · WebXR 交互进阶：把 9 个零件装成一套系统

430 讲的五个点：输入源三字段 → select vs squeeze → 状态机 → 双手变换数学 → 双阈值吸附 / poke vs 射线

一、输入源三字段：XRInputSource 到底告诉了你什么

页面右上角的输入源检查器是这节课的“教学利器”——它把 inputSource 摊开给你看：

字段回答的问题典型值课堂要点
handedness哪只手'left' / 'right' / 'none'没有它，你无法判断“谁在抓”，吸附判定该信谁就说不清
profiles什么设备字符串数组（型号 / 能力）同一段代码要在不同头显上跑，靠它分支
gamepad按了什么、摇杆在哪buttons[] / axes[]扳机、握持键、摇杆都从这里读；不要写死按键序号
PC 上为什么看到“模拟源”：没有头显时检查器显示的是PC 模拟输入源——这不是 bug，是故意的：没有设备也能讲清字段。戴进真机后，同一个面板会显示真实手柄。

二、select vs squeeze：抓取为什么不用扳机

事件族三个事件就是适合
selectselectstart / select / selectend扳机“点一下”——按下去、抬起来，一件事结束点击、确认、开火
squeezesqueezestart / squeeze / squeezeend握持键“握住”——按住多久，就持续多久抓取、拖拽、双手变换
一句话结论：抓取是“持续动作”，所以用 squeeze。用扳机抓，会出现“按住才拿得住、一松手就掉”的别扭感，甚至“想抓却把东西点飞了”。

三、状态机：什么条件下允许发生什么

01 页面里每个物体都有自己的状态，颜色就是状态的可见证据：

idle ──hover──▶ hover ──grab──▶ grab ──snap──▶ snap
  │               │                │              │
  └─poke──▶ active│                └─release──▶ idle
                  └─unhover──▶ idle
另有 disabled（禁用）：disabled ──enable──▶ idle

转移表：TRANS = { idle:{hover,grab,poke}, hover:{unhover,grab,poke,disable},
                 grab:{release,snap,disable}, snap:{release,hover,grab,reset}, … }
被拒绝的转移记在 S.lastReject（课堂上「删掉 idle→grab 出口」就能看到）
你改的 SNAP_DIST，不只是改一个数——它改的是 grab → snap 这条转移什么时候允许发生。删掉 idle → grab 出口后，“没悬停就能抓”的入口没了：必须先 hover 才能 grab，这不是 bug，是规则。

四、双手变换数学：间距 → 缩放，相对角 → 旋转

两只手同时抓同一个物体时（以「抓取那一帧」为基准，不是每帧累加）：

  缩放：  scale = d_now / d_start        （d = 两手之间距离）
  旋转：  rot   = θ_now − θ_start        （θ = 两手连线的相对角）

反例（错的做法）：每帧 scale *= (d_now / d_prev)
  → 手会抖、帧率会变，误差越缩越偏；松手 / 换手就断了
正确做法：始终相对「抓取瞬间」算绝对值 → 两手回原位，物体就回原样
为什么不能逐帧累乘：手抖、掉帧、换手都会把误差累积进去，而且松手再抓就没有基准了。“相对抓取瞬间”的绝对算法才可复现——这也是实训里 orb.scale 1 → 2、ΔrotY = 30° 能被实测验证的原因。

五、双阈值吸附 ＋ poke / 射线两条通道

机制阈值为什么不只用一条
吸附插槽距离（SNAP_DIST 默认 0.30 m）＋ 角度（朝向落在扇区内）只看距离：歪着也会被吸过去；只看角度：隔空也能吸。两个都满足才吸，才叫“对齐”
poke 直触POKE_DIST 0.14 m（手 / 柄尖到按钮）近处直接戳最自然；超过 0.14 m 就应该用射线，不用“伸长手”
射线按钮RAY_MAX 6.0 m远处用射线；同一个按钮两条通道，靠距离阈值切换
把 SNAP_DIST 从 0.30 改到 0.60，就变成“隔空老远就吸上”——误吸附比吸不上更糟，因为用户失去控制感。这就是练习 1-A 要你对比 0.12 / 0.30 / 0.60 的原因。

二、许可：四种必须分清

许可能商用？要署名？能不能进你的作品
CC0（Public Domain）✅❌ 不要求可以最省事（ArmChair_01、Fox 的模型本体）
CC-BY（如 4.0）✅⚠️ 必须可以但作品里要写清作者与来源（CesiumMan、Fox 的绑定动画）
CC-BY-NC❌ 禁止商用⚠️ 要不能进作品只当“许可陷阱”案例（DamagedHelmet）
SCEA Shared Source（不是 CC）✅（无 NC 限制）Object Form 再分发免署名（§6）可以但要读条款（Duck；§3 禁止就它申请专利 / 寻求版权保护）
待核实未知未知只能写“待核实”（WaltHead.obj / SambaDancing.fbx 在 three.js 仓库没有许可声明）
DamagedHelmet 就是许可陷阱：3,773,916 B / 15,452 三角面 / 5 张纹理，看着最漂亮，但模型本体是 CC-BY-NC 4.0（禁止商用）。课程作品虽然不直接卖钱，但公开发布、参赛、展示都有商用风险——课堂口径：不进作品，只在 03 转换器里当“怎么读许可、怎么判定不能用”的案例（它也刻意没放进 models\ 内嵌页）。

三、GLB vs GLTF：为什么最后要“一个文件”

.glb（二进制 glTF）.gltf（文本 glTF）
形态一个文件：几何 ＋ 贴图 ＋ 动画全打包一组文件：索引 .gltf ＋ .bin ＋ 贴图
传输 / 嵌入单文件，能直接内联进单文件页（base64）少一个文件就加载失败
file:// 双击✅ 可用❌ 常因 CORS / 相对路径失败
课堂结论交付用 GLB（WebXR 首选）下载时常拿到它（Poly Haven 就是 gltf＋纹理），转一步再进作品

四、转换 ≠ 优化（本课最重要的一条数字）

把一个 GLB 原样“再转一次”：
  Duck.glb   120,484 B  ──03 模型转换器 GLB→GLB──▶  152,408 B    （+26.5%）

为什么变大？贴图重新编码、缓冲重排——「再转一次」不是优化。
真要变小：减面 / 贴图降采样 / Draco / meshopt（第 10 次课的内容）。
这条数字 430 现场会投出来（03 转换器的真实统计）：你下载的模型转成 GLB 就完成“能用”，不是“变好”；“转了”和“优化了”是两件事。作业单里的“转换前后对比表”就是让你亲眼记录这件事。

六、归一化：为什么导入后先“缩到 1.2 m”

不同来源的模型单位五花八门——有的 0.1 m 高、有的 10 m 高，原点有的在脚底、有的在中心。所以工作台导入时统一做三件事：缩放（NORM_HEIGHT = 1.2 米高）→ 贴地 → 居中。 不归一化，你的场景就是“巨人和蚂蚁”：Fox、CesiumMan、Duck、ArmChair 来自四个不同来源，进场景后全被缩到 1.2 m，这是资产管线的必要一步。

七、场景 JSON 与许可卡：把“摆好的东西”变成能带走的数据

场景 JSON（02 导出）

{
  "format": "workbench-scene",
  "unit": "meter",
  "modelCount": 4,
  "models": [
    { "id": "fox", "name": "Fox", "file": "Fox.glb",
      "license": "CC0 + CC-BY 4.0", "author": "PixelMannen / @tomkranis",
      "pos": [x,y,z], "rot": 45, "scale": 1.5, "color": "#ff0000",
      "anim": "Survey", "triangles": 576 }
  ]
}

实测：同一场景连续导出两次，字符串完全一致（可复现）；VR 里摆的东西只有存成数据才带得走。
