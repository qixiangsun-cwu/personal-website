自检报告（截图或复制给老师）

如果第 ② 项是"否"：三条把它变成"是"的路

原理只有一句：浏览器只在安全上下文里暴露 navigator.xr。 https://、http://localhost、http://127.0.0.1 都算； 电脑的局域网 IP（http://192.168.x.x）不算。

通路怎么做适用场景
A · USB 直连
（最稳）		 数据线连头显 → 电脑上执行 adb reverse tcp:8080 tcp:8080 → 头显浏览器打开 http://127.0.0.1:8080/。 头显里的 127.0.0.1 会被转到你的电脑上，所以既是安全上下文、又不走网络。 教室网络差、上课演示
B · 传到 https 站点
（最省事）		 把你的文件交给老师，放到课程站点的学生作品目录里， 头显直接打开 https://…/student/你的学号/。 要交作业、要让别人看到
C · 局域网 + 白名单 电脑起静态服务（绑定 0.0.0.0），头显浏览器访问 http://电脑IP:8080/；先在头显浏览器里打开 chrome://flags/#unsafely-treat-insecure-origin-as-secure， 把 http://电脑IP:8080 填进白名单并启用。 电脑 IP 一变就要重填。 自己反复调试
一条常被忽略的坑：就算环境全对，「进入 VR」也必须由用户手势触发 （必须有人点一下按钮）。所以不要写"打开页面自动进入 VR"——规范不允许，各家浏览器也都不给。

把自检贴进你自己的作品

同一目录下的 vr-probe.js 是一个可以直接引用的探针：在你自己页面的 <head> 里加一行 <script src="vr-probe.js"></script>， 页面角落就会出现一个小面板，实时显示 FPS / DrawCall / 三角面 / 报错 / 是否在 VR 会话中。 头显里也能看见——这样你戴着就能知道"到底是没进 VR，还是进了但画不出来"。
