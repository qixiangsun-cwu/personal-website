07 · 进入 VR 的四步检查

这段代码就是"进不去 VR"时的排查顺序。每一步都可能失败，而每一步的失败原因都不一样。

第 0 步（前提）· 是不是安全上下文

检测中…
WebXR 只在 https:// 或 http://localhost（127.0.0.1） 下可用。 file:// 双击打开、局域网 http://192.168.x.x —— 浏览器会把 navigator.xr 直接藏起来， 这时测出的"设备不支持"是假结论。

第 1 步 · navigator.xr 是否存在

检测中…
不存在 → 要么不是安全上下文，要么浏览器没有实现 WebXR。先回第 0 步查。

第 2 步 · isSessionSupported('immersive-vr')

检测中…
返回 false → 浏览器有 WebXR，但这台设备不支持沉浸式 VR 会话（没有头显，或头显没连上）。

第 3 步 · 按钮是否可点，以及能否真正进入会话

检测中…
requestSession 的能力写在 requiredFeatures 而设备不支持 → 会话直接失败； 写成 optionalFeatures → 有就用、没有就降级。本项目用的是可选。

四种访问方式对照

方式安全上下文能进 VR 吗
file:// 双击否不能（只能看画面）
http://192.168.x.x否不能（除非加浏览器白名单）
http://127.0.0.1是能（本机服务 / USB 端口转发）
https://…是能（课堂首选）

最省事的做法：放到网络上

把它放到 HTTPS 上，就一次性解决了安全上下文、分享、离线三件事。 本课程网站已经托管了这份场景，头显里输入一个网址就能打开。 

# 没有公网空间时的本地兜底（仍然是安全上下文）
python -m http.server 8080
# 浏览器访问 http://127.0.0.1:8080/你的页面.html
# 头显侧：USB + adb forward tcp:8080 tcp:8080
