学生作品 · 联网自验工作流

你做好了 VR 作品，怎么让头显打开它、并且确认它真的进了 VR？ 这一页把三件事讲完：怎么起服务 → 怎么让头显连上 → 怎么判断是环境问题还是你的代码问题。

先记住这一条，它能省你两小时： 浏览器只在 安全上下文 里暴露 navigator.xr。 https://、http://localhost、http://127.0.0.1 算安全上下文； 你电脑的局域网 IP（http://192.168.x.x）不算。 所以用局域网 IP 打开自己的页面时，看不到"进入 VR"按钮、控制台里 navigator.xr 是 undefined—— 那不是你的代码写错了，是环境不满足。先按下面 A 或 C 把它变成安全上下文，再 debug。

第一步 · 起一个本机服务器（不用装任何东西）

本目录下的 serve.bat / serve.ps1 是一个 零依赖的静态服务器（只用 Windows 自带的 PowerShell，不需要 Python、不需要 Node、不需要管理员）。

  1. 把 serve.bat 和 serve.ps1 下到你自己的电脑上（右键 → 另存为，或找老师要）；
  2. 把它们和你的作品文件放在同一个文件夹里；
  3. 双击 serve.bat。窗口里会打印两个地址，这个窗口不要关。
============================================================
  VR 作品 · 本机服务器已启动
------------------------------------------------------------
  根目录 : D:\我的VR作品
  端口   : 8080

  头显里打开（USB 转发 / 安全上下文）:
      http://127.0.0.1:8080/

  头显里打开（同一 Wi-Fi，需先在头显浏览器加白名单）:
      http://192.168.x.x:8080/
============================================================

想换目录或端口：serve.bat "D:\我的VR作品" 8081 （也可以直接建个快捷方式，省得每次敲）。

第二步 · 让头显打开它：三条通路

通路怎么做什么时候用
A · USB 直连
安全上下文 ✅		 1）数据线连头显，头显里点「允许 USB 调试」（需先开开发者模式）；
2）电脑另开一个窗口执行：
adb reverse tcp:8080 tcp:8080
3）头显浏览器打开 http://127.0.0.1:8080/。
头显里的 127.0.0.1 会被转到你的电脑上，所以既是安全上下文、又完全不走网络。 		课堂、教室网络差、要最稳的效果
B · 交到课程站点
安全上下文 ✅		 把作品文件夹交给老师，放到课程站点的 /assets/vr-2026/student/<学号>/， 头显直接打开 https://站点/.../student/学号/。 要交作业、要让同学和老师都能看
C · 局域网 + 白名单
要一次配置		 1）头显与电脑连同一个 Wi-Fi；
2）头显浏览器打开 chrome://flags/#unsafely-treat-insecure-origin-as-secure；
3）把 http://你的电脑IP:8080 填进去，设为 Enabled，重启浏览器；
4）再打开 http://你的电脑IP:8080/。
电脑 IP 一变就要重填。 		自己反复调试、不想插线
头显连不上？按这个顺序查： ① 电脑和头显是不是同一个 Wi-Fi（校园网/手机热点常开「客户端隔离」，会直接连不上，那就换热点或走 A 路）； ② 电脑上的防火墙有没有拦（第一次运行 serve.bat 时如果弹出"允许访问网络"，要点允许）； ③ IP 有没有写错——以 serve 窗口里当时打印的为准，不要用聊天记录里的旧 IP。

第三步 · 判断"是环境问题，还是我的代码问题"

这是最容易浪费时间的一步。规矩很简单：先用一个你确定没问题的页面确认环境，再回头改自己的代码。

打开《VR 作品自检》 下载自检探针 vr-probe.js

① 环境自检页（../check/index.html）

  • 在头显里打开它，六项状态一次看全：安全上下文 / navigator.xr / immersive-vr / WebGL / 输入设备 / 能不能真的进 VR；
  • 它自带一个极简场景：看到方块 = 渲染正常；注视靶变绿 = 注视交互正常；
  • 点「生成自检报告」，把那段文字复制或截图给老师。

② 把探针贴进你自己的作品（vr-probe.js）

在你的页面里加一行就够：

<script src="vr-probe.js"></script>

页面右上角会出现一个小面板，实时显示：四项 WebXR 前提、FPS、DrawCall、三角面、 以及你页面里所有的 JS 报错。改完代码刷新就能看到变化，不用再猜。

一个必须知道的限制：这个面板是 DOM 元素，进了沉浸式 VR 就看不见了 （WebXR 只渲染 3D 场景，不渲染网页覆盖层）。 所以要么在 2D 模式/投屏/镜像里看它，要么临时把读数画进 3D 场景里。 「沉浸模式下看不见 HTML 面板」这条，本身就是一次值得记住的工程经验。

交作品前 · 自查清单

  1. 用 Chrome 或 Edge 打开过，控制台没有红字；
  2. 在自检页确认过环境：安全上下文 ✅、immersive-vr 支持 ✅；
  3. 头显里能进入 VR、能转一圈、能退出（三条退出路至少试通一条）；
  4. 页面里没有外部网络依赖（不要引 CDN；图片、字体、库都放本地同目录）—— 机房一断网，你的作品就白了；
  5. 文件名不要用中文和空格（部分机房电脑会乱码或直接打不开）；
  6. 把自己作品的 FPS / DrawCall 记下来，课堂上要说得出"我改了什么、数字怎么变"。
