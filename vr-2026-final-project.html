一

一句话：你要交什么

一件能戴进头显里玩的作品 + 一份讲得清来龙去脉的说明

一件用 WebXR 做的、能戴进头显里玩的虚拟现实作品，加上一份能讲清「我做了什么、为什么」的说明。

形式与数量

  • 用网页做（Three.js / WebXR），不用 Unity；
  • 一个人做一件——不是小组项目；
  • 现场演示 3—5 分钟；
  • 主题自选，但不能把课内案例 01—06 交一遍。

要满足的三件事

课程的能力目标是「独立完成一个体现虚实融合 + 智能交互特点的 VR/AR 小项目」。所以你的作品要满足：能跑 · 能演示 · 体现「为什么必须用 VR」。

一、交付物长什么样

作品本体

一个能在头显浏览器里打开、点「进入 VR」、走完主流程的页面。依赖放同目录或内联，断网也能跑。

说明文档

README.md：我改了什么 · 为什么这么改 · 怎么运行 · 哪里还没做完（四行就够）。

演示与证据

封面图 cover.jpg（1280×720）+ 体验数据 xr-data.json + 现场 3—5 分钟路演。

为什么禁止直接交课内案例：案例 01—06 是课上一起写过的参考实现，交它们等于交课堂练习。可以读它们的源码、抄它们的技术，但主题、完成度、交互数量都必须明显不同——这一条在评分量规里直接对应「VR 学科理解」与「演示与文档」两维。
二

十条硬门槛（缺一条就不合格）

不是加分项，是及格线。逐条配了「怎么算过（自查）」——能自己判，就不要等老师判

#门槛怎么算过（自查）
1 能进能退 在头显里进入 VR，走完主流程，三条退出路至少试通一条并报出用时
2 零外部网络依赖 拔掉网线 / 关掉 WiFi 也能跑；不引任何 CDN，依赖库放同目录或内联进 HTML
3 无报错 控制台没有 JS 报错，主流程能连走两遍
4 为什么必须是 VR 至少有一处只有头显才能成立的体验（绕到背后看、钻进去、真实尺度、双手协同），并在说明里写清
5 ≥3 种交互 例如：抓取 / 射线点按 / 传送 / 3D 面板按钮 / 投掷。PC 和 VR 两端都要能走完主流程
6 有目标、有反馈、进度可见 状态集中在一个对象里，能用 window.你的名字.S 查到
7 舒适度 默认传送 + Snap 45°；有隧道视野、眼高显示、一键重置、10 分钟休息提示
8 性能 有实时性能面板（FPS / DrawCall / 三角面）；三角面 ≤ 10 万；至少做一处有前后对照的优化
9 可访问性 坐姿 / 单手 / 注视停留至少两条通路可用，且能等价走完主流程；说明你的取舍
10 诚实 涉及校史、文物、机构等真实信息，不确定的一律写 【待补充】，不许编。说明里要写「已知简化」
「缺一条就不合格」是字面意思。第 1 条和第 8 条在历届里翻车最多：退不出去的作品在真实课堂上一定会出事；性能是戴进去才知道的，别留到最后一周。

一、上机前先用自检页跑一遍

第 2 / 3 / 7 / 8 / 9 条都能在电脑上先自查一轮：打开 《VR 作品自检》，看协议 / 安全上下文 / navigator.xr / immersive-vr / WebGL / 输入设备六项状态。环境项有 ❌ 就先解决环境，不要去看自己的代码。

二、怎么用这份清单

  1. M1 之前通读一遍——避免选一个天然撞门槛的题（比如「纯全景漫游」过不了第 5 条）；
  2. M3 硬门槛那天逐条打勾——第 1、3、5、7、9 条必须是真机验过的，不能是「应该可以」；
  3. M5 封版那天再逐条打勾一遍——封版后只修错、不加功能，但错要修完。
三

怎么评分：100 分 + 5 分加分

五个必评维度合计 100 分，另设 +5 加分；过程数据不排名，但完成度与得分算证据

一、必评五维（合计 100 分）

维度分值满分长什么样
功能完整25主流程两遍都通、无报错、自测通过
VR 学科理解20讲得清「沉浸 / 交互 / 构想」、临场感要素、晕动机制，而且这些理解体现在你的改动里
交互与人因20≥5 种交互且各有提示（高亮 / 悬停），PC 与 VR 等价，可访问性两条通路并说得出取舍
性能与工程15达到 72Hz 帧预算意识、有降级手段与优化对照、状态机清晰、能导出体验数据
演示与文档203—5 分钟讲清「做了什么、为什么」，说明文档诚实完整
加分+5智能交互（LLM）/ AR 虚实融合 / 思政题材 —— 三者任一生效且有降级方案

但完成度 / 得分数据算证据：用内核的 XRCore.goal() 记下的成绩会随数据一起导出，可以证明你真的跑完了。

二、每一维的三档标准（优 / 合格 / 不合格）

维度权重优（满分）合格（60%）不合格
功能完整25 主流程两遍无阻、无报错、自测通过 主流程可用，个别边角失效 主流程断裂

演示与文档20 3—5 分钟讲清「做了什么、为什么」，README 诚实完整 讲得完整但说不出取舍 讲不清 / 无文档
加分：智能交互 / AR 虚实融合 / 思政题材+5 三者任一生效且有降级方案 尝试过但未跑通 ——

三、这份量规的三个口径

① 分数从哪来

功能完整 25 + VR 学科理解 20 + 交互与人因 20 + 性能与工程 15 + 演示与文档 20 = 100，另有 +5 加分。

② 为什么「演示与文档」值 20 分

期末是大作业路演：3—5 分钟讲不清「做了什么、为什么」，观众与评分人都无法判断你真的做了什么。所以它独立占分。

③ 可访问性去哪了

课堂作业量规里「可访问性 +5 加分」已并入「交互与人因 20」——它已经是硬门槛第 9 条，不再另设加分。

注意两个数字的差别：硬门槛第 5 条是「≥3 种交互」（及格线），量规里拿满分要「≥5 种交互」（满分线）。先保 3，再冲 5。

时间交什么内容

二、三次课之间的自检节奏

M1 → M2
先把「为什么必须 VR」写死
这一句话决定了后面所有交互的设计依据。写不出来，说明这个题用普通网页也能做——换题比硬做省时间。
M2 → M3
设计图不许再改
动线图与状态机图定下来的那一刻，剩下的时间只用来「把它做出来」。中途改设计，是返工的唯一来源。
M3 → M4
先能玩，再看性能
M3 当天必须走完主流程并记录退出用时；M4 才谈优化——顺序反过来会陷入「一直在调性能，主流程还没通」。
M4 → M5
优化必须有前后对照
「我优化了」不算证据，「DrawCall 从 101 降到 2」才算。对照数据要能对上页面 HUD（见第九节）。
M5 → M6
只修错，不加功能
封版后的每一天都用来：跑主流程两遍、补 README 的四行、把已知简化写清楚、练一遍 3—5 分钟的路演。
M6 当天
现场演示 3—5 分钟
一句话说清「我做了什么、为什么」；再说清「我卡在哪一环——环境、作品还是设备」。两份材料：作品目录 + 体验数据。

六

怎么跑起来：三条通路 + 三条退出路

先怀疑环境，再怀疑代码——这一节一半的价值在这句话上

WebXR 只在安全上下文里可用。用 http://电脑IP:8080 直接开，头显里看不到「进入 VR」按钮，学生会误判成「我代码坏了」。

口号：先怀疑环境，再怀疑代码。
file:// 不是安全上下文 → navigator.xr 是 undefined → 页面上根本没有「进入 VR」按钮。「装进头显」的正确说法是「在头显里通过 https / localhost / 白名单地址打开」，不是「把 html 拷进去」。

一、三条通路（走通任意一条即可）

通路怎么做要不要配
① USB（首选） 数据线连头显，跑 adb reverse tcp:8080 tcp:8080，头显浏览器开 http://127.0.0.1:8080/ 需开发者模式 + adb；不走网络，教室网络再怎么隔离都不怕
② 局域网 电脑跑本机服务器；头显在 chrome://flags/#unsafely-treat-insecure-origin-as-secure 里填 http://电脑IP:端口 要配；IP 一变就得重填
③ 站点 https 作品交到课程站点的学生作品目录 ✅ 最省事，收作业与互评首选
零依赖本机服务器：serve.bat / serve.ps1（不需要装 Python / Node，也不需要管理员权限）。

二、为什么 file:// 打不开 WebXR

规范层面的原因

WebXR 会调用摄像头、手柄、眼动、空间追踪等敏感能力，所以规范要求它只在安全上下文（secure context）里可用：https: / http://localhost / http://127.0.0.1 算，file:// 与局域网 http://192.168.x.x 都不算。

你看到的现象

页面上没有「进入 VR」按钮，控制台里 navigator.xr 是 undefined。这不是你的场景做错了，是打开方式不对——换第 ① 或第 ③ 条通路即可。

三、三条退出路（每条作品都该有）

① 注视（或射线）点「退出」按钮

把退出按钮做成场景里的 3D 物件，不是网页浮层——沉浸模式下 DOM 看不见（见第九节）。

② 长按握把键 2 秒

手柄通路：不依赖视线、不依赖 UI，手边最顺手的一条。

③ 系统键返回

头显系统自带的一层保险；但不能只靠它——它是最后手段，不是你的设计。

至少试通一条，并报出用时。退不出去的作品不算完成。三条都试一遍更好：只有一条出口的应用，在真实课堂里一定会出事。

四、进不去 VR 时的排查顺序

  1. 先看地址：是不是 file:// 或局域网 IP？是就换通路；
  2. 再看自检页：打开 《VR 作品自检》，六项里协议 / 安全上下文 / navigator.xr / immersive-vr 有 ❌ 就是环境问题；
  3. 再看浏览器与设备：换个浏览器、重启头显浏览器再试；
  4. 最后才怀疑代码：到这一步，绝大多数情况是进入按钮没有由人手点一次——进 VR 必须人手点一次，这是规范要求，装成应用也一样。

怎么交

目录名一律 ASCII 学号；交作业姿势错了，作品再好也打不开

一、交到哪、交什么

assets/vr-2026/student/works/<学号>/
├─ index.html       ← 你的作品（依赖库同目录，或内联成单文件）
├─ README.md        ← 我改了什么 / 怎么运行 / 已知简化 / 哪些是占位

└─ xr-data.json     ← 体验数据导出
提交物要求
index.html作品本体。可带同目录依赖，或内联成真单文件；断网也能跑
README.md四行就够：我改了什么 · 为什么这么改 · 怎么运行 · 哪里还没做完（含「已知简化」与事实占位说明）
cover.jpg封面图，1280×720
xr-data.json体验数据导出（含 XRCore.goal() 记录的完成度 / 得分）
目录名一律用学号（ASCII），页面上显示中文姓名；作业墙按学号升序排列，卡片带作品类型标签。
作品目录统一放在站点：学生作业墙 assets/vr-2026/student/works/。

二、交作业姿势（历届最高频的事故）

⚠️ 右键 →「网页另存为（完整）」会带出一个 _files 文件夹。 只发 .html 给老师 → 依赖全丢，单独打开必然白屏。
正确做法：右键 →「另存为 → 网页（仅 HTML）」，或者直接下载原件；如果作品确实带同目录依赖，就把整个目录打包一起交。

三、提交前对一遍这张表

  1. 目录名是纯 ASCII 学号，没有空格、没有中文；
  2. 四件齐：index.html + README.md + cover.jpg（1280×720）+ xr-data.json；
  3. 拔网线打开一遍：能跑、控制台无报错、能点「进入 VR」；
  4. README 四行齐：我改了什么 · 为什么这么改 · 怎么运行 · 哪里还没做完；
  5. 数字对得上：README 与报告里的读数，和页面 HUD 上的一模一样（见第九节最后一条）。

资产拿到什么

一、性能口径（三个数必须记住）

72Hz = 13.9 ms

目标帧率是 72Hz，但每帧预算不是 16.7 ms——浏览器合成要占时间，所以按 13.9 ms 算。

移动头显三角面 ≤ 10 万

一体机的算力与功耗都有上限，超过这个量级很容易掉帧。这是保险线，不是随便定的。

先看 DrawCall，不要先看面数

优化顺序：先看 DrawCall（提交了多少次绘制命令），再看三角面。同一个画面，100 个方块各交一次 → 101 次 DrawCall；合成一个 InstancedMesh → 2 次。

二、怎么接上内核与探针

接内核 _xr_core.js

把库放同目录，用相对路径引入。接上之后，传送 + Snap、隧道视野、眼高显示、休息提示、体验数据导出就都有了——硬门槛第 7、9 条与量规「性能与工程」直接受益。

接探针 vr-probe.js

在自己的页面里加一行 <script src="vr-probe.js"></script>，就有 FPS / DrawCall / 三角面 / JS 报错四类读数，还会把读数画进 3D 场景——沉浸模式下只有 3D 面板看得见。

九

历届踩过的坑（照这个清单自查）

七条，全部真实发生过；调试不动的时候，先从头对一遍再动代码

坑表现怎么避
file:// 打开 没有「进入 VR」按钮 走三条通路之一
「网页另存为（完整）」 单独打开白屏 只存「仅 HTML」或下载原件
引用 CDN 有网能跑，机房断网白屏 库放本地同目录
disabled / hidden 被冻进 HTML 按钮显示「进入 VR」却点不动 运行时会被 JS 改的状态，代码里都要显式设一遍，别依赖 HTML 默认值
两套 three.js 混用 直接白屏 UMD 版（全局 THREE）和 ESM 版（import）不能互换
沉浸模式下 DOM 看不见 面板消失了 面板要做成场景里的 3D 物件，不能用网页浮层
数字对不上 报告里的读数和页面 HUD 不一致 编数据比做不出来更严重

一、这七条背后的三类原因

环境类（第 1—3 条）

都不是代码问题：安全上下文、依赖是否随作品走。记住口号「先怀疑环境，再怀疑代码」。

状态与版本类（第 4—5 条）

页面「看起来对」但「点不动」，多半是HTML 里的默认状态与运行时不符，或者两套库的加载方式冲突。

认知类（第 6—7 条）

沉浸模式里 DOM 不渲染、报告数字必须可复现——这两条不是 bug，是WebXR 与学术诚实的基本常识。

最后一条单独强调一遍：报告里的数字必须与页面 HUD 一致。评分时会当面对读数；对不上，其他部分做得再好也会被质疑。编数据比做不出来更严重。
十

安全与伦理

四条底线：人身安全 · 事实诚实 · 隐私与版权 · 密钥安全

① 戴上之前先看清周围

戴上之前先看清周围有没有人；戴着头显不许走动（要移动用传送）。教室设备一人一台，但空间是共享的。

② 眼镜同学先戴眼镜

眼镜同学先戴眼镜再戴头显；每人一副一次性眼罩。

③ 真实信息不确定就标占位

作品里涉及真实人物、校史、文物：不确定就标 【待补充】，不许编造。这一条同时是硬门槛第 10 条。

④ 大模型 Key 不能放前端

用到大模型 API：Key 不能写在前端（课堂演示级可以，正式产品必须走自家后端代理 + 限流 + 内容审核）。这条会讲，也会考。

一、做「加分项」时的额外要求

加分方向额外要求
智能交互（LLM）必须有离线降级兜底：断网 / 超时 / 幻觉时，作品要能继续走完主流程；Key 不进前端
AR 虚实融合手机端 WebXR 同样只在安全上下文可用；演示时准备好走 http 白名单或站点 https
思政题材史实、机构、人物信息不确定一律标 【待补充】；素材要有版权说明
一句话收束这份任务书：做出一个能跑、能演示、能说清「为什么必须用 VR」的作品，比做出一个看起来很大但走不完主流程的作品，分数高得多。
