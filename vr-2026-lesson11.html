本讲导览

上一次课我们数的是毫秒；这一次课我们数的是 token、轮数，以及完成度

第 10 次课每个人交了一份 M4 性能报告——"优化前 / 优化后"两组读数摆在那里，说明你已经会度量自己的作品了。这一次课做两件互为表里的事：让作品会说话（接一个真正的智能交互模块，而不只是预设文本），以及让它能被度量（把体验过程写成一份 JSON，让"我玩得怎么样"变成可评分的数据）。

本课命题（板书第 1 行）：智能交互不是"接一个 API"，是设计"接不上时怎么办"。
在线大模型会限流、会超时、会断网、会编造。一件要靠它说话的作品，如果没想清楚"它不回答时怎么办"，那不是一件作品，是一次演示。离线兜底是及格线，在线模型是加分项。

这节课最难的也不是画质，是"边界"：模型能说什么、能做什么、答不上来时退到哪。这三条想清楚了，作品才敢交出去；想不清楚，路演现场网络一抖就是事故。所以下面六个问题本讲都要回答，而且全都能在课上动手验证——

①一条消息的完整旅程我打的那几个字，到底经过了哪几站才变成屏幕上逐字冒出来的回答？一
②提示词工程改一句话，回答会不会真的不一样？二
③多轮窗口的遗忘边界第几轮开始，它忘了我前面说过的？三

一

一条消息的完整旅程

你打的那几个字，走了六站才变成你看到的那段话——其中三站是我们能改的

一、先玩，后讲：五步（4 分钟走完）

  1. 问 NPC "你是谁？" → 看逐字冒出来；
  2. 说 "天黑了" → 场景真的变夜；
  3. 说 "带我去西展台" → 你被传送过去；
  4. 视线对准展品，说 "讲讲这件展品" → 它按你看的方向选中并高亮讲解；
  5. 问 "你能做什么" → 它说清自己的能力边界。

这五步里藏着四个问题：为什么它能一个字一个字往外冒？为什么它说完话场景会变？为什么它知道我在看哪件展品？ 这一节全部回答。不要在第一步停下来讲原理——原理是下面十分钟的事。

二、六站链路（本次课最需要记住的一张图）

你打的字（或语音 ASR）
   │
   ├─① 拼上「对话历史 HISTORY」——最近 8 条（MAXH=8，约 4 轮）
   ├─② 拼上「系统提示词 CFG.sys」——内容就是 DEFAULT_SYS，可改
   ├─③ 发给模型：OpenAI 兼容 POST /chat/completions
   ├─④ 逐 token 流式回来：SSE（getReader + TextDecoder）
   ├─⑤ 前端打字机：约 70 字/秒（animate 内 dt*70）
   └─⑥ 出口两条：TTS 朗读（speechSynthesis）＋ 动作执行（parseAction → ACTS 白名单）

六个站。这六站里有三站是我们能改的：提示词（②）、历史窗口（①）、动作白名单（⑥）。今天三样都会动。

三、最容易被误解的一站：发给模型的不是"你这一句话"

发给模型的是一整个消息数组：

[ {role:'system', content: <系统提示词>},
  … 历史（最多 8 条）…,
  {role:'user',   content: <你这次问的>} ]

现场演示（浏览器控制台敲这一行，让全班看这个数组）：

NPC.buildMessages('你是谁')
"我以为我在聊天，其实我每问一次，都把前面所有对话重新发了一遍。"
这句话是理解今天一切成本问题的钥匙：轮数越多，每次请求越贵、越慢。 顺带说一句，这个函数叫 buildMessages，它里面还有一道 slice(-MAXH) 的双保险截窗——第三节讲多轮窗口时会回来看它。

四、流式不是"更快"，是"更早看见"

做法你看到什么总耗时
非流式等 3 秒 → 一次性出现一整段≈ 3 秒
流式（SSE）第 0.3 秒出现第一个字 → 逐字补齐几乎一样

很多同学以为流式是"让模型更快"。不是的——总时间几乎一样。流式做的是另一件事：把"等待"变成"进度"。 这一条对 VR 特别重要：戴上头显的人，比对着电脑屏幕的人更没有耐心；一个静止的画面在头显里会让人以为死机了。

五、出口有两条：TTS 和动作

出口 ① · TTS

speechSynthesis 中文朗读。可关——面板语音开关，PC 快捷键 T。工作室时段请统一关掉。

出口 ② · 动作

模型在回答末尾另起一行，输出且仅输出一个 JSON。前端做的事：正则解析 → 执行 → 从展示文本里剥离（parseAction / stripAction）。

注意"从展示文本里剥离"这五个字。那串 JSON 本来会在屏幕上显示出来——因为对模型来说它就是一段文字。是前端把它抠掉、执行掉，你才看见一句干净的话。这件事在第四节会展开讲，它是今天最重要的一个安全点。

六、收束：毫秒与 token 都是预算

上次课（第 10 次）本次课（第 11 次）
预算是什么帧预算 13.9 ms（72 Hz）上下文预算 8 条 / 约 4 轮
规模上限三角面 ≤ 10 万单次回答 ≤ 90 字（可改，第二节就改）
看什么读数DrawCall / P95 帧时间token 数 / 轮数 / 遵守率
手段实例化、合批、降级截窗、摘要、白名单兜底

同一件事，两种预算。上次你把渲染压进了 13.9 毫秒，这次你要把对话压进 8 条。会算预算的人，才敢说自己"做完了"。

二

提示词工程：现场改一句人设

本讲高潮 A——同一个问题、同一个模型，只因为一句话不同，回答和动作都变了

人设就是系统提示词 DEFAULT_SYS。默认长这样（一字未改照抄案例 06）：

你是虚拟现实课堂里的智能 NPC 向导"小澜"，站在文物会客厅中央。
用中文口语化回答，每次不超过 90 字。
会客厅有三件【示意】展品：东展台·青花瓷罐、西展台·青铜爵、中央圆台·玉璧。
你可以操作场景：需要时在回答最后另起一行输出且仅输出一个 JSON——
{"action":"teleport","target":"center|east|west"}（带我去某处）、
{"action":"time","value":"day|night"}（切换昼夜）、
{"action":"show","target":0|1|2}（讲解 0东 1西 2中 展品）。
没有合适动作就不要输出 JSON。不要编造不确定的事实。

一、这七句话里藏着四类东西

是哪几句管的是什么
第 1 句身份——你是谁、站在哪
第 2 句语气与字数——怎么说、说多少
第 3 句事实——场上有哪三件展品
第 4、5 句动作协议——允许输出哪三种 JSON
最后两句禁止——没有合适动作就不输出、不要编造不确定的事实

二、先猜，再看（不要提前给答案）

问题：如果我把第二句改成"只用文言文回答，每次不超过 30 字"，然后问一模一样的问题——回答会变吗？会变在哪几处？
举手：① 只变语气　② 语气 + 长度都变　③ 语气 + 长度 + 动作遵守率都变
给你们 20 秒，和旁边的人说一句你选哪个、为什么。选完之后我们真的改一次。这里不要剧透。

三、现场操作（严格按顺序，一步都不要省）

步做什么上屏看到什么
1先记基线：问"你是谁？"停在回答上；再问"带我去西展台"回答里出现"小澜""文物会客厅"；看到传送动作
2打开设置面板，只改第二句：用中文口语化回答，每次不超过 90 字。 → 只用文言文回答，每次不超过 30 字。——
3重问同一个问题（一字不改）："你是谁？"风格、长度、用词全变了
4再问同一个动作问题（一字不改）："带我去西展台"当场看它有没有输出那个 JSON——这就是答案

边操作边说（语速放慢）："注意我做了什么：我没有换模型，我没有改问题，我甚至没有改第三句的事实。我改的是一个字符串里的一句话。现在看——"

四、结论：让学生自己说

改之前改之后
回答风格口语化、现代汉语文言
回答长度~90 字以内~30 字以内（信息量肉眼可见地掉）
"带我去西展台"的动作有 {"action":"teleport",…}当场看它有没有

三件事要让学生自己说出来：第一，我先改的那句话管的是什么？——它不只管语气，它管长度； 第二，改成 30 字之后信息量变了没有？——变了，这叫作输出预算； 第三，也是最关键的：动作还好使吗？——动作协议的遵守率会随人设漂移。

落点：人设是"输出约束"，不是"角色扮演"。它同时管语气 · 字数 · 事实边界 · 动作协议要不要输出。
➜ 所以：动作白名单必须写在代码里，不能只写在提示词里。
你在提示词里写"只输出这三种动作"，那是一个请求，不是一道锁。模型今天遵守，明天可能不遵守；你换一句人设，遵守率就变了。真正的锁，是前端那三行白名单代码（见第四节）。
高潮 A 的必要条件：必须走在线模型。 离线模式下 KB 是关键词匹配，改人设不会改变回答，高潮当场失效。 教师机课前必须配好一个可用的在线端点，并把两种人设各跑一遍；把两组回答截图存好做失败备份——端点当场挂掉时至少还能证明"差异是真的"。
备选人设（课前各试一遍，现场不要试）：只用 5 岁小孩的语气回答，每次不超过 20 字。 ／ 像严谨的博物馆研究员一样回答，每次必须给出处。

收尾一句："今天你改的是一个字符串。明天你会写一整个 DEFAULT_SYS——那时候你已经知道它会改变什么了。"

三

多轮窗口的遗忘边界

窗口 = 最近 8 条消息 ≈ 4 轮对话；第 9 条进来，最旧的那条被挤出去

var HISTORY=[], MAXH=8;

function pushMsg(role, content){
  HISTORY.push({role:role, content:content});
  while(HISTORY.length>MAXH) HISTORY.shift();     // 超窗就从最旧的开始丢
}
function buildMessages(userQ){
  var ms=[{role:'system', content:CFG.sys}];
  var hist=HISTORY.slice(-MAXH);                  // 双保险：外部直接 push 也不超窗
  for(var i=0;i<hist.length;i++) ms.push(hist[i]);
  ms.push({role:'user', content:userQ});
  return ms;
}

MAXH=8——最近 8 条消息，约 4 轮对话。buildMessages 里还有一道 slice(-MAXH) 的双保险截窗：就算外部绕过 pushMsg 直接往 HISTORY 里塞，也超不了窗。

一、现场验：连追 5 轮

轮你问你观察什么
1"记住一个词：紫藤。"它答应了
2—4随便问三件别的事（"你是谁""天黑了""讲讲这件展品"）——
5"我第 1 轮让你记的词是什么？"看它的回答
遗忘不是 bug，是设计。 窗口越大越贵——每一次请求都要把全部历史重发一遍（回到第一节那个数组）；窗口越大也越慢——token 越多，等待越久。 所以"它忘了"和"它记得"之间，是一个你要主动做的工程决定，不是一个功能开关。

二、想要"真记得"，得换方案

摘要记忆

把旧对话压成一段摘要再塞回上下文。省 token，代价是细节被抹平。这个词今天只点名，不展开。

向量检索

按语义把相关的旧内容找回来，而不是按时间顺序全带上。这就是后面幻觉治理要说的 RAG 的同一条思路。今天只点名。

案例 06 的小测 L2 有一道题专考这一点（QUIZ 里 lv:2，题面即"MAXH=8（约 4 轮）的直接后果是什么"）——可以当堂让学生先猜再验。

时间紧张时的降级：把"连续追问 5 轮"改成"直接投 MAXH=8 与双保险截窗两行代码"（8′ → 4′）。这是降级优先级里的第 6 档——能砍，但砍了就少一次"学生自己看出来"的机会。
四

动作协议与白名单

模型只"建议"，程序才"决定"——本讲唯一需要背下来的工程约束

一、先问一个问题（想 10 秒再答）

如果模型输出的不是 teleport，而是 location.href='http://……'， 或者 deleteSave()、openDoor()——你的作品会怎么样？
……答案是：会照做。因为如果按最朴素的方式写——把模型输出的 JSON 直接丢给执行函数——它就照做。 这就是今天最重要的一个安全点。

二、约定好的三种动作（案例 06 的真实约定，照抄未改一字）

{"action":"teleport","target":"center|east|west"}   传送
{"action":"time","value":"day|night"}               昼夜切换
{"action":"show","target":0|1|2}                    高亮讲解 0东·青花瓷罐 1西·青铜爵 2中·玉璧

为什么不用原生 function calling？——任何 OpenAI 兼容端点（含免费 / 国产模型）都能用这种约定 JSON，课堂零门槛；原生 tools 调用留作作业。

三、白名单：枚举允许的，而不是枚举禁止的

var ACTS={ teleport:['center','east','west'], time:['day','night'], show:[0,1,2] };

/* parseAction：非法 action / 越界 value 一律拒绝 */
if(!o.action || !ACTS[o.action]) return null;
if(ACTS[o.action].indexOf(v)<0) return null;

现场演示（控制台敲这一行）：

NPC.parseAction('{"action":"teleport","target":"moon"}')

看，返回 null。moon 不在白名单里，这个动作被拒绝。 注意另外一件事：被拒绝了，但对话没有崩。这一条同样重要——兜底不是"出错就停下"，是"出错照常继续，只是不做那件事"。

四、三层结论（按顺序讲，不要跳）

① 模型是不可信输入源

它会被提示注入（prompt injection）带偏，也会单纯地"想帮你"。

② 白名单是"只允许这三件事"

不是"禁止可疑的事"——枚举允许的，不枚举禁止的。这是安全设计的通用姿势。

③ 执行权在前端

模型只是建议，ACTS 才决定。"模型说"和"程序做"之间必须隔一层校验。

这就是为什么白名单必须写在代码里。你在提示词里写"只输出这三种动作"是一个请求； 前端那三行 ACTS 校验才是一道锁。第二节的高潮已经证明：换一句人设，遵守率就变了。

五、工作室里怎么查（教师巡回第 2 个检查点）

如果他做了动作，造一个越界的 target 喂给他的解析函数，看是否被拒绝、对话是否照常继续。 新增一种动作的完整改法是三处：ACTS 白名单 + doAction 分支 + 提示词里的说明——漏掉任何一处都不成立。 改动不超过 20 行，这是加分项的挑战档。

五

幻觉治理与密钥安全

事实进知识库，模型只组织语言；Key 进服务器，前端只发问题

一、幻觉治理：不要指望"把温度调到 0"

做法效果
❌ 把 temperature 调到 0只是让输出更确定——编造时会更理直气壮、更稳定地编造
✅ 把事实放进系统提示词 / 知识库模型只负责组织语言，事实有你给的出处
✅ 这个做法有名字：RAG（检索增强）答案的事实来自知识库，模型只做措辞

案例 06 的真实做法（照 README 原文）：三件展品的讲解文案刻意不做史实断言——原话是"避免幻觉示范反面教材"； 「安全与合规提醒」里写："场景事实类回答应把事实放进系统提示词 / 知识库，模型只负责组织语言。"

把这条纪律接到你自己身上——大作业硬门槛第 10 条：诚实。
涉及校史、文物、机构等真实信息，不确定的一律标 【待补充】，不得编造；README 写明"已知简化"。
➜ 你要求模型做到的事，你自己的 README 也要做到。

二、密钥安全：先看现状

浏览器（你的机器）  ──[ Key 明文，存在 localStorage + 内存 ]──►  大模型 API

照念案例 06 README 的原话（安全与合规提醒）：

"本页把 API Key 放在前端（localStorage + 内存），任何能打开控制台的人都看得到——只适合本机课堂演示。"

现场演示（这一步必须让学生自己看见自己的）：按 F12 → Console → 敲 NPC.CFG。 ……看见了吗？你的 Key，就在那儿，明文。现在问一个问题：你的作品是要交出去、要在路演上给 40 个人看的。你会希望有人当场按一下 F12 吗？

二、04 当成品参照：「导览打卡」＝ 目标闭环 + 难度曲线

漫游型 VR 最容易做成"转一圈就完了"。转一圈不是作品，是 demo。04 加了一条主线：有目标、有评价、有数据沉淀。

  • 路线 5 站：学校正门 → 中心广场 → 运动场 → 图书馆前 → 生活区（起始站自动计为已到访，需再走 4 站）；
  • 到访自动打卡，HUD 实时显示进度与用时；
  • 线索三段递减（这是设计重点，不是随便给提示）。
已到访站数给的线索难度从哪里来
0—1 站直给地名 + 详细描述：「下一站是【中心广场】。中心广场：正前方是有柱廊的主楼。」建立校园空间坐标系
2—3 站只给特征描述，不给地名：「下一步线索：运动场：有标准跑道与看台。」开始撤掉外部导引
≥4 站只给一句功能提示：「再想一想：借书和自习的地方。」逼你凭空间记忆找路

为什么越往后线索越短？因为前两站的任务是让你建立校园的空间坐标系；后面要逼你从"照着地名走"切换到"凭空间记忆找路"。 这正好对应 VR 里的空间认知与路径整合（path integration）——这就是"VR 能训练空间能力"这句话的证据。

评级公式（写在 finishTask() 里，可当堂改参数做实验）

扣时分   = clamp(round((用时秒 - 300) / 10), 0, 20)    // 超 5 分钟后，每 10 秒扣 1 分
扣分线索 = clamp(求助次数 × 4, 0, 20)                  // 每条线索扣 4 分
扣晕动   = clamp(round((平滑移动秒 - 90) / 6), 0, 15)  // 晕动暴露超 90 秒开始扣
总分     = clamp(100 − 扣时分 − 扣分线索 − 扣晕动, 0, 100)
评级：≥85 优秀 / ≥70 良好 / ≥55 合格 / 其他 需要再练一遍
扣分项它考察的是什么（必须念）
用时找路效率，不是速度——跑得快但走错方向会同时吃用时和求助扣分
求助次数多大程度上依赖外部导引而非自身空间记忆
晕动暴露把"舒适度"变成真实代价：想省时间走平滑移动，就要付晕动的分数——这是一次真的人因权衡
结算后：XRCore.goal('campus-tour','数字校园导览打卡', result) → 成绩写进 XR 体验数据 → 导出 JSON ⇒ 过程性评分证据。
也就是说：你今天玩得怎么样，是可以被拿出来当证据的。

三、两条边界必须同时讲清（04 README 原文都写了）

  1. 可以当评分证据的只有一类数据：XRCore.goal() 写入的成就数据； 其余过程数据不作排名——坐姿或单手模式天然更慢，它用于你自己前后两次对比，不是排名。
  2. 04 没有实现 3D 高斯溅射（3DGS）。3DGS 需要真实多视角照片 + 训练，无法在单文件离线页面里生成； README 明确建议单独安排一次采集与训练实验课。今天谁要是问"我们是不是用了 3DGS"——答案是：没有，也不该说用了。
其他必须在课堂上说明的"已知简化"（如实写）：
① 06 的 NPC 是程序化几何拼装（圆柱 + 球），非骨骼动画角色；"说话"只有头部微动，无口型——"会说话"指内容会说话，不是嘴会动；
② 04 的建筑与地标是程序化示意，不是实景——这是示意场景，不是真实校园；
③ 04 / 06 缺触觉与抓取类交互，这是场景性质决定的，不是遗漏；
④ 04 的语音识别依赖浏览器实现，Safari / Firefox 支持有限——课堂演示统一用 Chrome 系。

AR 对照（原要求 15′，本课只给 6′）

同一套"识别—配准—叠加"的逻辑，换到 AR 长什么样——只讲三句，多一句都不讲

案例 05 是六个案例里唯一保留真 immersive-ar 入口的一例：

navigator.xr.isSessionSupported('immersive-ar')   // 检测

一、三句要讲的

第 1 句 · 现实

这是 05 README 对比表的原话。所以这一例专为 PC 浏览器全流程演示设计，走的是模拟跟踪——用"相机—识别图距离 / 视线夹角 / 正对度"算特征点分。
第 2 句 · 形态差异
"注册"在两个形态下指两件事
AR 里"注册"＝把模型钉在识别图上；VR 里"注册"＝把玩家放进场景。"虚实融合"这四个字，在两种形态下指的是两件事。
第 3 句 · 本课口径
以 VR 沉浸作品为主，AR 只作对照与可选加分
本课次 AR 只给这几分钟——想做的同学，把它做成期末的 +5 加分项（智能交互 / AR 虚实融合 / 思政题材，三者任一生效且有降级方案才算生效）。
如果时间不够，先砍它。降级优先级里 AR 对照排第 4 位，处置方式就是"改成课后阅读"。 同样排在第 4 位的还有"05 的 Vuforia 对照"——后者本来就是课后阅读。但不许把 15′ 讲成 45′。

一、八句话速查

主题要记住的
本课命题智能交互不是"接一个 API"，是设计"接不上时怎么办"。离线兜底是及格线，在线模型是加分项
一条消息的旅程输入 →（① 历史 + ② 系统提示词）→ ③ 模型 → ④ SSE 流 → ⑤ 打字机 → ⑥ TTS / 动作。六站里三站能改
最容易误解的一站发给模型的不是"你这一句话"，是 [{system}, …history…, {user}]——每问一次都把全部上下文重发一遍
流式不是"更快"，是"更早看见"：总耗时几乎一样，等待被摊平成了进度
提示词工程人设是"输出约束"不是"角色扮演"：同时管语气 · 字数 · 事实边界 · 动作协议要不要输出
遗忘边界HISTORY + MAXH=8 ≈ 4 轮；遗忘不是 bug，是预算（摘要记忆 / 向量检索只点名）
动作协议 + 白名单模型只建议，程序才决定；枚举允许的，不枚举禁止的；非法 action / 越界 value 一律拒绝且对话不崩
密钥安全Key 放前端只适合本机课堂演示；正式产品后端代理 + 限流 + 内容审核（＋日志）
