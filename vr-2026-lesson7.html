一

WebXR 作品的三层工程结构

本课唯一必须记住的结构：DOM 层 / XR 层 / 状态层，以及三处交界

一、先看一个现象：`Shift+P` 切坐姿

不先讲结构，先看现象。在案例 01 的 PC 预览里按一次 Shift+P——场景里的两块面板一起下沉了 0.45 米，还往下倾了 0.18 弧度（与工程面板同步）。

问题：这两块面板，是网页上的东西，还是场景里的东西？
答案：都是场景里的 3D 物件。如果是网页上的浮层，按 Shift+P 它只会被压在原地——而且更要命的是，进了沉浸模式，网页浮层根本不渲染，你压根看不见它。
于是得到第一层结论：沉浸模式下，DOM 看不见。你的所有界面，必须是场景里的 3D 物件。

这一屏必须让学生自己看出来：不要直接说“下沉 0.45m 说明它是 3D 的”，先问“它为什么跟着沉”，等学生说出“因为它跟着参考系”再往下讲。

二、一句话：DOM 层管 PC，XR 层管头显

沉浸模式（immersive-vr）里，DOM 层退出渲染。于是同一份 HTML 里，必然住着两种界面——

  • 给 PC 和开发期看的：能点、能敲键盘、能显示报错；
  • 给头显里看的：必须是 3D 物件。

把现象翻译成一句工程话：你交付的是一个 HTML 文件，但这个文件在两种情况下表现完全不同。在 PC 上它是网页（有 DOM、有键位、有控制台），在头显里它是一段 3D 场景（DOM 全部下线，只剩渲染出来的 3D 内容）。一份文件里同时住着两种界面，怎么写才不会打架？答案是分成三层。

为什么是这三层，而不是“代码结构”？你们现在的作品是一个大 HTML 文件，所有东西混在一起：状态散在十个变量里，界面一半是 DOM 一半是 3D，帧循环里夹着业务逻辑。 不先给一套分层的话，后面第 8—11 次课每次都只能“贴代码”，改一处动全身。
三层是可以肉眼验证的：Shift+P 一按，DOM 层没变、XR 层下沉了 3D 面板——全班同时能看到“层在哪里分界”。

交界二 · PC 键位是“必需”，不是“顺手加的”

硬门槛里有一条：主流程 PC 与 VR 两端都能完成。
理由很现实：教室机位 36 个 / 选课 40 人——总有人手上没有头显；而且期末你要交的是能给别人看的东西，不可能人人发一台头显。
所以 DOM 层不是“给开发者的赠品”，它是一条正式通路。你们改作品时，PC 那条路不能塌。

这一层最容易被写坏的一个地方，是按钮：看着能点、其实点不动。上一届有同学的处理办法很好——加了一行 btn.disabled = false，又加了一个 window.isSecureContext 检测：不在安全上下文里，按钮上直接写“进入 VR（需要 HTTPS）”。他不是背下来这两条，是踩过之后把它写进了代码里。

③ 帧循环

每一帧做什么。状态就在这一层被读到画面上。

⚠️ 进 VR 的前提是安全上下文：navigator.xr 只在 https / localhost / 127.0.0.1 下暴露。 file:// 下它就是 undefined —— 页面上根本没有“进入 VR”这个按钮，这不是代码坏了。 这就是从第 5 次课立的那句口号：先怀疑环境，再怀疑代码。

帧预算为什么是 13.9ms，不是 16.7ms

目标 72Hz ⇒ 13.9 ms / 帧 —— 不是 16.7 ms。差的这 2.8 ms，是浏览器合成占掉的时间（16.7 是 60Hz 的数）。
工程面板实时显示：FPS · 帧时间 · 最差 1% 帧 · DrawCalls · 三角面 · 贴图数。

今天不讲优化（那是第 10 次课）。今天只要求你认出两个读数在哪：FPS 与降级等级。待会儿进 VR 的时候，先低头找到这两处。

动态降级 L1 / L2

触发条件动作能否恢复
帧时间持续超预算 20% 达 2 秒L1 降像素比 → L2 关阴影余量恢复时自动回升（可逆）
没有降级记作 L0—

待会儿进 VR，如果面板上写着 L1 或者 L2，那说明当时的机器撑不住——把它记下来，第 10 次课专门解决这个。

移动与转向：默认值不是随便选的

做法舒适度代价
瞬移（传送）最不易晕破坏空间连续性
平滑移动沉浸感好晕动症主要来源
Snap 45° 转向显著降低眩晕—（有 380 ms 冷却防误触）
平滑转向连续更易晕
VR 里永远不要强制旋转相机。你可以在场景里放一个“看这里”的提示，但不要替用户转头——那是晕得最快的一种做法。

第 3 层 · 状态层就是一个 `S` 对象

整个作品的可变部分，住在一个 S 对象里：力 / 速度 / 计数 / 开关 / 进度，全在这里。案例 01 的调试入口：浏览器控制台输入 VRSandbox，可查看 / 操作全部状态；面板上的“重力”按钮，实时改的就是 S.gravity（默认 9.8）。

⚑ 为什么“一个 S”这么重要：案例 01 有两个投掷相关的常量挂在状态上——S.gravity（重力，默认 9.8）与 S.restitution（弹性）。 课堂作业里有这么一条：把重力从 9.8 调到 3，再投一次，描述手感差异。
假设重力不是挂在 S 上，而是散在三个函数里各写一遍 9.8——改重力得改几处？三处，而且只要漏一处，这个球的行为就自相矛盾。 这就是“一个 S”的价值：同一个东西，全作品只有一个来源。
硬门槛：状态集中在一个 S 对象，且可被外部查询（window.XX.S）。为什么要“能被外部查询”？三个真实用途：
① 你自己调试——控制台敲一行就能看到现在的状态，不用到处打 console.log；
② 别人验收你的作品——第 12 次课路演，评审要看“你到底做到了哪一步”；
③ 数据可以导出——体验数据里的时长 / 交互次数 / 完成度，都是从状态里取的。
换句话说：状态不集中，你后面三次课的里程碑全都交不出来。

四、三处交界，一句话总结

交界规则违反的后果
DOM ⇄ XR沉浸模式下 DOM 下线面板 / 名字在头显里看不见
XR ⇄ 状态帧循环每帧读一次 S状态改了但画面不变
状态 ⇄ DOM面板按钮与键盘快捷键共用同一个 S同一个人两个值，行为自相矛盾

最后一条叫 单一设置源（single source of truth）。举例：面板上有个“重力”按钮把它调到 3，你又写了个键盘快捷键按一下把重力设回 9.8；如果这两个用了不同的变量，屏幕上显示的是 3，实际跑的是 9.8——你自己都会被自己骗。

一、VR 手柄与 PC 键位映射（这两套都要走通）

VR：头显 + 双手柄

  • 手柄射线：远距离指向（物体 / 面板 / 地面）；
  • 扳机：面板按钮、传送落点、远距离拉取；
  • 握持键（侧键 / squeeze）：抓取 0.35 m 内物体；释放即投掷；
  • 左摇杆：平滑移动；右摇杆：Snap 45° / 平滑转向；
  • 触觉：抓取 / 命中 / 收纳 / UI 各不同强度。

PC：鼠标 + 键盘

  • 鼠标拖拽：环视；
  • W A S D（Shift 加速）：行走；Q / E：转身；
  • 鼠标左键点物体：抓取（再点一次放开）；
  • 鼠标左键点地面：传送；左键点面板：操作按钮；
  • R：重置场景。
PC 快捷键行为课上怎么用

Shift+H惯用手循环：双手 → 单手（自动）→ 仅右手 → 仅左手 → 双手★ 至少试一次“仅左手”，见下

二、这段必须做的两件事（不讲就是漏掉本课最重要的边界）

① 当场切一次单手模式（Shift+H 到“仅左手”）：案例在单手模式下所有交互仍可完成。
这句话要落成结论——任何单一输入通道都能走完主流程。这是第 9 次课的验收口径，今天先埋下。
② 当场切一次注视停留（Shift+G）：注视停留只能点 3D 面板（工程面板 + 案例自有控制面板，停留 1.2 s 触发，相机上有注视准星）。 场景实体（球、方块）仍需手柄射线——这条边界不要掩盖，它正是第 9 次课“免手柄通路怎么补”的讨论起点。

⚑ 这一屏必须让学生自己看出来：先把视线移到场景里的球上停住，球不动；问“为什么球不动”，等学生说出“面板和物体是两套判定”再往下讲边界二。

边界二 · 未在真机验证的部分（必须对学生诚实）

LAB 01 · 射线 · 悬停 · 三通道反馈——为什么“一碰就触发”是灾难

页面里有什么：一块 3D 面板 + 3 个靶球；HUD 显示“悬停 / 确认 / 误触”三个计数，以及“视 / 听 / 触”三个通道灯。

三步体验：① 面板切到单级模式，用射线扫过按钮（不按扳机）——看“误触”计数往上跳；② 切到两级，再扫过——只高亮，不触发；③ 在两级模式下按扳机确认——三个通道灯同时亮。

看哪两个数：误触次数（单级会涨、两级为 0）；通道灯数量（悬停 2 个、确认 3 个）。

结论：悬停 ≠ 确认；一次有效交互至少给两个通道，强度要分档（悬停 0.2 / 确认 0.5）。

常见坑：进了 VR 声音不响——浏览器的自动播放策略，要在“进入 VR”那个用户手势里调 ctx.resume()。

对应：作业 H2（三通道按钮）；M1“核心交互”第 1 项。

LAB 02 · 抓取校准：attach 与 add——差一个字母，差一个位姿

页面里有什么：一张桌子 + 一个长条物体 + 两侧距离标尺；一块“读数屏”显示本次抓取的世界位置跳变 Δ（毫米）。

三步体验：① 模式 attach → 点“抓取一次”——读数屏 Δ 应接近 0 mm，物体“一到手里就对”；② 模式切 add → 再抓一次——读数屏 Δ 会到上千毫米（截图实测 1492.6 mm），物体会“跳”一下；③ 把抓取距离档从 0.35 切 0.20 / 0.80，各抓一次——感受“太近够不着 / 太远像隔空取物”。

看哪两个数：Δ 值（attach≈0 / add≫0）；抓取成功与否（距离档位决定）。

结论：add 换父级坐标系→跳；attach 保持世界变换→不跳。抓取对齐是给别人的手设计的，不是给你自己的手。

常见坑：改完代码没刷新，看到的是缓存；抓歪 30° 时“跳”最明显，别只用一个角度试。

对应：作业 H3（抓取距离校准表）；第 9 次课谜题交互。

LAB 03 · 投掷校准：力度 × 平滑 × 重力——“手感”是三个数字

页面里有什么：投掷线 + 8 m 外带环数的靶盘 + 3 个球；右侧一块命中记录表（力度 / 平滑 / 重力 / 命中环数 / 落点距离）。

三步体验：① 力度 0.6 → 投一次 → 再 1.15 → 再 2.0，各看落点与命中；② 把平滑从 0.35 改 0.05，再投——体会“手一抖球就飞”；③ 把重力从 9.8 改 3（月球）/25（木星），各投一次看手感差异。

看哪两个数：命中环数；落点距离（m）。截图实测示例：力度 1.15 → 10 环 8.50 m；力度 0.6 → 未中 3.77 m。

结论：投掷 = 速度采样（EMA 平滑）+ 力度系数 + 重力；手感是调出来的，不是写出来的。

常见坑：平滑系数是“保留权重”——0.05 几乎不平滑（抖就飞），0.35 更稳但会滞后；进 VR 后用手柄速度而不是鼠标位移。

对应：作业 H3（力度-命中小表）；第 10 次课性能数据习惯。

LAB 04 · 重力实验室：同一颗球，三种世界——验证“一个 S”

页面里有什么：3 m 高的落球架 + 接球盘 + 三档重力（地球 9.8 / 月球 3 / 木星 25）+ 弹性（0.45 / 0.9）；HUD 实时显示 g、e、落地时间、首次弹起高度、弹跳次数、理论比值 √(9.8/g)。

三步体验：① 地球档按“落下（空格）”，记落地时间；② 切月球档再落一次——球像羽毛；③ 切木星档再落一次——球“砸”下来；最后把弹性调到 0.9 看“跳跳球”。

看哪两个数：落地时间 t（地球≈0.69 s、月球≈1.24 s、木星≈0.43 s）；弹跳次数（e=0.45 vs 0.9）。

结论：改一个 S.gravity，落体、面板读数、音高同时变——状态只有一个来源；月球/地球落地时间比 ≈ 1.807 = √(9.8/3)。

常见坑：只看“球变慢了”不够，要读数字证明比值；面板与代码不一致，说明状态没集中。

对应：作业 H1/H3；第 8 次课状态机（一个 S）。

LAB 05 · 重力手套：简化版 vs 三段式——功能与体验差一个窗口

页面里有什么：前方 4—6 m 一排 5 个物体 + 接取区；面板可切简化版 / 三段版；HUD 显示阶段（待选 / 已选 / 飞行中 / 接住 / 掉落）、甩腕窗口、接住与错过次数、弧线中点偏移。

三步体验：① 简化版：指向物体 → 扳机 → 物体直接飞向手并自动吸附；② 三段版：悬停选中（高亮）→ 再按一次扳机确认 → 物体会沿弧线飞来；③ 在到达前 ±0.25 s 内快速“甩腕”（PC 按空格；VR 用手柄速度 >1.2 m/s）——接住 / 错过。

看哪两个数：甩腕窗口剩余时间（0.09 s → now）；弧线中点偏移（截图 0.39 m，>0.15 才说明是弧线不是直线）。

结论：Alyx 的重力手套是选中 → 确认 → 飞行 / 甩腕接住三段；同样的“拉取”，多一个时机窗口就从“方便”变成“好玩”。

常见坑：窗口外甩腕也会“接住”=判定写错；简化版没有风险，所以学生做出来的往往“能用不好玩”。

对应：H1 记录；M1“核心交互”的候选（如果你的作品有“取物”）。

LAB 06 · Diegetic UI：信息长在世界里——DOM 进 VR 就消失

页面里有什么：同一组“分数 / 生命 / 提示”四种呈现：① 世界内腕表 + 胸口血条；② 空间面板（贴墙）；③ 跟随头部；④ 网页浮层（DOM）。面板可一键切换。

三步体验：① 依次切四种模式，看同一组数字怎么跟着变；② 切到“网页浮层”再进 VR——浮层消失；③ 回到“世界内”，低头看腕表：分数、生命都在。

看哪两个数：分数 / 生命在四种模式下是否一致（同一个 S）；浮层在 VR 里是否可见（答案：不可见）。

结论：沉浸模式下 DOM 不渲染；界面必须是 3D 物件。diegetic 最沉浸但要主动看，复杂数据配 spatial。

常见坑：把提示做成 DOM，PC 上好好的，戴上去“什么都没有”——第 6 次课“名字牌”踩过的同一个坑。

对应：H5 的 diegetic 改造；第 8 次课“状态 → UI 同步”。

LAB 07 · 舒适度：移动范式 × 隧道遮罩——为什么会晕

页面里有什么：一条 24 m 走廊 + 地面刻度；四种移动方式（瞬移 / 平滑 / 平滑+遮罩 / 关闭移动）+ Snap 45° + 遮罩强度 0/0.5/1 + 一个“强制转相机”的反例开关；HUD 显示视觉流指标 VFI 与自评记录。

三步体验：① 平滑移动走 20 秒，打 1—5 分；② 加遮罩到 0.8 再走 20 秒，再打分；③ 切瞬移走一段，再打分；顺手开一下“强制旋转相机”，看 HUD 红字警告。

看哪两个数：VFI（视觉流指标）与自评分数；遮罩 0 与 1 的周边暗角差异。

结论：晕来自“眼动身不动”的感觉冲突；少动、慢动、挡周边；新手默认瞬移 + Snap 45°，永远不强制转相机。

常见坑：把“平滑 + 平滑转向”当默认——新用户 10—15 分钟就可能不适；个体差异是脱敏，不是体质差。

对应：第 9 次课可访问性；H6 单手结论。

LAB 08 · Fitts 定律 × Goldilocks 舒适区——面板放多高

页面里有什么：目标按距离 / 大小依次出现并计时；面板画 ID = log₂(A/W+1) → MT 散点；高度档 1.0 / 1.3 / 1.7 / 2.0 m。

三步体验：① 打 6—8 个靶（不同距离与大小），看散点往右上走；② 把面板高度切 1.0 → 判定“偏低（要弯腰）”；③ 切 2.0 → “偏高（要抬手）”，1.3 / 1.7 才是“舒适”。

看哪两个数：ID（bit）与 MT（ms）；高度判定（偏低 / 舒适 / 偏高）。

结论：目标越远越小越慢；近处用手、远处用线；交互面板放在胸口到眼高（约 1.2—1.8 m）。

常见坑：无头 / 模拟数据下的 MT 是“机制验证值”，课堂结论要用你自己的真机数据；只测一个距离看不出规律。

对应：H1 记录；你作品面板的摆放高度。

LAB 09 · 触觉语义分级 × 手部追踪 pinch——一个强度用到底就是噪音

页面里有什么：四档语义按钮（悬停 0.2 / 抓取 0.5 / 命中 0.8 / 错误 1.0 长）+ pinch 时间线 + 虚拟手；HUD 记录最近 5 次 pulse（强度 / 时长 / 真机是否支持）。

三步体验：① 依次按四档，感受强度与时长差异（0.2/30ms、0.5/60ms、0.8/90ms、1.0/200ms）；② 按 P 模拟 pinch：先“靠近”（0.2）再“捏合确认”（0.5）；③ 看 HUD 是否标注“PC 只记日志 / 真机支持未验证”。

看哪两个数：四档强度值与时长；pinch 状态（idle → near → confirm）。

结论：触觉要按语义分级（UI / 抓取 / 命中 / 错误），不是“越强越好”；手部追踪的 pinch = 确认，是免手柄通路。

常见坑：PICO 固件版本差异，触觉与 pinch 未在真机验证；课上按 HUD 提示，无响应就用键盘模拟走通路。

对应：H1；第 9 次课“免手柄通路”。

三条通路：先怀疑环境，再怀疑代码

收束段花 7 分钟把三条现场走一遍，但课堂上只教走通的那一条

这节课是后半程第一次真机实操，后面五次课每次都要走通路。今天不把通路讲透，后面五次课每次都要花 20 分钟救火。 三条都演示、只教一条，是为了让学生知道“还有别的办法”，遇到问题时不会卡死在一条路上；同时避免教师在课堂上同时维护三条路径。

#通路我怎么操作特点与麻烦
①USB + adb reverse数据线连头显与笔记本，执行 adb reverse tcp:8080 tcp:8080 → 头显浏览器开 http://127.0.0.1:8080/天然是安全上下文（127.0.0.1），校园网再怎么隔离也不怕、不占网络；但要开发者模式与 adb
②局域网 http + 头显白名单头显浏览器进 chrome://flags/#unsafely-treat-insecure-origin-as-secure，填入 http://电脑IP:端口不用连线；但电脑 IP 一变就要重填，这是它最大的麻烦
③站点 https直接打开 https 地址最省事，也是以后收作业与互评的首选；需要有可发布的站点
板书一句（第 5 次课已确立，全程沿用）：先怀疑环境，再怀疑代码。
navigator.xr 只在 https / localhost / 127.0.0.1 下暴露。 file:// 不是安全上下文 → navigator.xr 是 undefined → 页面上看不到“进入 VR”按钮。
双击 HTML 文件永远进不了 VR。“装进头显”的正确说法是：在头显里通过 https / localhost / 白名单地址打开。

二、课堂只教一条，但三条都演示

课前教师会实测并选定一条（本次课选定的是哪一条：【待确认：由教师课前实测后当堂宣布】）。三条你都试一下“能不能打开”，但主用那一条就行。 你们不用三条都会——会用一条，就够了。
看不到“进入 VR”按钮时，先问是不是安全上下文，再怀疑代码。
40 人同时进 VR 的通路压力：校园网常有客户端隔离，40 台设备同时投屏会压垮一个 AP。 课堂取证首选头显系统截屏 → USB 导出，不占网络也不受隔离影响。本班 PICO 每人一台、教师负责投屏，所以这条压力主要落在前两节练习段的机位（40 人 / 36 机位）：多出的 4 人合用机位或带自己的笔记本。

#检查项怎么算过（当场能演示）
A1全景图正确等距柱状全景贴在球体内表面，上下极点不撕裂、接缝不显眼；鼠标拖拽能环视一周
A2名字牌是 3D 物件名字在场景里（牌子/铭牌/立体文字都行），不是网页 div——戴进头显也能看见
A3≥2 个热点注视/点击热点能跳转或切换场景；至少 1 个热点有反馈（高亮 / 音效 / 提示字）
A4退出路三条退出路至少试通一条（注视「退出 VR」1.5 s / 长按握把 2 s / 系统键），并记下用时
A5三条通路走通一条PC 上先跑通，再按站点 https / USB+adb / 局域网白名单里的一条打开；看不到“进入 VR”按钮 = 先查安全上下文
A6控制台无报错打开 F12，主流程连走两遍，Console 没有红色报错
A 段最常见的四个坑：① 名字还是 DOM 浮层（进 VR 就没了）；② 全景上下极点撕裂（投影参数 / 球体内表面朝向）；③ 热点只能“看”不能“点”（射线命中没接）；④ 双击 HTML 打开——file:// 不是安全上下文，永远进不了 VR。

#检查项怎么算过（当场能演示）
B1节点 + 边≥4 个节点、≥5 条边；每条边都真的能走通（点热点能到，不是“画在图上有”）

示范案例：一个“能评分的小玩法”长什么样

两个可直接打开的标准答案：投篮擂台（作品示范）与作业样板（交付示范）

“把零件攒成一个作品”这句话太抽象。所以给两个可以直接玩、也可以直接拆的示范： 一个告诉你“完整的小玩法”是什么样，一个告诉你“合格的作业交付”是什么样。 先玩、再拆、再改——不要从零开始想。

一、拆解：什么叫“可评估的小玩法”

示范作品（demo01）的统一要求只有三条，但每条都在回答一个设计问题——为什么这个玩法能被“评分”而不是“只能看”：

要求示范里怎么做的它解决了什么问题
① 目标 + 计分显示在 3D 里计分板是场景里的一块 CanvasTexture 面板，分数/时间/最高分三行玩家不用退出沉浸就知道自己做得怎么样；这也是第 8 次课“状态→UI 同步”的伏笔
② 命中给两通道以上反馈筐闪（视）+ 上扬音效（听）+ pulse(0.8, 90)（触）“差一点”和“进了”必须一眼一听就能区分，否则玩家学不会调整力度
③ 有重置按钮面板上的“重置”把球、分数、计时、阶段一起复位球一定会飞出场地。没有重置，演示 30 秒就卡死——这是擂台类玩法排行第一的翻车点
＋ 阶段状态机ready → playing → over，UI 与提示音随阶段变，over 锁输入“开始前不计分、结束后不能刷分”——这是第 8 次课状态机的最小原型，今天先用起来
示范案例怎么用（三步）：
① 先玩：完整打一局，感受“什么时候想再来一次”；
② 再拆：打开源码找四个东西——计分变量在哪、命中判定在哪、三通道反馈在哪、重置函数在哪；
③ 再改：换主题（投篮→投壶/投币）、换规则（+2/+1 改连击）、换反馈（换音色/换震动强度），改三处就算你的作品。

①《交互清单》自动生成

② 三条达标线自检

能进能退 ✔ · ≥3 种交互可用 ✔ · 控制台无报错 ✔（用 window.onerror 实时计数，报错就变红）。

五、下课前一定要知道的七句话

① 沉浸模式下 DOM 看不见

你的界面必须是 3D 物件（名字也一样）。

② 72 Hz 的帧预算是 13.9 ms

不是 16.7 ms。面板上要认出 FPS 与降级等级 L0 / L1 / L2。

③ 注视停留只能点 3D 面板

场景实体（球、方块）仍然需要手柄——这条边界就是第 9 次课要讨论的问题。

④ 先怀疑环境，再怀疑代码

file:// 不是安全上下文，看不到“进入 VR”按钮——那通常不是你的代码坏了。

⑤ 没有反馈的交互等于没有交互

一次有效交互 = 视 / 听 / 触至少两个通道；悬停与确认强度要分档（0.2 / 0.5 / 0.8）。

⑥ 状态只有一个 S

改一处，画面 / 手感 / 面板读数同时变——这是第 8 次课状态机的起点。

⑦ 先能演，再谈装新

旧作品进不去、退不出，装十个零件也没用。今天的达标是"能演示"，不是"功能多"。
