一

WebXR 作品的三层工程结构

本课唯一必须记住的结构：DOM 层 / XR 层 / 状态层，以及三处交界

一、先看一个现象：`Shift+P` 切坐姿

不先讲结构，先看现象。在案例 01 的 PC 预览里按一次 Shift+P——场景里的两块面板一起下沉了 0.45 米，还往下倾了 0.18 弧度（与工程面板同步）。

问题：这两块面板，是网页上的东西，还是场景里的东西？
答案：都是场景里的 3D 物件。如果是网页上的浮层，按 Shift+P 它只会被压在原地——而且更要命的是，进了沉浸模式，网页浮层根本不渲染，你压根看不见它。
于是得到第一层结论：沉浸模式下，DOM 看不见。你的所有界面，必须是场景里的 3D 物件。

这一屏必须让学生自己看出来：不要直接说“下沉 0.45m 说明它是 3D 的”，先问“它为什么跟着沉”，等学生说出“因为它跟着参考系”再往下讲。

二、一句话：DOM 层管 PC，XR 层管头显

沉浸模式（immersive-vr）里，DOM 层退出渲染。于是同一份 HTML 里，必然住着两种界面——

  • 给 PC 和开发期看的：能点、能敲键盘、能显示报错；
  • 给头显里看的：必须是 3D 物件。

把现象翻译成一句工程话：你交付的是一个 HTML 文件，但这个文件在两种情况下表现完全不同。在 PC 上它是网页（有 DOM、有键位、有控制台），在头显里它是一段 3D 场景（DOM 全部下线，只剩渲染出来的 3D 内容）。一份文件里同时住着两种界面，怎么写才不会打架？答案是分成三层。

为什么是这三层，而不是“代码结构”？你们现在的作品是一个大 HTML 文件，所有东西混在一起：状态散在十个变量里，界面一半是 DOM 一半是 3D，帧循环里夹着业务逻辑。 不先给一套分层的话，后面第 8—11 次课每次都只能“贴代码”，改一处动全身。
三层是可以肉眼验证的：Shift+P 一按，DOM 层没变、XR 层下沉了 3D 面板——全班同时能看到“层在哪里分界”。

第 1 层 · HTML / DOM 层，它只负责两件事

① PC 通路

鼠标拖拽环视 / W A S D 行走（Shift 加速）/ Q E 转身 / 左键点物体抓取 / 左键点地面传送 / 左键点面板 / R 重置。

② 开发期与调试

键位说明牌、报错提示、window.isSecureContext 检测（不安全时按钮直接写“进入 VR（需要 HTTPS）”）。

交界一 · 为什么你的名字必须是 3D 物件

同一件事写法结果
❌ 网页浮层<div class="name">张三</div>PC 上看得见，头显里不存在
✅ 3D 物件场景里的一块牌子 / 铭牌 / 碑PC 与头显都在

上一次课全班 9 份作品，做出了 9 种 3D 名字：横匾 / 门牌 / 金色铭牌 / 署名石碑 / 霓虹横幅 / 牌坊 / 立牌 / 云柱牌子 / 场景内立体文字。这就是“分层”在你们自己作品里的第一次落地。

交界二 · PC 键位是“必需”，不是“顺手加的”

硬门槛里有一条：主流程 PC 与 VR 两端都能完成。
理由很现实：教室机位 36 个 / 选课 40 人——总有人手上没有头显；而且期末你要交的是能给别人看的东西，不可能人人发一台头显。
所以 DOM 层不是“给开发者的赠品”，它是一条正式通路。你们改作品时，PC 那条路不能塌。

这一层最容易被写坏的一个地方，是按钮：看着能点、其实点不动。上一届有同学的处理办法很好——加了一行 btn.disabled = false，又加了一个 window.isSecureContext 检测：不在安全上下文里，按钮上直接写“进入 VR（需要 HTTPS）”。他不是背下来这两条，是踩过之后把它写进了代码里。

第 2 层 · XR 层，它只干三件事

① 会话

immersive-vr —— 能不能进 VR 的第一个前提。

② 参考系

local-floor —— 眼高由它决定。

③ 帧循环

每一帧做什么。状态就在这一层被读到画面上。

⚠️ 进 VR 的前提是安全上下文：navigator.xr 只在 https / localhost / 127.0.0.1 下暴露。 file:// 下它就是 undefined —— 页面上根本没有“进入 VR”这个按钮，这不是代码坏了。 这就是从第 5 次课立的那句口号：先怀疑环境，再怀疑代码。

帧预算为什么是 13.9ms，不是 16.7ms

目标 72Hz ⇒ 13.9 ms / 帧 —— 不是 16.7 ms。差的这 2.8 ms，是浏览器合成占掉的时间（16.7 是 60Hz 的数）。
工程面板实时显示：FPS · 帧时间 · 最差 1% 帧 · DrawCalls · 三角面 · 贴图数。

今天不讲优化（那是第 10 次课）。今天只要求你认出两个读数在哪：FPS 与降级等级。待会儿进 VR 的时候，先低头找到这两处。

动态降级 L1 / L2

触发条件动作能否恢复
帧时间持续超预算 20% 达 2 秒L1 降像素比 → L2 关阴影余量恢复时自动回升（可逆）
没有降级记作 L0—

待会儿进 VR，如果面板上写着 L1 或者 L2，那说明当时的机器撑不住——把它记下来，第 10 次课专门解决这个。

移动与转向：默认值不是随便选的

做法舒适度代价
瞬移（传送）最不易晕破坏空间连续性
平滑移动沉浸感好晕动症主要来源
Snap 45° 转向显著降低眩晕—（有 380 ms 冷却防误触）
平滑转向连续更易晕
VR 里永远不要强制旋转相机。你可以在场景里放一个“看这里”的提示，但不要替用户转头——那是晕得最快的一种做法。

第 3 层 · 状态层就是一个 `S` 对象

整个作品的可变部分，住在一个 S 对象里：力 / 速度 / 计数 / 开关 / 进度，全在这里。案例 01 的调试入口：浏览器控制台输入 VRSandbox，可查看 / 操作全部状态；面板上的“重力”按钮，实时改的就是 S.gravity（默认 9.8）。

⚑ 为什么“一个 S”这么重要：案例 01 有两个投掷相关的常量挂在状态上——S.gravity（重力，默认 9.8）与 S.restitution（弹性）。 课堂作业里有这么一条：把重力从 9.8 调到 3，再投一次，描述手感差异。
假设重力不是挂在 S 上，而是散在三个函数里各写一遍 9.8——改重力得改几处？三处，而且只要漏一处，这个球的行为就自相矛盾。 这就是“一个 S”的价值：同一个东西，全作品只有一个来源。
硬门槛：状态集中在一个 S 对象，且可被外部查询（window.XX.S）。为什么要“能被外部查询”？三个真实用途：
① 你自己调试——控制台敲一行就能看到现在的状态，不用到处打 console.log；
② 别人验收你的作品——第 12 次课路演，评审要看“你到底做到了哪一步”；
③ 数据可以导出——体验数据里的时长 / 交互次数 / 完成度，都是从状态里取的。
换句话说：状态不集中，你后面三次课的里程碑全都交不出来。

四、三处交界，一句话总结

交界规则违反的后果
DOM ⇄ XR沉浸模式下 DOM 下线面板 / 名字在头显里看不见
XR ⇄ 状态帧循环每帧读一次 S状态改了但画面不变
状态 ⇄ DOM面板按钮与键盘快捷键共用同一个 S同一个人两个值，行为自相矛盾

最后一条叫 单一设置源（single source of truth）。举例：面板上有个“重力”按钮把它调到 3，你又写了个键盘快捷键按一下把重力设回 9.8；如果这两个用了不同的变量，屏幕上显示的是 3，实际跑的是 9.8——你自己都会被自己骗。

一、VR 手柄与 PC 键位映射（这两套都要走通）

VR：头显 + 双手柄

  • 手柄射线：远距离指向（物体 / 面板 / 地面）；
  • 扳机：面板按钮、传送落点、远距离拉取；
  • 握持键（侧键 / squeeze）：抓取 0.35 m 内物体；释放即投掷；
  • 左摇杆：平滑移动；右摇杆：Snap 45° / 平滑转向；
  • 触觉：抓取 / 命中 / 收纳 / UI 各不同强度。

PC：鼠标 + 键盘

  • 鼠标拖拽：环视；
  • W A S D（Shift 加速）：行走；Q / E：转身；
  • 鼠标左键点物体：抓取（再点一次放开）；
  • 鼠标左键点地面：传送；左键点面板：操作按钮；
  • R：重置场景。
PC 快捷键行为课上怎么用
Shift+P坐姿 / 站立（面板随之下沉 0.45 m、下倾 0.18 rad）讲三层结构时的开场现象
Shift+H惯用手循环：双手 → 单手（自动）→ 仅右手 → 仅左手 → 双手★ 至少试一次“仅左手”，见下
Shift+G注视停留点击（停在按钮上 1.2 s 触发，相机上有注视准星）讲“边界一”时的演示

⚑ 这一屏必须让学生自己看出来：先把视线移到场景里的球上停住，球不动；问“为什么球不动”，等学生说出“面板和物体是两套判定”再往下讲边界二。

边界二 · 未在真机验证的部分（必须对学生诚实）

三条通路：先怀疑环境，再怀疑代码

收束段花 7 分钟把三条现场走一遍，但课堂上只教走通的那一条

这节课是后半程第一次真机实操，后面五次课每次都要走通路。今天不把通路讲透，后面五次课每次都要花 20 分钟救火。 三条都演示、只教一条，是为了让学生知道“还有别的办法”，遇到问题时不会卡死在一条路上；同时避免教师在课堂上同时维护三条路径。

#通路我怎么操作特点与麻烦
①USB + adb reverse数据线连头显与笔记本，执行 adb reverse tcp:8080 tcp:8080 → 头显浏览器开 http://127.0.0.1:8080/天然是安全上下文（127.0.0.1），校园网再怎么隔离也不怕、不占网络；但要开发者模式与 adb
②局域网 http + 头显白名单头显浏览器进 chrome://flags/#unsafely-treat-insecure-origin-as-secure，填入 http://电脑IP:端口不用连线；但电脑 IP 一变就要重填，这是它最大的麻烦
③站点 https直接打开 https 地址最省事，也是以后收作业与互评的首选；需要有可发布的站点
板书一句（第 5 次课已确立，全程沿用）：先怀疑环境，再怀疑代码。
navigator.xr 只在 https / localhost / 127.0.0.1 下暴露。 file:// 不是安全上下文 → navigator.xr 是 undefined → 页面上看不到“进入 VR”按钮。
双击 HTML 文件永远进不了 VR。“装进头显”的正确说法是：在头显里通过 https / localhost / 白名单地址打开。

课前教师会实测并选定一条（本次课选定的是哪一条：【待确认：由教师课前实测后当堂宣布】）。三条你都试一下“能不能打开”，但主用那一条就行。 你们不用三条都会——会用一条，就够了。

示范案例：一个“能评分的小玩法”长什么样

两个可直接打开的标准答案：投篮擂台（作品示范）与作业样板（交付示范）

“把零件攒成一个作品”这句话太抽象。所以给两个可以直接玩、也可以直接拆的示范： 一个告诉你“完整的小玩法”是什么样，一个告诉你“合格的作业交付”是什么样。 先玩、再拆、再改——不要从零开始想。

一、拆解：什么叫“可评估的小玩法”

E5 的统一要求只有三条，但每条都在回答一个设计问题——为什么这个玩法能被“评分”而不是“只能看”：

要求示范里怎么做的它解决了什么问题
① 目标 + 计分显示在 3D 里计分板是场景里的一块 CanvasTexture 面板，分数/时间/最高分三行玩家不用退出沉浸就知道自己做得怎么样；这也是第 8 次课“状态→UI 同步”的伏笔
② 命中给两通道以上反馈筐闪（视）+ 上扬音效（听）+ pulse(0.8, 90)（触）“差一点”和“进了”必须一眼一听就能区分，否则玩家学不会调整力度
③ 有重置按钮面板上的“重置”把球、分数、计时、阶段一起复位球一定会飞出场地。没有重置，演示 30 秒就卡死——这是 E5 排行第一的翻车点
＋ 阶段状态机ready → playing → over，UI 与提示音随阶段变，over 锁输入“开始前不计分、结束后不能刷分”——这是第 8 次课状态机的最小原型，今天先用起来
示范案例怎么用（三步）：
① 先玩：完整打一局，感受“什么时候想再来一次”；
② 再拆：打开源码找四个东西——计分变量在哪、命中判定在哪、三通道反馈在哪、重置函数在哪；
③ 再改：换主题（投篮→投壶/投币）、换规则（+2/+1 改连击）、换反馈（换音色/换震动强度），改三处就算你的作品。

五、下课前一定要知道的六句话

① 沉浸模式下 DOM 看不见

你的界面必须是 3D 物件（名字也一样）。

② 72 Hz 的帧预算是 13.9 ms

不是 16.7 ms。面板上要认出 FPS 与降级等级 L0 / L1 / L2。

③ 注视停留只能点 3D 面板

场景实体（球、方块）仍然需要手柄——这条边界就是第 9 次课要讨论的问题。

④ 先怀疑环境，再怀疑代码

file:// 不是安全上下文，看不到“进入 VR”按钮——那通常不是你的代码坏了。

⑤ 没有反馈的交互等于没有交互

一次有效交互 = 视 / 听 / 触至少两个通道；悬停与确认强度要分档（0.2 / 0.5 / 0.8）。

⑥ 状态只有一个 S

改一处，画面 / 手感 / 面板读数同时变——这是第 8 次课状态机的起点。
