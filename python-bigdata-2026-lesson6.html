一

文件与编码 本章起点

文件是什么 · 文本文件与二进制文件 · 常见格式与对应库 · 字符编码 UTF-8 / GBK / ASCII

前五章写的程序有一个共同点：数据都放在变量里。变量活在内存中，程序一结束、电脑一关机，内存里的东西就没了。想让数据"活到下一次运行"，只有一条路——写进文件。这一章从这个最简单的动作开始，然后把"打开、读写、关闭"三件事一件件讲透。

1.1 文件是什么

课件给的定义是：文件是数据的抽象和集合，是数据持久存储的重要方式。这句话可以拆成两个关键词来理解——抽象：磁盘上那堆 0 和 1 怎么排我们不用管，Python 给它们包了一层统一的东西叫"文件"，你只管按名字打开、按内容读写；持久：数据从内存搬到磁盘，程序退出、机器重启都还在，而且能被别的程序再读出来（今天写的 csv，明天 Excel 和 pandas 都能打开）。

所以"用程序操作文件"永远是三步：① 打开文件——指定路径和名字，拿到一个文件对象；② 通过这个对象读写内容；③ 关闭文件——把缓冲区里的内容真正保存到磁盘。后面两个模块，就是把这三步拆开讲。

图 6-1　内存是"工作台"，文件是"仓库"——数据只有写进文件，才能留到下一次运行
一句话记住：内存是工作台，文件是仓库。工作台上摆着正在处理的数据，仓库里存着要留到明天的数据。open() 是去仓库取货，close() 是把货放回仓库——中间那次"读写"就是干活。
✅ 本节小结：文件是数据的持久存储；程序结束内存清空，写进文件的数据不丢，还能在不同程序之间共享。操作文件永远三步：打开 → 读写 → 关闭。

磁盘上的文件千千万，按"数据怎么组织"只分两类。这个区分非常实用：决定了你用什么模式打开、看到的到底是什么类型的数据。下面的表把两类文件放在一起对照。

对比项文本文件二进制文件
存的是什么字符串（str）字节串（bytes）
编码采用单一特定编码（如 UTF-8）没有"文本编码"概念，要按各自的格式解码
行的概念由若干文本行组成，每行以换行符 \n 结尾没有行，只有一长串字节

课件里那句"二进制文件需要进行解码之后才能正确显示、修改或执行"说的就是这个意思：一张 jpg 里没有"字符串"，只有按 JPEG 格式排好的字节；想看到图，得让图片查看器按 JPEG 规则去解码。而 txt 里存的就是文字本身，只要知道它用的是哪种编码，就能翻译回人能读的字符。下图把两类文件的"内部长相"画出来。

图 6-2　文本文件存"字符"，二进制文件存"字节"——打开模式必须跟着数据走

光看图不够直观。下面这段代码做一件事：把同一段中文写进文件，先用文本模式读它，再用二进制模式（'rb'）读它，看同一个文件给出的两种答案。

同一个文件、两种读法：文本模式读成 str，二进制模式读成 bytes 
import os, tempfile

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'data1.txt')
    with open(path, 'w', encoding='utf-8') as f:
        f.write('你好')

    with open(path, encoding='utf-8') as f:
        print('文本模式读到：', repr(f.read()))

    with open(path, 'rb') as f:
        raw = f.read()
    print('二进制模式读到：', raw)
    print('字节数：', len(raw))
运行结果（实测）
文本模式读到： '你好'
二进制模式读到： b'\xe4\xbd\xa0\xe5\xa5\xbd'
字节数： 6
看输出里的两个细节：① 文本模式读到的 '你好' 是 str，len 是 2（两个字符）；② 二进制模式读到的 b'\xe4\xbd\xa0\xe5\xa5\xbd' 是 bytes，每个 \xe4 这样的是一个字节——"你好"两个字在 UTF-8 下占 6 个字节（一个汉字 3 字节）。同一个文件，模式不同，交到你手里的东西就不同。
✅ 本节小结：按数据的组织形式，文件分文本文件（存字符串、单一编码、按 \n 分行、记事本能看懂）和二进制文件（存字节串、要按格式解码、记事本看不懂）。文本用 'r' 打开，二进制用 'rb' 打开。

1.4 编码：字符与字节之间的翻译官

计算机里只有 0 和 1，也就是字节；而我们写进程序的是字符（"你"、"好"、"A"）。把字符变成字节叫 编码 encode，把字节变回字符叫 解码 decode。同一个字符，用不同编码翻译出来的字节可能完全不同——这就是编码问题的根源。

2.1 open() 的三个参数

open(file, mode, encoding) 的功能是打开文件并返回一个文件对象。三个参数各自管一件事，缺省值记牢：mode 默认是 'rt'（只读文本），encoding 在 Windows 上不建议依赖默认值。

如果指定的文件不存在、访问权限不够、磁盘空间不足或者别的原因导致创建文件对象失败，open() 会直接抛出异常。所以打开文件这件事，最好放在 try 里，或者至少心里有数——下面这段代码就是"只读打开一个不存在的文件"的真实下场。

打开一个不存在的文件：open() 直接抛 FileNotFoundError 
import os

name = 'chpt6_not_exist.txt'
print('这个文件存在吗？', os.path.exists(name))
f = open(name, encoding='utf-8')
print(f.read())
运行结果（实测）
这个文件存在吗？ False

为什么报错信息里只有文件名、没有一长串路径？因为这里给的是相对路径——"当前工作目录下的 chpt6_not_exist.txt"。相对路径是相对程序运行时所在的目录，不是相对你写代码的那个文件。找不到文件时，先 os.getcwd() 看清当前在哪，再决定用相对路径还是完整路径。

2.3 路径与转义：r"" 原始字符串

2.4 close() 与 with：别让文件漏着

为什么一定要 close()？因为 write() 写的内容不是立刻落到磁盘，而是先放在缓冲区里攒着，close() 才把缓冲区刷到磁盘并释放文件句柄。程序若在 close() 之前异常退出，缓冲区的内容就可能丢。

手动 open() + close() 的问题是：中间一旦报错，close() 那一行就被跳过了。Python 的 with 语句（上下文管理语句）解决了这件事：不论什么原因跳出 with 代码块，都保证文件被正确关闭。

忘记 close() 会怎样？① 缓冲区里的内容可能没落盘，程序崩了数据就丢了；② 文件句柄被占着，Windows 上再想删、改名这个文件会失败；③ 打开的文件一多，句柄耗尽，后面直接打不开新文件。所以——能用 with 就别手动 open/close，这是本课要求的标准写法。
✅ 本节小结：close() 才把缓冲区刷到磁盘并释放文件；手动 open/close 遇到异常会漏掉 close。用 with open(...) as f: 写，离开代码块自动关闭，异常也关，是推荐写法。

3.4 例 6-1：商品类别码统计

下面这个例子是课件例 6-1 的完整复现。题目是：从文件 data1.txt 中读取一组商品编号数据（数据之间以英文逗号分隔），取出各编号的前 2 位（表示商品的类别码），然后去除重复的类别码，并按类别码排序。思路一共五步：读全部 → 按逗号切 → 每个编号取前 2 位 → 用集合去重 → 排序。

import os, tempfile

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'data1.txt')
    with open(path, 'w', encoding='utf-8') as f:
        f.write('1001,1002,2001\n2002,1001,3001')

    with open(path, 'r', encoding='utf-8') as fr:
        codes = fr.read()                     # 读取数据，返回一个字符串
        print(codes)

    alist = codes.split(',')                  # 返回一个字符串列表
    print(alist)
    codes = [c[0:2] for c in alist]           # 每个编号取前 2 位
    print(codes)
    uni_codes = set(codes)                    # 去除重复的类别码
    uni_codes = sorted(list(uni_codes))
    print(uni_codes)

前面三个模块，我们读写的一直是 .txt 纯文本：一行一句话，read() 回来就是一串字符。可现实里的数据往往长成表格的样子——姓名、年龄、职业、工资，一列一个字段，一行一条记录。要把它存成纯文本，最简单的办法就是在字段之间插一个分隔符；最自然的选择是逗号，于是就有了 CSV。

4.1 CSV 是什么

CSV 是 Comma-Separated Values（逗号分隔值）的缩写。它是一种以逗号作为分隔符的纯文本文件格式，通常用来存表格数据：每一行是一条记录，行内各字段用逗号隔开，同一份文件里每行的列数应当相同。txt / csv 这类文本文件可以直接用记事本打开看，也能用 Excel 打开看——同一份文件，两种看法。

先看 Excel 里的样子。下面这张图就是把 user_info.csv 拖进 Excel 之后的样子：表头是姓名、年龄、职业、工资，下面张三、李四两行数据。别被单元格骗了——文件本身并没有任何“表格结构”，它就是三行用逗号连起来的纯文本。

把“表格”还原成“文本”，就是下面这个文件卡片：记事本里看到的三行字，和 Excel 里看到的三行两列，指的是同一份数据。Excel 只是按逗号把它摆成了网格。

user_info.csvUTF-8 · 纯文本 · 3 行
姓名,年龄,职业,工资
张三,20,销售员,5000
李四,22,程序员,8000
双击用记事本打开就是这三行；用 Excel 打开就被逗号拆成了三行四列的表格。文件里没有“格”，只有逗号。

逗号当分隔符有个绕不开的麻烦：字段内容本身就带逗号怎么办？比如“销售, 北京”这种写法。CSV 的规矩是：如果字段里含逗号，就用一对英文双引号把它包起来，引号里面的逗号一律不算分隔符。下图把一行 CSV 拆开来看。

图 6-11　一行 CSV 怎么变成四个字段：逗号切开，引号保护字段内部的逗号

明白了“逗号拆分”的规矩，就该知道手工 split(',') 不靠谱。Python 标准库自带 csv 模块，它就是专门按上面那套规矩干活的分隔器。下面的 demo 把两种拆法摆在一起对比：普通的 str.split 遇到带引号的字段会翻车，csv.reader 则拆得干干净净。

手工 split 和 csv.reader 拆同一行：带引号的字段谁拆得对 
import csv, io

line = '张三,20,销售员,5000'
print('先用 str.split(",")：')
print(line.split(','))
print('字段个数：', len(line.split(',')))

line2 = '"销售, 北京",5000'
print('遇到带逗号的字段：', line2.split(','))
print('字段个数：', len(line2.split(',')))
print('csv.reader 读出来：', list(csv.reader(io.StringIO(line2))))

字段个数： 4
遇到带逗号的字段： ['"销售', ' 北京"', '5000']
字段个数： 3
csv.reader 读出来： [['销售, 北京', '5000']]

✅ 本节小结：CSV 是逗号分隔的纯文本——一行一条记录、每行列数相同、记事本和 Excel 都能打开。字段内部含逗号时用引号包起来，所以拆列不要用 split(',')，交给 csv 模块。

4.2 csv.writer：写 CSV

写 CSV 分两步：先用 open() 打开文件拿到文件对象，再用 csv.writer(fileobj) 在文件对象外面包一层 csv 写对象。这一层“壳”的作用只有一个：把列表转成一行逗号分隔的文本，然后交给文件对象写下去。

写法作用说明
csv.writer(f)创建 csv 写对象参数是已打开的文件对象，不是文件名
writer.writerow(list)写一行列表里一个元素 = 一个字段，返回写入的字符数
writer.writerows(rows)写多行参数是“列表的列表”，一次写多行

看 demo：表头用 writerow() 写一行，数据用 writerows() 一次写完。写完之后再以文本方式读回来，你就能看到 csv 模块到底往文件里写了什么。

writerow 写一行、writerows 写多行，把课程表存成 CSV 
import csv, os, tempfile

rows = [
    ['课程', '班级', '人数'],
    ['Python', '数据1班', 45],
    ['Python', '数据2班', 48],
]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'course.csv')
    with open(path, 'w', encoding='utf-8', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(rows[0])       # 写一行：表头
        writer.writerows(rows[1:])     # 写多行：数据
    with open(path, encoding='utf-8', newline='') as f:
        print(f.read())
运行结果（实测）
课程,班级,人数
Python,数据1班,45
Python,数据2班,48

注意 open(path, 'w', encoding='utf-8', newline='') 里的最后一个参数 newline=''：写 CSV 时必须写。这不是可有可无的装饰，漏了它，Windows 上的 CSV 会变成“每隔一行一个空行”。原因在下面这个 demo 里看得最清楚。

漏写 newline='' 会怎样：多出来的空行是这么来的 
import csv, os, tempfile

rows = [['姓名', '年龄'], ['张三', 20], ['李四', 22]]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'user_info.csv')

    with open(path, 'w', encoding='utf-8') as f:          # 漏写 newline=''
        csv.writer(f).writerows(rows)
    with open(path, encoding='utf-8', newline='') as f:
        raw = f.read()
    print('漏写时：', repr(raw))
    print('再读回来：', list(csv.reader(raw.splitlines())))

    with open(path, 'w', encoding='utf-8', newline='') as f:   # 正确写法
        csv.writer(f).writerows(rows)
    with open(path, encoding='utf-8', newline='') as f:
        raw = f.read()
    print('写对后：', repr(raw))
    print('再读回来：', list(csv.reader(raw.splitlines())))
运行结果（实测）
漏写时： '姓名,年龄\r\r\n张三,20\r\r\n李四,22\r\r\n'
再读回来： [['姓名', '年龄'], [], ['张三', '20'], [], ['李四', '22'], []]
写对后： '姓名,年龄\r\n张三,20\r\n李四,22\r\n'
再读回来： [['姓名', '年龄'], ['张三', '20'], ['李四', '22']]
为什么必须写 newline=''？行尾的换行符有两拨人在管：csv 模块默认往每行末尾写一个 \r\n（回车 + 换行两个字符）；而 Python 在 Windows 上以文本模式写文件时，还会把其中的 \n 再翻译成 \r\n。两个一叠加，行尾就从 \r\n 变成了 \r\r\n——用记事本、Excel 或普通文本模式打开时，一个单独的 \r 也算一次换行，于是每两行之间多出一个空行；csv.reader 读到空行就返回 []（就是 demo 里“再读回来”多出来的那些方括号）。加上 newline='' 就是告诉 open()：别做换行符翻译，行尾交给 csv 自己管。机房用的是 Windows，这个参数一定要写。
✅ 本节小结：写 CSV = open(..., 'w', newline='') 拿到文件对象 → csv.writer(f) 包一层 → writerow() / writerows() 写行。少写 newline=''，Windows 上就会多出空行。

4.3 csv.reader：读 CSV

读是写的逆过程，但要注意一个关键差别：写进去的是列表，读出来的却全是字符串。csv.reader(iterable) 返回一个可迭代对象，每迭代一次给你一行，这一行是一个字符串列表——哪怕文件里写的是 20、5000 这样的数字，读回来也是 '20'、'5000'。

下图把“文件对象”和“csv 读写对象”的关系画清楚：文件对象负责行，csv 读写对象负责把一行文本和一行列表互相转换。

图 6-12　文件对象管“行”，csv 读写对象管“列”——两条通路都从 open() 开始

csv.reader 读出来的第一行通常是表头（姓名、年龄、职业、工资）。表头不是数据，后面算工资时得把它跳过。跳过的方法不是“判断一下再 continue”，而是在循环之前先调用一次 next(reader)，把第一行取走——之后 for row in reader 就是从第二条记录开始。

csv.reader 迭代：每行是一个字符串列表，next() 先取走表头 
import csv, os, tempfile

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'user_info.csv')
    with open(path, 'w', encoding='utf-8', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(['姓名', '年龄', '职业', '工资'])
        writer.writerow(['张三', 20, '销售员', 5000])
        writer.writerow(['李四', 22, '程序员', 8000])

    with open(path, encoding='utf-8', newline='') as f:
        reader = csv.reader(f)
        header = next(reader)              # 先取走表头
        print('表头（跳过）：', header)
        for row in reader:
            print(row, '| 类型：', type(row).__name__)
        print('字段都是字符串：', [type(x).__name__ for x in row])
运行结果（实测）
表头（跳过）： ['姓名', '年龄', '职业', '工资']
['张三', '20', '销售员', '5000'] | 类型： list
['李四', '22', '程序员', '8000'] | 类型： list
字段都是字符串： ['str', 'str', 'str', 'str']
读 CSV 的三条铁律：① 每行是列表，不是字符串；② 列表里每个元素都是 str，要算数必须 int() / float() 转换；③ 表头用 next(reader) 跳过，不要在循环里判断“第一行不是数据”。
✅ 本节小结：csv.reader(f) 逐行迭代，每行给一个字符串列表；next(reader) 把表头取走，循环就从数据行开始。数字字段读回来是字符串，别忘了转换。

4.4 例 6-4 + 例 6-5：把 user_info.csv 写进去再读出来

这两个例题是本节的核心，数据就用课件里的那两行：张三（20 岁，销售员，5000）和李四（22 岁，程序员，8000）。课件的代码把文件写在 d:\mypython\ 下，这里为了不污染你的磁盘，改用 tempfile.TemporaryDirectory() 建一个临时目录，代码结构一行都没变。

例 6-4　将列表中的用户信息写入 user_info.csv 文件

先把三行数据（含表头）放在列表里，然后 csv.writer 逐行写进去；紧接着再打开同一个文件读回来，确认写进去的内容。这一步很关键——写完立刻读回来看一眼，比在脑子里推断可靠得多。

例 6-4：把 data 写入 user_info.csv，再读回来看看 
import csv, os, tempfile

data = [['姓名', '年龄', '职业', '工资'],
        ['张三', 20, '销售员', 5000],
        ['李四', 22, '程序员', 8000]]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'user_info.csv')

    # 例 6-4：把列表中的用户信息写入 user_info.csv
    with open(path, 'w', encoding='utf-8', newline='') as f:
        csv_writer = csv.writer(f)
        for row in data:
            csv_writer.writerow(row)       # 逐行写入列表内容

    # 再把文件读回来，确认写进去的是什么
    with open(path, 'r', encoding='utf-8', newline='') as f:
        csv_reader = csv.reader(f)
        for row in csv_reader:
            print(row)
运行结果（实测）
['姓名', '年龄', '职业', '工资']
['张三', '20', '销售员', '5000']
['李四', '22', '程序员', '8000']

例 6-5　读取 user_info.csv，计算工资收入的最大值

读的时候要处理三件事：跳表头（next(csv_reader)）、取工资列（row[3]，第 4 列，下标从 0 开始）、转成整数（int(row[3])）。工资收集到 salary 列表里，最后 max(salary) 求最大值。

例 6-5：next() 跳表头 → int(row[3]) 收工资 → max() 求最高工资 
import csv, os, tempfile

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'user_info.csv')
    with open(path, 'w', encoding='utf-8', newline='') as f:
        csv.writer(f).writerows([['姓名', '年龄', '职业', '工资'],
                                 ['张三', 20, '销售员', 5000],
                                 ['李四', 22, '程序员', 8000]])

    # 例 6-5：读 user_info.csv，求工资的最大值
    salary = []
    with open(path, 'r', encoding='utf-8', newline='') as f:
        csv_reader = csv.reader(f)
        header_row = next(csv_reader)      # 跳过表头
        for row in csv_reader:
            salary.append(int(row[3]))     # 第 4 列是工资
    print(salary)
    print('最高工资为：' + str(max(salary)))
运行结果（实测）
[5000, 8000]
最高工资为：8000
例 6-5 里 header_row = next(csv_reader) 这个赋值其实没用到 header_row，它的副作用才是重点：next() 把表头那一行消耗掉了。如果省掉这一句，int('工资') 会直接抛 ValueError。另外课件里的路径写死在 d:\mypython\，也没显式写 encoding 和 newline；这里换成临时目录并按前两节的规范补齐，读写逻辑与课件完全一致。
✅ 本节小结：例 6-4 用 csv.writer 把“列表的列表”逐行写成 CSV；例 6-5 用 next() 跳表头、int(row[3]) 把字符串工资转成整数、max() 求最高工资。这两步合起来，就是“存进去、算出来”的完整闭环。

4.5 DictReader / DictWriter（选学）

csv.reader 给的是列表，取字段只能靠列号（row[0]、row[3]）。一旦 CSV 的列顺序变了，所有下标都得跟着改，很容易错位。所以 csv 模块还提供了按表头名取字段的版本：csv.DictReader 把每行变成字典，csv.DictWriter 按 fieldnames 写字典。

csv.reader → 列表（按列号取）
row = ['张三', '20', '销售员', '5000']
row[0]        # '张三'
row[3]        # '5000'
# 列顺序一变，下标全得改
csv.DictReader → 字典（按表头取）
row = {'姓名': '张三', '年龄': '20',
       '职业': '销售员', '工资': '5000'}
row['姓名']    # '张三'
row['工资']    # '5000'
# 列顺序变了也不怕
🎬 动态演示：csv.reader 给列表、DictReader 给字典

看 demo：用 DictWriter(f, fieldnames=['姓名', '职业', '工资']) 写，字典的键和 fieldnames 对上就写、对不上就报错；读的时候 DictReader 自动把表头当年键，每行给一个字典。

DictWriter 按 fieldnames 写字典，DictReader 按表头读成字典 
import csv, os, tempfile

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'user_info.csv')
    with open(path, 'w', encoding='utf-8', newline='') as f:
        writer = csv.DictWriter(f, fieldnames=['姓名', '职业', '工资'])
        writer.writeheader()
        writer.writerow({'姓名': '张三', '职业': '销售员', '工资': 5000})
        writer.writerow({'姓名': '李四', '职业': '程序员', '工资': 8000})

    with open(path, encoding='utf-8', newline='') as f:
        for row in csv.DictReader(f):
            print(row['姓名'], row['职业'], row['工资'],
                  '| 键：', list(row.keys()))
运行结果（实测）
张三 销售员 5000 | 键： ['姓名', '职业', '工资']
李四 程序员 8000 | 键： ['姓名', '职业', '工资']
选学内容，考试不要求默写。判断标准：如果后面还要按字段名反复取数据、或者列顺序可能变，用 DictReader 更稳；只是从头到尾按位置处理几列，reader 就够了。读回来的字典值仍然是字符串，要算数还得转换。
✅ 本节小结：列表按列号，字典按表头。数据列多、顺序会变时用 DictReader / DictWriter，靠 fieldnames 对齐字段名，比记 row[3] 稳。

目录常用操作 上机常用

os 模块目录函数 · getcwd / chdir / listdir · mkdir vs makedirs · rmdir 只删空目录 · scandir 与 DirEntry · os.path 判断与拆分 · 递归遍历目录树

文件操作处理的是“一个文件”，目录操作处理的是“一堆文件放在哪”。Python 内置的 os 模块提供了目录与路径的常用方法：看当前在哪、列目录内容、建目录、删目录、判断是文件还是目录、把路径拼起来或拆开。这些函数是后面“遍历整个数据集目录”“批量改名”这类任务的地基。

5.1 os 模块的目录函数

先把这一节要用的函数摆成一张表。不用背，写代码时回来查。要注意两个容易混淆的地方：listdir 和 scandir 都能列目录，但返回的东西完全不一样；mkdir 和 makedirs 只差几个字母，能建的层级却差很多。

函数作用返回 / 要点
os.listdir(path)列出目录下的所有名字字符串列表；只有名字，不带路径；顺序不保证
os.scandir(path)列出目录项DirEntry 可迭代对象，每项有 name / path / is_file() / is_dir()
os.mkdir(path)创建一级目录父目录必须已存在；目录已存在报 FileExistsError
os.makedirs(path)创建多级目录缺的父目录自动补齐；已存在时加 exist_ok=True 不报错
os.rmdir(path)删除目录只能删空目录；非空报 OSError，要连内容删用 shutil.rmtree()
os.getcwd()取当前工作目录返回绝对路径字符串
os.chdir(path)切换当前工作目录之后的相对路径都相对于它；切走记得切回
os.path.isdir(path)判断是不是目录返回 True / False；配套还有 isfile / exists
os.path.join(a, b)拼接路径按系统分隔符连接，自动处理该不该加 \
os.path.basename(path) / splitext(path)取文件名 / 拆后缀basename 给 'file1.txt'；splitext 给 ('file1', '.txt')
路径的两种写法：listdir('.') 里的 '.' 表示当前目录，'..' 表示上一级。写 listdir(路径) 是“看别人家”，写 listdir('.') 是“看自己家”——不切换目录也能看，所以多数时候不需要 chdir。
✅ 本节小结：目录操作的函数分成三组——看（listdir / scandir / getcwd）、改（mkdir / makedirs / chdir）、删（rmdir）。再加一组判断与路径处理（os.path.*）。

5.2 当前目录：getcwd / chdir / listdir

假设 Windows 的 D 盘上有一个叫 my_dir 的文件夹，结构如下图：里面有三个东西——file1.txt、file2.csv 两个文件，以及子目录 dir1；dir1 里又放着 file3.py、file4.py、file5.txt 三个文件。后面几节的 demo 都用这个结构，只是建在临时目录里。

图 6-13　my_dir 的目录树：一个目录里可以既有文件，又有子目录，子目录里再有文件

getcwd() 问“我现在在哪个目录”，chdir(path) 说“我要换到那个目录去”，listdir(path) 列“那个目录里有什么”。三个函数配合起来，就是课件里那串操作：先 chdir 进 my_dir，再 getcwd 看位置，最后 listdir('.') 看内容。不切换目录也能列，直接写 listdir(r“D:\my_dir”) 就行。

照 my_dir 的样子建一棵目录树，再用 listdir 列出来 
import os, tempfile

with tempfile.TemporaryDirectory() as td:
    work = os.path.join(td, 'my_dir')
    os.makedirs(os.path.join(work, 'dir1'))
    for name in ['file1.txt', 'file2.csv']:
        with open(os.path.join(work, name), 'w', encoding='utf-8') as f:
            f.write('x')
    for name in ['file3.py', 'file4.py', 'file5.txt']:
        with open(os.path.join(work, 'dir1', name), 'w', encoding='utf-8') as f:
            f.write('x')

    print('my_dir 里：', sorted(os.listdir(work)))
    print('dir1 里：', sorted(os.listdir(os.path.join(work, 'dir1'))))

chdir 有一个坑：它改的是整个进程的工作目录。切进去忘了切回来，后面所有用相对路径的代码都会在错误的目录里找文件。所以演示 chdir 的标准写法是——先存旧目录，演示完再切回。

getcwd / chdir：切进去，干完活，再切回来 
import os, tempfile

old = os.getcwd()                        # 先记住原来的工作目录
with tempfile.TemporaryDirectory() as td:
    work = os.path.join(td, 'my_dir')
    os.mkdir(work)
    with open(os.path.join(work, 'file1.txt'), 'w', encoding='utf-8') as f:
        f.write('hello')

    os.chdir(work)                       # 切换当前工作目录
    print('getcwd() 等于 abspath(".")：', os.getcwd() == os.path.abspath('.'))
    print('当前目录里的内容：', os.listdir('.'))
    os.chdir(old)                        # 演示完必须切回来

print('已经切回原来的目录：', os.getcwd() == old)
运行结果（实测）
getcwd() 等于 abspath(".")： True
当前目录里的内容： ['file1.txt']
已经切回原来的目录： True
不要 chdir 完了不回来。一个 Python 程序从头到尾只有一个工作目录，改了就影响后面所有代码。能用 listdir(路径) 传路径解决的，就别 chdir；非得切，就学上面的写法：old = os.getcwd() → 干活 → os.chdir(old)。
✅ 本节小结：getcwd() 看位置、chdir() 换位置、listdir() 看内容。listdir('.') 看当前目录，listdir(路径) 看不切换也能看的目录。切换目录务必切回。

5.3 建目录与删目录：mkdir / makedirs / rmdir

建目录的两个函数只差三个字母，能力却差一截：mkdir 只能建一级，父目录必须已经存在；makedirs 可以一次建多级，缺的父目录它会一层一层补上。删目录的 rmdir 则有一条铁律：只能删空目录。

看 demo 验证：mkdir 建两级会在父目录缺失时抛 FileNotFoundError，同一个目录再建一次抛 FileExistsError；换成 makedirs，三级目录一次到位。

mkdir 只能建一级、makedirs 能建多级：用异常把差别看清楚 
import os, tempfile

with tempfile.TemporaryDirectory() as td:

    os.rmdir(os.path.join(d, 'sub'))       # 先删空子目录

rmdir 和 shutil.rmtree 的区别是“安全性”：rmdir 只能删空目录，误删的可能性很小；shutil.rmtree(路径) 会连里面的所有文件和子目录一起删掉，且不进回收站。初学阶段写 rmtree 前，先把路径 print 出来看三遍。
✅ 本节小结：mkdir 建一级、父目录必须在；makedirs 建多级、父目录自动补；rmdir 只删空目录，非空要 shutil.rmtree（删了就没了，小心）。

5.4 scandir 与 os.path 判断

前面 listdir 返回的是名字列表——想知道某个名字是文件还是目录，还得再调一次 os.path.isdir。os.scandir(path) 更省事：它返回一个由 DirEntry 对象组成的可迭代对象，每个 DirEntry 自带 name（名字）、path（拼好的路径）和 is_file() / is_dir() 两个判断方法。它不会一次性把所有信息读进内存，目录很大时也扛得住。

scandir 返回 DirEntry：名字、路径、是文件还是目录，一次拿全 
import os, tempfile

with tempfile.TemporaryDirectory() as td:
    work = os.path.join(td, 'my_dir')
    os.makedirs(os.path.join(work, 'dir1'))
    for name in ['file1.txt', 'file2.csv']:
        with open(os.path.join(work, name), 'w', encoding='utf-8') as f:
            f.write('x')

    entries = sorted(os.scandir(work), key=lambda e: e.name)
    print('拿到的东西：', type(entries[0]).__name__)
    for e in entries:
        kind = '目录' if e.is_dir() else '文件'
        print(e.name, '是', kind, '| is_file =', e.is_file())

5.5 遍历目录树（递归）与 pathlib 简介

把 5.2 的目录树真正“走一遍”，需要递归：处理一个目录时，如果里面还有子目录，就用同样的办法再进子目录处理，直到没有子目录为止。函数自己调用自己，天然适合这种“一层套一层”的结构。

下图是递归遍历的执行顺序：先处理 my_dir，发现 dir1 是目录，就钻进去把它的三个文件打印完，再退回来继续处理 file1.txt、file2.csv。这种“钻到底再回来”的顺序叫深度优先。

🎬 动态演示：递归遍历目录树，文件夹里还有文件夹

递归函数要写对两件事：基准情形（目录里没有子目录了，循环自然结束）和递归调用（遇到子目录，带着新的路径和更深的缩进再调自己）。缩进用 ' ' * depth 造出来，层级越深缩进越多，打印结果就是一棵树。

递归函数 walk(path, depth)：把 my_dir 整棵树打印出来 
import os, tempfile

def walk(path, depth=0):
    for name in sorted(os.listdir(path)):
        full = os.path.join(path, name)
        mark = '[目录]' if os.path.isdir(full) else '[文件]'
        print('    ' * depth + mark + ' ' + name)
        if os.path.isdir(full):
            walk(full, depth + 1)

with tempfile.TemporaryDirectory() as td:
    work = os.path.join(td, 'my_dir')
    os.makedirs(os.path.join(work, 'dir1'))
    for name in ['file1.txt', 'file2.csv']:
        with open(os.path.join(work, name), 'w', encoding='utf-8') as f:
            f.write('x')
    for name in ['file3.py', 'file4.py', 'file5.txt']:
        with open(os.path.join(work, 'dir1', name), 'w',
                  encoding='utf-8') as f:
            f.write('x')

    print('my_dir/')
    walk(work, 1)
运行结果（实测）

        [文件] file3.py
        [文件] file4.py
        [文件] file5.txt
    [文件] file1.txt
    [文件] file2.csv

标准库 pathlib 是 Python 3.4 之后推荐的路径写法，把路径当对象而不是字符串：Path('my_dir') / 'dir1' / 'file3.py' 用 / 拼路径，.name / .parent / .suffix / .stem 取各部分，.iterdir() 列目录。选学，但很值得认识。

为什么递归遍历是后面所有“批量处理”的基础？因为数据集往往按“类别 / 子类 / 文件”存成多层目录。会写递归遍历，就能把一个目录树下所有 .csv 找出来、批量统计行数、统一改名——本课最后两节的文件综合应用和第 7 节的 AI 真实数据文件，用的都是这个套路。
✅ 本节小结：遍历目录树用递归——遇到子目录就带新路径和更深的缩进调自己；pathlib.Path 用 / 拼路径、用属性拆路径，是更现代的写法（选学）。

6.1 例 6-6：统计英文短文的长度

例 6-6 要做的事一句话就能说完：data3.txt 里每一行是一篇英文短文，统计每篇短文有多少个字符。题目看着简单，但它把"文本文件按行读"讲得很干净——for line in f 每次给你一整行，而且这一行末尾还带着换行符 \n。

图 6-16　文件操作综合应用的通用流水线：四个步骤，每一步都在改变数据的形态
例 6-6 完整复现：data3.txt 每行一篇短文，统计每篇长度 
import os, tempfile

PASSAGES = [
    'Reading makes a full man.',
    'Practice makes perfect.',
    'A little learning is a dangerous thing.',
]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'data3.txt')
    with open(path, 'w', encoding='utf-8') as f:      # 先造一个 data3.txt
        for p in PASSAGES:
            f.write(p + '\n')

    with open(path, 'r', encoding='utf-8') as f:      # 再按行读回来
        for line in f:
            print(line.strip())                       # 去掉行尾换行后再打印
            text = len(line.strip())                  # 一篇短文的长度
            print('长度：' + str(text))

长度：25
Practice makes perfect.
长度：23
A little learning is a dangerous thing.

两个容易忽略的细节：① line.strip() 去掉的是首尾的空白与换行符，不会动中间的空格——所以它统计的正是一篇短文本身的字符数；② len() 数的是字符个数，不是字节数（第 1 节讲过，"你好"是 2 个字符，在 UTF-8 下却占 6 个字节）。如果文件里混了中文，这两种"长度"会差很多。
为什么不用 f.readlines()？因为 for line in f 是一次只取一行——文件有 100 万行也只占一行的内存。例 6-6 只有三行无所谓，但第 7 节的语料文件动辄几十万行，这个习惯就得从第一行代码开始养。
✅ 本节小结：按行读文本是最常用的姿势——for line in f 一次一行，strip() 剪掉行尾换行，len() 数长度。例 6-6 的全部核心只有四行，但"一行一篇短文"这个约定，正是后面 CSV、jsonl、日志文件的共同前提：行是文本文件最小的记录单位。

6.2 例 6-7：成绩合并 → 排序 → 写文件

例 6-7 是本课最有代表性的一个例子。data2.txt 里每一行是一组成绩，成绩之间用空格分隔；要求把所有组的成绩合并到一起、按升序排序，再把结果写进 data2_sorted.txt。它值得反复看，是因为它有三次数据形态变化，而且每一次变化都只由一行代码完成。

例 6-7 完整复现：split → extend → float → sort → 写回（打印三次形态变化） 
import os, tempfile

DATA = '78.5 92.0 66.5\n88.0 95.5\n70.0 81.0 59.5 100.0\n'

with tempfile.TemporaryDirectory() as td:
    src = os.path.join(td, 'data2.txt')
    dst = os.path.join(td, 'data2_sorted.txt')
    with open(src, 'w', encoding='utf-8') as f:       # 先造一个 data2.txt
        f.write(DATA)

    scores = []
    with open(src, 'r', encoding='utf-8') as fr:
        for line in fr:
            line = line.strip()
            alist = line.split()                      # 返回字符串列表
            scores.extend(alist)                      # 合并数据
    print('scores 1: ', scores)

    scores = [float(sc) for sc in scores]             # 转换为浮点数
    print('scores 2: ', scores)

    scores.sort()                                     # 排序
    print('scores 3: ', scores)

    with open(dst, 'w', encoding='utf-8') as fw:      # 写回新文件
        for sc in scores:
            fw.write(str(sc) + ' ')                   # 用空格分隔

    with open(dst, encoding='utf-8') as fr:
        content = fr.read()
    print('data2_sorted.txt 的内容：[' + content + ']')
    print('末尾有换行符吗？', content.endswith('\n'))

6.3 综合案例：追加写日志与批量处理

套路一：追加写日志（a 模式 + 时间戳）

追加写日志：a 模式 + 时间戳，每次循环只加一行

    ('2026-03-02 08:15:37', '10.0.0.23', '/detail?id=7'),

一共写了 5 轮，每轮都是 a 模式，前面的记录全都还在
这里换成 w 就全毁了：open(log, 'w') 一打开就把文件截断成空，循环五轮之后文件里只剩最后一行的内容——前四行在第一次循环时就没了。日志、流水、训练记录这类"只增不改"的文件，永远用 a。
真实代码里时间戳这样取：from datetime import datetime，然后 datetime.now().strftime('%Y-%m-%d %H:%M:%S')。注意页面上的例子故意用了固定字符串——同一个 demo 每次运行的结果必须一致，否则校验器和你的眼睛都会被"每次都不一样"搞乱。这条经验在做数据实验时同样成立：能固定的随机种子、时间、路径，就都固定下来。

套路二：把日志读回来做 Top-N 统计

日志写完之后要能读回来才有价值。每一行按空格 split() 之后，第 3 段是 IP、第 4 段是 URL，用一个字典数次数，再按次数倒序排——这就是最朴素的"访问统计"。

套路三：批量遍历目录，挑出某一类文件

数据拿到手，第一个动作往往是"先把要的文件挑出来"。思路固定：os.walk() 递归遍历整棵目录树 → 用 endswith('.csv') 判断扩展名 → 挑中的用 shutil.copy2() 复制到一个干净的目录。这一套就是"数据准备"的雏形。

批量处理：遍历目录树，挑出所有 .csv 并复制到新目录

7.1 jsonl：大模型语料的存储格式

JSON 你见过：整个文件是一个数组或对象，json.load() 一次读进来变字典。jsonl（JSON Lines）不一样——一行一条 JSON，行与行之间互不相关。大模型的训练语料、指令微调数据、评测集，绝大多数都是这个格式：train.jsonl、sft.jsonl、eval.jsonl。

图 6-19　jsonl 的结构：文件 = 很多行，每行 = 一条完整的 JSON 记录（一个字典）
写 jsonl：一条一行，json.dumps 之后逐行 write 
import json, os, tempfile

records = [
    {'id': 1, 'text': '今天天气很好', 'label': '正面'},
    {'id': 2, 'text': '物流太慢了', 'label': '负面'},
    {'id': 3, 'text': '包装完整，下次还买', 'label': '正面'},
]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'samples.jsonl')
    with open(path, 'w', encoding='utf-8') as f:
        for r in records:
            line = json.dumps(r, ensure_ascii=False)   # 中文原样保留
            f.write(line + '\n')                        # 一条记录占一行

    with open(path, encoding='utf-8') as f:
        lines = f.readlines()
    print('文件一共', len(lines), '行，一行一条记录：')
    for i, line in enumerate(lines, 1):
        print('第', i, '行 →', line.strip())

    print('-' * 44)
    print('把第 2 行单独解析回字典：', json.loads(lines[1]))

读 jsonl：逐行 json.loads，一行坏了只跳过这一行

LINES = [
    '{"id": 1, "text": "今天天气很好", "label": "正面"}',

    '{"id": 3, "text": "这一行故意写坏了", "label":',
    '{"id": 4, "text": "包装完整", "label": "正面"}',
]

with tempfile.TemporaryDirectory() as td:
    path = os.path.join(td, 'samples.jsonl')
    with open(path, 'w', encoding='utf-8') as f:
        f.write('\n'.join(LINES) + '\n')

    labels, bad = {}, []
    with open(path, encoding='utf-8') as f:
        for no, line in enumerate(f, 1):
            line = line.strip()
            if not line:
                continue                     # 跳过空行
            try:
                obj = json.loads(line)
            except json.JSONDecodeError:
                bad.append(no)               # 只记下坏行，继续往下读
                continue
            labels[obj['label']] = labels.get(obj['label'], 0) + 1

    print('解析成功的记录：', 4 - len(bad), '条；坏行行号：', bad)
    print('标签分布：', labels)
    print('结论：坏掉的一条被跳过，其余记录一条都没丢')

json.dumps 的 ensure_ascii 参数别漏：默认 ensure_ascii=True，中文会被转成 \u4eca\u5929 这样的转义序列——文件仍然能被 json.loads 正确读回来，但人眼看着是一堆乱码，而且每条记录都白白多出好几个字节。写中文语料一律用 json.dumps(obj, ensure_ascii=False)。
✅ 本节小结：jsonl = 一行一个 json.dumps 的结果。写的时候 for r in records: f.write(json.dumps(r, ensure_ascii=False) + '\n')，读的时候 for line in f: json.loads(line)。它把"文件操作"和"数据格式"两件事接在了一起：行是文件层的分隔，JSON 是数据层的结构，两者互不干扰——这正是它能扛住几十万条语料的原因。

7.2 训练日志：追加写 + 落盘

模型训练一跑就是几十分钟到几天，中途随时可能崩。所以训练脚本必须把每一轮的 loss、准确率立刻追加到日志文件里——这样即使进程被杀，前面几十轮的记录还在。写法就是上一节的套路一：a 模式，一轮一行。

训练日志：每轮追加一行，读完再统计最低 loss 出现在第几轮 
import os, tempfile

# 假时间 + 假指标，保证输出每次一样（真实训练里由程序实时产出）
EPOCHS = [
    ('2026-03-02 09:00:12', 1, 1.8421, 0.4120),
    ('2026-03-02 09:03:45', 2, 1.2053, 0.6681),
    ('2026-03-02 09:07:20', 3, 0.8834, 0.7462),
    ('2026-03-02 09:11:02', 4, 0.6742, 0.8105),
    ('2026-03-02 09:14:38', 5, 0.5120, 0.8563),
]

with tempfile.TemporaryDirectory() as td:
    log = os.path.join(td, 'train.log')

    for ts, ep, loss, acc in EPOCHS:                  # 每轮训练完追加一行
        with open(log, 'a', encoding='utf-8') as f:
            f.write(ts + ' epoch=' + str(ep) + ' loss=' + format(loss, '.4f')
                    + ' acc=' + format(acc, '.4f') + '\n')

    losses, accs = [], []
    with open(log, encoding='utf-8') as f:
        for line in f:
            fields = {}
            for token in line.split():                # 时间 epoch=1 loss=… acc=…
                if '=' in token:                      # 只挑 key=value 形式的段
                    key, val = token.split('=')
                    fields[key] = float(val)
            losses.append(fields['loss'])
            accs.append(fields['acc'])

    print('每轮 loss：', losses)
    print('每轮 acc ：', accs)
    print('-' * 40)
    best = min(losses)
    print('最低 loss =', best, '，出现在第', losses.index(best) + 1, '轮')
    print('5 轮一共下降：', format(losses[0] - losses[-1], '.4f'))
    print('日志文件', os.path.getsize(log), '字节，一行一轮，随时打开都能看')
运行结果（实测）
每轮 loss： [1.8421, 1.2053, 0.8834, 0.6742, 0.512]
每轮 acc ： [0.412, 0.6681, 0.7462, 0.8105, 0.8563]
----------------------------------------
最低 loss = 0.512 ，出现在第 5 轮
5 轮一共下降： 1.3301

解析日志的一个小陷阱：时间戳 2026-03-02 09:00:12 中间本身就有个空格，按空格 split() 之后"第几段是 loss"就不好数了（日期一段、时刻一段，位置容易算错）。所以上面代码改成只认 key=value 形式的段：谁带等号就解析谁。字段顺序变了、以后多加一个字段，代码都不用改——这是解析日志比较稳的写法。
为什么不把指标存在变量里、训完再一次性写？因为"训完"可能永远不会到来——显存溢出、断电、手动 Ctrl+C，随便哪一下都会让内存里的列表消失。日志的作用就是把进度钉在磁盘上。这也是本章反复强调"写完要 close() / 用 with"的原因：不关闭，数据可能还躺在缓冲区里，一崩就全没了。
再往前一步：真实训练常用 tensorboard、wandb 这类工具画 loss 曲线，但它们的底层动作和这段代码一样——追加一行文本。所以你现在写的 f.write(ts + ' loss=' + ...)，就是那些炫酷曲线的第一层。
✅ 本节小结：训练日志 = a 模式 + 一轮一行 + 立刻落盘。读回来统计更简单：split() 之后按 '=' 取右半边，float() 转成数字，然后 min() / index() 就能回答"第几轮最好"。能追加、能读回、能统计——这三件事凑齐了，日志才真的有用。

7.3 读词表 / 读配置 / 读数据集清单

除了语料和日志，AI 工程里还有三种"小而重要"的文件。它们的格式各不相同，但读法都落在本章的知识点上。

vocab.txt：词表

  • 一行一个词（或一个字符）
  • 行号就是它的 id
  • 用 enumerate 边读边编号 → 字典
  • 文本转向量时查这张表

config.json：配置

  • 整个文件是一个字典
  • json.load(f) 一次读完
  • 存学习率、批大小、层数
  • 改参数不用改代码

dataset/：数据集目录

  • 一个类别一个文件夹
  • os.listdir + 计数 = 分布
  • 类别不均衡要在训练前发现
  • os.walk 数文件数
读词表：一行一个词，行号即 id，做成字典

一、知识点总结卡

文件与编码

  • 文件 = 数据的持久存储，本质是磁盘上的一串字节
  • 文本文件：存字符串，单一编码，按 \n 分行（txt / csv / py）
  • 二进制文件：存字节串，需解码才能看（jpg / mp3 / mp4 / exe）
  • s.encode('utf-8') 字符 → 字节；b.decode('utf-8') 字节 → 字符
  • 中文在 UTF-8 下占 3 字节，GBK 下占 2 字节，ASCII 根本编不了
  • 格式对应库：txt 内置 / csv → csv · pandas / excel → openpyxl · pandas / json → json

打开与关闭

  • open(file, mode, encoding)，mode 默认 'rt'
  • r 只读、文件不存在报错；w 清空重写；a 末尾追加；x 新建、已存在报错
  • t 文本（默认）/ b 二进制 / + 可读可写
  • 路径里 \ 要转义成 \\，或写 r"D:\test.txt"
  • 拼路径优先用 os.path.join()，别手工 + '\\'
  • 推荐写法只有一个：with open(...) as f:

读写与文件指针

  • read(n) 读 n 个字符；read() 全读
  • readline() 一行；readlines() 全部行 → 列表
  • for line in f 逐行迭代，最省内存，大文件用它
  • 每行末尾带 \n，用 .strip() 去掉
  • write(s) 返回写入的字符数；writelines() 不自动加换行
  • tell() 当前指针位置；seek(offset, whence) 移动指针

CSV 文件

  • 逗号分隔的纯文本表格，可用记事本和 Excel 打开
  • 写：csv.writer(f) → writerow() / writerows()
  • 读：csv.reader(f) 迭代，每行是字符串列表
  • 开文件必须写 newline=''，否则 Windows 上多空行
  • 读数字要自己转：int(row[3]) / float(...)
  • 表头用 next(reader) 跳过
  • DictReader 按表头取字段（选学）

目录操作

  • os.getcwd() 当前目录；os.chdir(p) 切换
  • os.listdir(p) 返回名字列表（不含子目录内容）
  • os.scandir(p) 返回 DirEntry，有 .name / .path / .is_file() / .is_dir()
  • os.mkdir() 建一级；os.makedirs() 建多级
  • os.rmdir() 只能删空目录；非空用 shutil.rmtree()
  • os.path.exists / isfile / isdir / join / basename / splitext

综合应用套路

  • 固定四步：读 → 处理 → 写 → 核对
  • 读进来的是字符串，参与计算前先 int() / float()
  • 多行数据先 split() 成列表，再 extend() 合并
  • 写完一定再读一遍验证，别凭感觉
  • 批量处理目录：遍历 → 判断扩展名 → 处理 → 输出
  • AI 语料多用 jsonl：一行一条 JSON，可流式读
