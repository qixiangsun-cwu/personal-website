一

软件生态与工具选型

4.1 四类工具各管一段 · 4.2 建模与引擎怎么选

1.1 四类工具：一类工具只干一件事

类别它负责什么典型工具本课程会用到
建模造出物体的形状Blender、3ds Max、MayaBlender（看一眼界面 + 导出一个 FBX）
引擎把内容组织成可运行的应用Unity、Unreal EngineUnity 6（全程）
资产提供现成的模型、贴图、动画、音效Sketchfab、Poly Haven、Mixamo、AI 生成工具素材库 + AI 生成
验证检查“在真机上到底行不行”XR Device Simulator（PC 模拟）、头显真机模拟器为主 + 头显验证
“一类工具只干一件事”是本课的第一条原则：建模软件不做交互逻辑，引擎不做精细建模，资产库不负责优化。知道边界，才知道遇到问题该找哪一环。

1.2 建模软件：Blender 与 3ds Max

Blender（免费 · 开源）

免费、跨平台、更新快，建模/雕刻/渲染/动画一体；社区教程极多，适合个人开发与课程作业。本课程用它做“建模—导出 FBX”的最小闭环。

3ds Max / Maya（行业标准 · 商业授权）

在建筑可视化、影视与游戏公司中使用广泛，插件生态成熟、团队协作流程完善；代价是授权成本与学习曲线。

1.3 引擎：Unity 与 Unreal 怎么选

维度Unity 6（本课程选择）Unreal Engine
上手成本较低，C# 语法友好，教学资料多较高，C++ 与蓝图双轨
XR 支持OpenXR + XR Interaction Toolkit，跨 PICO / Quest / Vive内置 XR 框架，偏向高保真与主机级画面
画面保真够用，移动端一体机表现稳定更强，但更吃 GPU
一体机性能移动端优化路径成熟对头显算力要求更高
为什么本课程选 Unity：C# 上手快、XR Interaction Toolkit 提供现成交互组件、OpenXR 一次配置可跨品牌设备，且对移动端一体机（PICO 4 Ultra）的性能优化路径更成熟。Unreal 更强的是画面上限，但“画面更好”往往意味着更高的 GPU 开销——这正是上次课讲的生成设备的现实意义。
硬件接口 ①②：① 资产产出的模型有多“重”（面数、贴图），直接决定设备能不能跑满 90Hz；② 引擎越追求画面，越吃 GPU——生成设备（也就是“算力在哪”）不是抽象概念，它决定了你能选哪条技术路线。
二

资产从哪来：一个模型到 VR 的五道关

4.3 三条来路 + 五道关 + 三个最常翻车的坑

2.1 三条来路

素材库（最快）

Sketchfab 模型库、Poly Haven 贴图与 HDRI、Mixamo 角色动画。适合快速搭场景，注意授权与命名规范。

自己建（最可控）

用 Blender 从零建模，尺寸、拓扑、UV 自己说了算。代价是时间——课程里只在必要的小物件上使用。

AI 生成（最新）

Meshy、Hunyuan3D、TRELLIS 等文/图生 3D，适合快速原型。但要检查拓扑、UV、比例与版权，通常需要二次修整。

2.2 五道关：模型从建模软件到 VR 场景

① 建模  →  ② 减面  →  ③ 导出 FBX  →  ④ 导入设置  →  ⑤ 在场景里验证
            控制面数      禁中文路径      单位与缩放 ↑         戴上头显看
                                         最常翻车的一关
关卡要做什么没做好会怎样
① 建模按真实比例建模，统一单位进 Unity 后比例不对
② 减面控制在合理面数（一体机尤其敏感）掉帧、发热、眩晕
③ 导出 FBX路径与文件名不含中文导入失败、材质丢失
④ 导入设置检查 Scale / 轴向 / 材质模型躺倒、悬空、变成粉色
⑤ 验证先在模拟器看，再戴头显看“在 PC 上明明没问题”

2.3 最常见的三个坑

  1. 缩放不对：模型小到看不见、或大到撑爆场景 → 改 Transform → Scale（常用 1 或 0.01）；
  2. 贴图变粉红：材质丢失或路径含中文 → 重新指定材质，并把素材放到纯英文路径；
  3. 轴向搞错：模型躺倒或漂在空中 → Blender 默认 Z 轴向上，Unity 是 Y 轴向上，需要旋转或导出时校正。
硬件接口 ③：面数过高 → 掉帧 → 眩晕。这不是“画面问题”，而是接上了上次课的刷新率与 Motion-to-Photon 延迟：延迟一旦超标，人就会不适，再好的内容也救不回来。
三

实验 A · 环境核对与界面认知

12 分钟 · 不安装，只核对：确认版本与插件齐全就能开工

本次课不安装、不下载 Unity——机房已部署好 Unity 及整套 XR 环境。你要做的是把版本与插件核对清楚，然后直接开工。

A1 查 Unity 版本号（今天的第一个任务）

路径打开 Unity → 顶部菜单 Help → About Unity，弹窗里能看到完整版本号，例如 6000.0.83f1
要做的把这个版本号抄到任务卡上（教师会收齐全班版本号，用于排查工程兼容问题）
为什么第一件事就查版本：Unity 只能升级工程，不能降级。如果现在记录的版本低于你以后使用的版本，工程就可能打不开——这是真实工程里最常见的坑之一。

A2 确认项目里装了哪些包

  • 路径：Window → Package Manager → 左上角下拉框选 In Project；
  • 要找的包：XR Plugin Management、XR Interaction Toolkit；
  • 顺带看：列表中若有 Input System，说明输入系统已就绪；
  • 若缺包：下拉框切到 Unity Registry 搜索安装；若机房不能联网，用教师提供的 .unitypackage 本地导入（Assets → Import Package → Custom Package）。

A3 打开或新建项目

  • 打开已有：Unity Hub → 项目 → 点机房提供的模板项目；
  • 若需新建：Hub → 新建项目 → 模板选 3D (Built-In Render Pipeline)；
  • 工程命名用英文（如 VRCase01），工程路径必须是纯英文。

A4 认识六个面板（必记）

面板位置作用一句话记忆
Hierarchy 层级左侧列出场景里所有物体场景里“有什么”
Scene 场景中央编辑视角，搭建场景你工作的地方
Game 游戏中央运行时真实画面（相机视角）玩家“看到什么”
Inspector 检视右侧选中物体的组件与属性选中什么改什么
Project 项目底部工程里所有资源文件素材“存在哪”
Console 控制台底部报错、警告、调试输出出问题先看这里

自测三个问题：运行时报错先看哪个面板？哪个面板显示“玩家实际看到的画面”？哪个面板列出场景里“有什么物体”？

A5 保存场景

File → Save（Ctrl+S）。场景文件是 Assets/ 下的 .unity 文件，养成随时保存的习惯。

硬件接口 ④：稍后要加的 XR Origin，就是上次课讲的 Inside-Out 定位在软件里的落点——硬件负责“知道自己在哪”，软件负责“把位置用起来”。

实验 C · 导入模型与第一个脚本 ★

25 分钟 · 让场景里真的有东西，而且它会动

C1 导入 FBX 模型

  • Project 面板右键 → Create → Folder，先建一个 Models 文件夹；
  • 把教师提供的 .fbx（或 .obj）拖进 Assets/Models；
  • 选中模型，Inspector 里会出现 Model / Rig / Materials 三个标签页。
本次课不依赖联网下载模型（避免机房网络问题），统一使用教师提供的模型文件。

C2 放进场景并修正比例

检查项怎么做
比例是否合理与场景里的 Cube / Plane 对比；不对就改 Transform → Scale（1 或 0.01）
位置是否合适调整 Transform → Position 的 Y 值（Unity 是 Y 轴向上）
材质是否正常若呈粉红色，说明材质丢失或贴图路径含中文，需重新指定

C3 写出第一个脚本

Project 面板空白处右键 → Create → C# Script，命名为 SpinObject——首字母大写、不能有中文、不能有空格。

using UnityEngine;

public class SpinObject : MonoBehaviour
{
    public float speed = 60f;   // 每秒旋转的角度

    // Start 在物体第一次被激活时调用一次
    void Start()
    {
        Debug.Log("SpinObject 启动了");
    }

    // Update 每帧调用一次（适合做持续运动）
    void Update()
    {
        transform.Rotate(0f, speed * Time.deltaTime, 0f);
    }
}

挂载与运行

  1. 选中场景里的模型（或任意物体）；
  2. 把 SpinObject 从 Project 面板拖到 Inspector 下方空白处；
  3. 点 ▶ Play，物体开始旋转；
  4. Play 状态下可以在 Inspector 里实时改 Speed，看转速变化（试试从 60 改成 600）。

读代码要点（对应 4.3 开发语言）

概念在这个脚本里的体现
GameObject你挂脚本的那个物体
ComponentSpinObject 本身就是挂在物体上的一个组件
MonoBehaviourUnity 所有脚本的基类，必须继承
Start()只执行一次，适合初始化
Update()每帧执行，适合持续动作
Time.deltaTime让转动速度与帧率无关——快慢机器上转得一样
Time.deltaTime 是本课最值得记住的细节：没有它，高刷新率的机器上物体会转得更快。这和上次课讲的帧率、延迟是同一件事的两面。

双轨验证：模拟器 → HTC Vive 真机 ★

25 分钟 · 同一个场景，在 PC 与头显里各看一遍

你已经在 PC 上用 Device Simulator 跑通了场景。现在戴上 HTC Vive 看一个真实运行的 VR 场景，体会软件设置与硬件体验之间的差距——这就是本课程“双轨流程”的核心。

本实验室的头显是 HTC Vive ×5：有线 + 基站方案，头显固定在 5 个机位上、搬不动，所以这一环节看的是教师演示的场景，不是每位同学自己的工程（后续课次设备流程熟练后，再安排"带自己工程上机"）。

组织形式

  • 5 组轮换，5 套 HTC Vive 同时开放，按机位号分 1—5 组，每组 8 人；
  • 每人约 3 分钟（只看一眼，不是完整体验）；
  • 未轮到的组：继续完善自己的场景，或帮旁边同学排错。

戴上头显做三个动作

  • 看：画面清不清晰？和 PC 上的 Game 视图比，差别在哪？
  • 转：快速转头——画面跟得上吗？有没有拖影或延迟？
  • 走：瞬移一步，感受移动时的舒适度。

二、7 个课堂演示（U1—U7）

U1 · 3 分钟
版本与包核对
目标：全班机器版本一致，每人知道自己这台是什么环境。
操作：Help → About Unity 读版本号 → Package Manager → In Project 读四个包版本 → 填任务卡。
应看到：编辑器 6000.6.0f1；Input System 1.20.0 / XRI 3.6.0 / XR Management 4.7.0 / OpenXR 1.18.0。
翻车点：装成"团结引擎（Tuanjie）"或 2022 LTS，工程直接打不开。
U2 · 6 分钟
OpenXR 一次性配置
目标：让"一次配置支持 Vive / PICO / Quest"这句话变成看得见的东西。
操作：Project Settings → XR Plug-in Management → Windows 标签勾 OpenXR → 展开 OpenXR 看 Interaction Profile 列表 → 按提示重启编辑器。
应看到：HTC Vive Controller、PICO、Oculus Touch 等配置项并排在同一张表里。
对应知识点：上次课的 Outside-In 基站定位，落到软件里就是 XR Origin 读取的姿态数据。
U3 · 6 分钟
XR Origin + Device Simulator：看 / 转 / 走 / 抓
目标：没有头显也能把 6DoF 演完整。
操作：Hierarchy 右键 → XR → XR Origin (VR)；删掉旧的 Main Camera；把 XR Device Simulator 预制体拖进 Hierarchy；Play 后用 WASD 移动、按住鼠标右键转头、Tab 切左右手、G 握持、鼠标左键触发。
应看到：Game 视图里有虚拟手柄；走动时物体之间出现视差——这就是 6DoF 的价值。
翻车点：按键没反应 → 先用鼠标点一下 Game 视图；画面异常 → 旧主相机没删。
U4 · 5 分钟
射线交互与反馈：Hover / Select / 变色
目标：把"交互 = 事件 + 反馈"这句话讲实。
操作：给立方体挂 XRSimpleInteractable + InteractButton 脚本；Play 后用射线指上去、按下、移开。
应看到：灰色 → 悬停变黄（hoverEntered）→ 按下变绿（selectEntered）→ 移开复位。
对应知识点：输入设备那一节的"手柄是怎么被看见的"，在软件里变成"事件是怎么被触发的"。
U5 · 6 分钟
第一个脚本：Start / Update / Time.deltaTime
目标：讲清"初始化一次"和"每帧一次"的区别，以及转速为什么要乘 deltaTime。
操作：把 SpinObject 拖到物体上 → Play（默认 60 度/秒）→ 在 Inspector 把 speed 改成 180 → 再 Play 对比 → 看 Console。
应看到：转速随参数变化；Console 里 Start 的日志只出现一次。
对应知识点：如果不乘 deltaTime，高刷新率的机器上物体会转得更快——这就是"帧率"这个硬件指标在代码里的落点。
U6 · 6 分钟
自检与性能读数：F1 与 F2
目标：把"验收"从手感变成数字，把"面数 → 掉帧 → 眩晕"这条链落地。
操作：Play 后 SceneSelfCheck 自动跑五项检查，按 F1 可重查；按 F2 开性能浮层读 FPS / Triangles / Draw Calls；把场景里的树复制成 10 棵，再看这三个数。
应看到：缺项被直接点名；三角面与 Draw Call 上升、帧率下降。
翻车点：个别机器取不到计数器、显示 n/a，属正常，不影响场景运行。
U7 · 5 分钟
模型导入与比例：从建模软件到场景
目标：把"资产导入五道关"里最容易翻车的一段摊开讲。
操作：导入 _woodhouse.fbx 与 Palm.fbx → 检查 Scale Factor 与单位 → 放进场景，和 XR Origin 比高矮 → 材质变粉红时重新指定贴图。
应看到：尺寸正常（人能从门口走过去）；粉红材质修好后显示正常。
翻车点：素材路径含中文或空格；贴图丢失（材质的引用关系断了）；坐标轴不一致导致模型躺倒（Blender 是 Z 轴向上、Unity 是 Y 轴向上）。
